## 📝 Summary

The defining characteristic of a modern chat app is **instantaneous, bi-directional communication**. In traditional web architectures, apps used inefficient polling (asking the server every few seconds if new messages exist). 

In this lecture, Denis introduces Google Firestore's **Real-Time Snapshot Listeners** (`addSnapshotListener`) combined with Kotlin's **`callbackFlow`**. This architecture keeps a persistent WebSocket pipeline open to Google's cloud servers. Whenever any user posts a message to a room's subcollection, Firestore pushes the update down to all listening clients in real time, converting incoming snapshot events into a reactive Kotlin Coroutine `Flow<List<Message>>`.

## 🧠 Real-Time Pipeline Architecture

```
Firestore Subcollection: rooms/{roomId}/messages
                       │
                       │ WebSocket Push Notification on new document
                       ▼
             addSnapshotListener { querySnapshot, error ->
                       │
                       ▼
          trySend(messagesList).isSuccess
                       │
                       ▼

                       │
```

## 📒 Detailed Code Implementation

### 1. The Message Data Model (`Message.kt`)
```kotlin
package eu.tutorials.chatroomapp.data

data class Message(
    val senderFirstName: String = "",
    val senderId: String = "",
    val text: String = "",
    val timestamp: Long = System.currentTimeMillis(),
    val isSentByCurrentUser: Boolean = false
)
```
- `senderFirstName`: Display name of author (e.g. *"Alice"*).
- `senderId`: Author's email or UID used to determine alignment (right vs. left).
- `text`: Message body content.
- `timestamp`: UTC epoch milliseconds used for chronological ordering via `orderBy("timestamp")`.
- `isSentByCurrentUser`: Client-side UI flag formatting current user bubbles in brand purple.

### 2. The Message Repository (`MessageRepository.kt`)
```kotlin
package eu.tutorials.chatroomapp.data

import com.google.firebase.firestore.FirebaseFirestore
import kotlinx.coroutines.channels.awaitClose
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.callbackFlow
import kotlinx.coroutines.tasks.await

class MessageRepository(private val firestore: FirebaseFirestore) {

    // 1. Send Message to Firestore Subcollection
    suspend fun sendMessage(roomId: String, message: Message): Result<Unit> = try {
        firestore.collection("rooms")
            .document(roomId)
            .collection("messages")
            .add(message)
            .await()
        Result.Success(Unit)
    } catch (e: Exception) {
        Result.Error(e)
    }

    // 2. Real-Time Stream of Messages via callbackFlow
    fun getChatMessages(roomId: String): Flow<List<Message>> = callbackFlow {
        // Attach real-time snapshot listener ordered by timestamp
        val subscription = firestore.collection("rooms")
            .document(roomId)
            .collection("messages")
            .orderBy("timestamp")
            .addSnapshotListener { querySnapshot, error ->
                if (error != null) {
                    close(error)
                    return@addSnapshotListener
                }
                querySnapshot?.let { snapshot ->
                    val messageList = snapshot.documents.mapNotNull { doc ->
                        doc.toObject(Message::class.java)
                    }
                    // Emit updated list into the Coroutine Flow
                    trySend(messageList).isSuccess
                }
            }

        // Clean up: unsubscribe from Firestore when consumer stops listening
        awaitClose {
            subscription.remove()
        }
    }
}
```

## 🔍 How `callbackFlow` Solves the Callback Problem

### The Challenge
Firestore's `addSnapshotListener` is a push-based callback API designed in Java. Kotlin Coroutines, however, prefer structured streams like `Flow`. If you try to consume callbacks inside a normal coroutine builder, there is no way to emit values across threads or properly clean up resources when the user leaves the screen.

### The Solution: `callbackFlow`
1. **Thread-Safe Emission:** `trySend(messageList)` pushes the freshly deserialized message list into the flow channel buffer safely from Firestore's background callback thread.
2. **Lifecycle Cleanup with `awaitClose`:** When the user navigates away from the chat screen, Compose stops collecting the Flow. The coroutine is cancelled, which immediately triggers the `awaitClose { subscription.remove() }` block. This deregisters the listener on Google's servers, preventing **memory leaks** and unnecessary cloud read charges!

## 📌 Important Terms

| Term | Definition |
| :--- | :--- |
| **`addSnapshotListener`** | Firestore method that registers an ongoing event listener triggered whenever document data changes. |
| **`callbackFlow`** | Kotlin Coroutine Flow builder specifically engineered to bridge multi-shot callback APIs into reactive streams. |
| **`trySend()`** | Synchronously enqueues an element into the channel buffer without suspending. |
| **`awaitClose`** | Suspends the coroutine until the flow channel is cancelled or closed, executing mandatory cleanup routines. |
| **Subcollection** | A collection tied to a parent document: `rooms/{roomId}/messages`. |

## ❓ Q&A

**Q: What happens if the phone loses internet connection while in a chat?**  
A: Cloud Firestore has built-in offline persistence! It queues pending outgoing messages locally in SQLite cache. As soon as connectivity returns, Firestore automatically syncs the queued messages to the cloud and resolves all timestamps.

**Q: Why do we call `orderBy("timestamp")`?**  
A: Without an explicit ordering clause, Firestore returns documents by internal document ID order. Specifying `.orderBy("timestamp")` guarantees messages arrive in chronological order.

## ✅ Key Takeaways

1. ⚡ **No more polling:** `addSnapshotListener` delivers push notifications from Google Cloud within milliseconds.
2. 🌊 **`callbackFlow` bridges paradigms:** It transforms legacy Java-style callbacks into idiomatic Kotlin Coroutine flows.
3. 🧹 **Zero memory leaks:** `awaitClose { subscription.remove() }` detaches cloud listeners the moment the user exits the chat.
4. 📂 **Clean subcollection scoping:** Nesting messages under rooms guarantees message isolation between channels.
