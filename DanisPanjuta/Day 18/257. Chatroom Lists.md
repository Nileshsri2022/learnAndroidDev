## 📒 Detailed Code Implementation

### 1. The Room Data Model (`Room.kt`)
```kotlin
package eu.tutorials.chatroomapp.data

data class Room(
    val id: String = "",
    val name: String = ""
)
```
- `id`: Unique document ID generated automatically by Firestore.
- `name`: Display name of the chat room (e.g. *"Jetpack Compose Discussions"*).
- *Default Values:* Must provide default values `= ""` for Firestore object deserialization.

### 2. The Room Repository (`RoomRepository.kt`)
```kotlin
package eu.tutorials.chatroomapp.data

import com.google.firebase.firestore.FirebaseFirestore
import kotlinx.coroutines.tasks.await

class RoomRepository(private val firestore: FirebaseFirestore) {

    // Creates a new room document in Firestore
    suspend fun createRoom(name: String): Result<Unit> = try {
        val room = Room(name = name)
        // .add() auto-generates a unique 20-character document ID
        firestore.collection("rooms").add(room).await()
        Result.Success(Unit)
    } catch (e: Exception) {
        Result.Error(e)
    }

    // Fetches all available room documents
    suspend fun getRooms(): Result<List<Room>> = try {
        val querySnapshot = firestore.collection("rooms").get().await()
        val rooms = querySnapshot.documents.map { document ->
            document.toObject(Room::class.java)!!.copy(id = document.id)
        }
        Result.Success(rooms)
    } catch (e: Exception) {
        Result.Error(e)
    }
}
```

### 3. The Room ViewModel (`RoomViewModel.kt`)
```kotlin
package eu.tutorials.chatroomapp.viewmodel

import androidx.lifecycle.LiveData
import androidx.lifecycle.MutableLiveData
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import eu.tutorials.chatroomapp.Injection
import eu.tutorials.chatroomapp.data.Result
import eu.tutorials.chatroomapp.data.Room
import eu.tutorials.chatroomapp.data.RoomRepository
import kotlinx.coroutines.launch

class RoomViewModel : ViewModel() {

    private val _rooms = MutableLiveData<List<Room>>()
    val rooms: LiveData<List<Room>> get() = _rooms

    private val roomRepository: RoomRepository = RoomRepository(Injection.instance())

    init {
        loadRooms()
    }

    // Create room and reload list on success
    fun createRoom(name: String) {
        viewModelScope.launch {
            when (roomRepository.createRoom(name)) {
                is Result.Success -> loadRooms()
                is Result.Error -> { /* Handle error / toast */ }
            }
        }
    }

    // Load rooms from cloud repository
    fun loadRooms() {
        viewModelScope.launch {
            when (val result = roomRepository.getRooms()) {
                is Result.Success -> _rooms.value = result.data
                is Result.Error -> { /* Log or surface error */ }
            }
        }
    }
}
```

## 📌 Important Terms

| Term | Definition |
| :--- | :--- |
| **`collection("rooms").add()`** | Generates a new document with an auto-assigned cryptographic ID and persists the object payload. |
| **`document.toObject()`** | Firestore SDK utility that automatically maps document fields to Kotlin data class properties. |
| **Document ID (`document.id`)** | The unique primary key assigned to the document in Firestore. |
| **`Injection.instance()`** | Simple Service Locator / Singleton pattern providing the shared `FirebaseFirestore` instance. |

## ❓ Q&A

**Q: Why do we call `.copy(id = document.id)` when mapping documents?**  
A: By default, Firestore stores document data in document fields, but the document's ID itself is part of document metadata (not stored as a field inside the JSON). Calling `.copy(id = document.id)` ensures the Kotlin data object holds its own Firestore ID for navigation and subcollection queries.

**Q: Does `getRooms()` listen for real-time changes?**  
A: No; `.get()` is a one-shot query fetching the current snapshot. Creating rooms explicitly calls `loadRooms()` to refresh the list, while individual chat messages inside a room (covered next) use continuous real-time streams.

## ✅ Key Takeaways

1. 🗄️ **Clean CRUD design:** `RoomRepository` encapsulates all Firestore collection interactions.
2. 🔄 **Automated ID generation:** Using `.add()` lets Firebase generate collision-proof document keys automatically.
3. 📱 **Reactive UI bridge:** `RoomViewModel` exposes `LiveData<List<Room>>` ready to be observed by Compose `LazyColumn`.
