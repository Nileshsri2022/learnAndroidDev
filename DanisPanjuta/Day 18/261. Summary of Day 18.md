## 📝 Day 18 Executive Summary

Day 18 brought the **Firebase Chat Room Application** to full completion. Across Days 17 and 18, students learned how modern commercial Android software combines native front-end UI toolkits (**Jetpack Compose**) with production cloud infrastructure (**Google Firebase**).

Today, we mastered **Cloud Firestore** NoSQL data modeling, designed hierarchical subcollections for message partitioning, implemented a clean Repository layer using Kotlin Coroutines, converted push callbacks into cold reactive streams using `callbackFlow`, and built a dual-screen Compose UI: a room browser with dynamic dialog creation (`ChatRoomListScreen`) and an instant messaging room with formatted chat bubbles and real-time live synchronization (`ChatScreen`).

## ❓ Self-Check Questions

??? question "Why is `callbackFlow` preferred over standard `flow { }` for Firestore snapshot listeners?"
    Standard `flow { }` builders cannot emit values from within asynchronous callbacks executed on foreign threads. `callbackFlow` provides a thread-safe channel with `trySend()`, along with an `awaitClose` block to guarantee listener deregistration when the flow collector cancels.

??? question "How does Firestore structure subcollections under parent documents?"
    A subcollection is referenced by chaining collections and documents: `firestore.collection("rooms").document(roomId).collection("messages")`. This ensures messages for one room are isolated from all other rooms.

??? question "How does the UI determine whether a message bubble should appear on the left or the right?"
    `MessageViewModel` checks if `message.senderId == currentUser.email`. If true, `isSentByCurrentUser` is set to `true`, prompting `ChatMessageItem` to align the bubble to `Alignment.End` with brand primary coloring.
