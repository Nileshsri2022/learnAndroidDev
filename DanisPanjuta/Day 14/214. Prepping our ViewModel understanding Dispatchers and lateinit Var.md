# Prepping our ViewModel understanding Dispatchers and lateinit Var

---

## Overview

The `ViewModel` now talks to `WishRepository` instead of dummy data. That means **background threading** (`Dispatchers.IO`) and exposing **cold `Flow`s** that are initialized later via `lateinit`. This lecture rewrites `WishViewModel` for Room.

---

## Step 1 — dependencies via Graph

```kotlin
class WishViewModel(
    private val wishRepository: WishRepository = Graph.wishRepository
) : ViewModel() {

    var wishTitleState by mutableStateOf("")
    var wishDescriptionState by mutableStateOf("")

    fun onWishTitleChanged(newString: String) { wishTitleState = newString }
    fun onWishDescriptionChanged(newString: String) { wishDescriptionState = newString }

    lateinit var getAllWishes: Flow<List<Wish>>
    lateinit var getWishes: Flow<List<Wish>> // alias used in HomeView in some commits

    init {
        viewModelScope.launch {
            getAllWishes = wishRepository.getWishes()
        }
    }

    fun addWish(wish: Wish) = viewModelScope.launch(Dispatchers.IO) {
        wishRepository.addWish(wish = wish)
    }

    fun getWishById(id: Long): Flow<Wish> = wishRepository.getWishById(id)

    fun updateWish(wish: Wish) = viewModelScope.launch(Dispatchers.IO) {
        wishRepository.updateWish(wish = wish)
    }

    fun deleteWish(wish: Wish) = viewModelScope.launch(Dispatchers.IO) {
        wishRepository.deleteWish(wish = wish)
    }
}
```

| Member | Type | Why |
| :--- | :--- | :--- |
| `wishRepository = Graph.wishRepository` | Default param | Dependency injection via singleton Graph (next) |
| `lateinit var getAllWishes: Flow<List<Wish>>` | `lateinit` | Flow is set in `init` after `Graph` is initialized — cannot be `val` with initializer |
| `viewModelScope.launch { getAllWishes = ... }` | Main | Assigning the Flow reference itself (not collecting) |
| `viewModelScope.launch(Dispatchers.IO) { wishRepository.addWish }` | IO | Disk writes must not be on `Main` — `Dispatchers.IO` is the Android-recommended dispatcher for Room |
| `wishTitleState` / `wishDescriptionState` | `mutableStateOf` | Form state, still Compose-observed |

---

### lateinit vs nullable

| Declaration | When value is missing |
| :--- | :--- |
| `lateinit var getAllWishes: Flow<List<Wish>>` | Access before init → `UninitializedPropertyAccessException` — loud failure that surfaces initialization bugs |
| `var getAllWishes: Flow<List<Wish>>? = null` | Silently null — requires null checks everywhere |

Room + `Application` initialization guarantees `init` runs before any UI collects, so `lateinit` is safe and cleaner.

---

## Dispatchers

| Dispatcher | Use |
| :--- | :--- |
| `Dispatchers.Main` | UI + `collectAsState` |
| `Dispatchers.IO` | Database, network, file I/O |
| `Dispatchers.Default` | CPU work |
| `viewModelScope` | CoroutineScope tied to `ViewModel` lifecycle — auto-cancelled on `onCleared()` |

`suspend fun addWish` must be called from a coroutine; `Dispatchers.IO` moves the disk write off the main thread so the UI stays responsive.

---

## Recap / cheat sheet

- **ViewModel:** `WishViewModel(Graph.wishRepository)` → `lateinit var getAllWishes: Flow<List<Wish>>` set in `init`; writes via `viewModelScope.launch(Dispatchers.IO)`.
- **lateinit:** non-null promise initialized later; crash if accessed too early — correct for `Flow` assigned in `init`.
- **IO:** `Dispatchers.IO` for Room writes.
