# Using the Graphs Repository as a Default in Our WishViewModel

---

## Overview

`WishViewModel` already has a `Graph.wishRepository` default. This lecture makes that explicit and shows how `HomeView` and `AddEditDetailView` obtain the `ViewModel` without manually passing the repository — framework `viewModel()` uses the default, tests override it.

---

## The constructor

```kotlin
class WishViewModel(
    private val wishRepository: WishRepository = Graph.wishRepository
) : ViewModel()
```

| Call site | What happens |
| :--- | :--- |
| `viewModel()` inside a `@Composable` | AndroidX creates `WishViewModel()` → `wishRepository = Graph.wishRepository` |
| `WishViewModel(FakeRepository())` in a test | `Graph` is bypassed; fake is used |

---

## Navigation already supplies it

`Navigation`:

```kotlin
@Composable
fun Navigation(
    viewModel: WishViewModel = viewModel(), // ← uses Graph.wishRepository by default
    navController: NavHostController = rememberNavController()
) {
    NavHost(...) {
        composable(HomeScreen.route) { HomeView(navController, viewModel) }
        composable(AddScreen.route + "/{id}") { AddEditDetailView(...) }
    }
}
```

`MainActivity`:

```kotlin
setContent { WishlistAppTheme { Navigation() } }
```

No manual `WishRepository` or `WishDatabase` construction in UI — `Graph` handled it at app start.

---

## Recap / cheat sheet

- **Default:** `WishViewModel(Graph.wishRepository)` keeps UI call sites `viewModel()` trivial.
- **Test:** `WishViewModel(FakeRepository())` — no Room needed.
- **Navigation:** `Navigation(viewModel=viewModel(), navController=rememberNavController())` → `HomeView` + `AddEditDetailView` share the same `WishViewModel` instances.
