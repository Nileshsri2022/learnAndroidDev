# The Room WishDatabase Class

---

## Overview

A `RoomDatabase` subclass is the **connection** to the SQLite file. It declares which entities and DAOs belong to the database and what the `version` is. Room generates the concrete `_Impl`; the app only declares the abstract class.

---

## The class

`WishDatabase.kt`:

```kotlin
import androidx.room.Database
import androidx.room.RoomDatabase

@Database(
    entities = [Wish::class],
    version = 1,
    exportSchema = false
)
abstract class WishDatabase : RoomDatabase() {
    abstract fun wishDao(): WishDao
}
```

| Element | Meaning |
| :--- | :--- |
| `@Database(entities=[Wish::class], version=1)` | This DB has one table (`Wish`) and schema version `1` (bump on migration) |
| `exportSchema = false` | Do not export schema JSON to `schemas/` — keep false for single-version course app |
| `abstract class WishDatabase : RoomDatabase()` | Room generates `WishDatabase_Impl` |
| `abstract fun wishDao(): WishDao` | Abstract accessor — Room returns a cached `WishDao` implementation |

No `suspend` or `Flow` here — the database is just the holder.

---

## How it is instantiated (next lectures)

```kotlin
Room.databaseBuilder(
    context.applicationContext,
    WishDatabase::class.java,
    "wish_database" // SQLite file name
).build()
```

`"wish_database"` becomes the file `wish_database` in `app_database/` on the device.

---

## Recap / cheat sheet

- **Database:** `@Database(entities=[Wish::class], version=1, exportSchema=false) abstract class WishDatabase: RoomDatabase() { abstract fun wishDao(): WishDao }`.
- **Versioning:** bump `version` and provide migration when schema changes.
