# Initializing our Database

---

## Overview

`WishDatabase` is abstract; it needs to be **built** at app start. This lecture adds `Room.databaseBuilder` and wires the result into the `Graph` singleton.

---

## The builder

Inside `Graph.provide(context)` (next lecture) or directly in `Application.onCreate` for now:

```kotlin
val wishDatabase = Room.databaseBuilder(
    context.applicationContext,
    WishDatabase::class.java,
    "wishlist.db" // or "wish_database"
).build()
```

| Arg | Value | Meaning |
| :--- | :--- | :--- |
| `context.applicationContext` | `Application` context | Database must outlive any `Activity` — use `Application` context to avoid leaks |
| `WishDatabase::class.java` | The `@Database` class | What to instantiate |
| `"wishlist.db"` | File name | SQLite file in `app_database/wishlist.db`; change name to reset the DB during development |

> The lecture uses `context` passed to `Graph.provide`; the `Application` class (next) supplies `this` as that context.

After the build:

```kotlin
val wishRepository = WishRepository(wishDao = wishDatabase.wishDao())
```

That repository is what `WishViewModel` holds by default (`Graph.wishRepository`).

---

## Where not to build

Never build inside an `Activity` `onCreate` or a `@Composable` — each call would create a **new connection** and leak the previous one. Build **once** in the `Application`.

---

## Recap / cheat sheet

- **Build:** `Room.databaseBuilder(appContext, WishDatabase::class.java, "wishlist.db").build()`.
- **Provide DAO:** `wishDatabase.wishDao()` → `WishRepository(...)`.
- **Once:** in `Application.onCreate`, not in UI.
