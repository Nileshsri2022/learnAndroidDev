# Quick Overview Of Storage Options - Reading the book

## Overview

This lecture reads **Chapter 11.5 — Saving Data Locally on Android** from the course companion book (co-authored by Loveth Nwokike). It contextualizes why Room was chosen over other Android storage options.

---

## Storage options on Android

| Option | What it stores | Access | Example |
| :--- | :--- | :--- |
| **SharedPreferences** | Small key-value primitives (`String`, `Int`, `Boolean`) | Private file, via `getSharedPreferences` | User settings, onboarding flag |
| **Internal storage** | Private files, app-specific | Only this app, deleted on uninstall | Private images, cache |
| **External storage** | Shared files (SD card, USB) | Other apps + user, needs permission | Exported photos, downloads |
| **SQLite** | Structured relational tables, SQL queries | App-private DB file | Any structured data |
| **Room** | SQLite with abstraction | Same file, but via `@Entity`/`@Dao`/`@Database` | Wishlist, 7-Minute Workout history, etc. |

Rule of thumb:

- <100 values, no relations → `SharedPreferences`.
- Files/bulks → internal/external storage.
- Structured data + queries → **Room** (preferred) — raw SQLite is *possible* but requires boilerplate (`SQLiteOpenHelper`, `Cursor`, manual SQL strings).

---

## Why Room over raw SQLite?

*From the book:*

> *SQLite was found to be complex, requiring long lines of code for its actualization. Room was created to reduce this complexity. It provides an abstract layer over SQLite, allowing you to interact with the database using Data Access Objects (DAOs).*

Key Room features:

| Feature | Role |
| :--- | :--- |
| `@Entity` | Maps a data class to a table |
| `@Dao` | Declares CRUD methods (`insert`, `update`, `delete`, `query`) |
| `@Database` | Holds the connection, lists entities + version |
| `Flow` | Reactive stream — UI recomposes on DB changes |

The Wishlist uses all four, plus a `Repository` that isolates the `Dao` from the `ViewModel`.

## Why KAPT was added yesterday

The `kotlin-kapt` plugin and `kapt("room-compiler")` are needed because Room's annotation processor generates `_Impl` classes (e.g. `WishDatabase_Impl`) at compile time.

---

## Recap / cheat sheet

- **Small →** `SharedPreferences`; **files →** internal/external; **structured →** Room/SQLite.
- **Room > SQLite** = less boilerplate + compile-time query verification + `Flow`.
- **Room components:** Entity, Dao, Database, Repository, Flow, ViewModel.
