# Adding the Application Class and Using our Graph

---

## Overview

An `Application` subclass is instantiated **before any `Activity`**. It is the correct place to call `Graph.provide(this)` exactly once, so the database exists before any `ViewModel` is created. This lecture adds `WishlistApp` `Application` and registers it in the manifest.

---

## Step 1 — create the class

`WishlistApp.kt`:

```kotlin
class WishlistApp : Application() {
    override fun onCreate() {
        super.onCreate()
        Graph.provide(this)
    }
}
```

| Override | When |
| :--- | :--- |
| `onCreate()` | Once per process, before `MainActivity.onCreate` |

`Graph.provide(this)` builds `WishDatabase` with the `Application` context — the safe, long-lived context that prevents leaks.

---

## Step 2 — register in Manifest

`AndroidManifest.xml`:

```xml
<manifest ...>
    <application
        android:name=".WishlistApp"
        android:icon="@mipmap/ic_launcher"
        android:theme="@style/Theme.Wishlist">
        <activity android:name=".MainActivity" ... />
    </application>
</manifest>
```

| Attribute | Value |
| :--- | :--- |
| `android:name` | `".WishlistApp"` (or fully qualified `eu.tutorials.wishlistapp.WishlistApp`) |

Without this entry, `Application.onCreate` never runs → `Graph.database` stays `lateinit` → crash `UninitializedPropertyAccessException` on first `WishViewModel` access.

---

## Verification

Delete the app's data (app info → Storage → Clear data) → reinstall. The DB file `wishlist.db` is recreated empty. The dummy list is gone — the `LazyColumn` is now empty until a write succeeds, proving the DB path is active.

---

## Recap / cheat sheet

- **App:** `class WishlistApp: Application() { override fun onCreate(){ Graph.provide(this)} }`.
- **Manifest:** `<application android:name=".WishlistApp">`.
- **Once:** `Graph.provide` is called exactly once per process.
