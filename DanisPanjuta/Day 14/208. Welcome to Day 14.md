# Welcome to Day 14

---

## Overview

Day 14 finishes the **Wishlist app** by adding **persistent storage** with **Room**. Yesterday's UI was in-memory via `DummyWish`; today every create/read/update/delete (**CRUD**) goes through a database that survives app kills and reboots.

---

## Why Room?

| Storage | Scope | Use case |
| :--- | :--- | :--- |
| `SharedPreferences` | Key-value, small primitives | Settings, flags |
| Internal/External files | Private/shared files | Images, exports |
| **SQLite** | Structured tables, queries | Full database engine |
| **Room** | Abstraction over SQLite | Type-safe DAOs, compile-time verification, `Flow` |

Room was created because raw SQLite is verbose and error-prone. Room provides an **abstract layer**: `@Entity` + `@Dao` + `@Database` + `Repository` + `Flow` + `ViewModel`.

## CRUD

| Operation | Method | Example |
| :--- | :--- | :--- |
| **Create** | `insert` | Add a new Wish |
| **Read** | `getWishes`, `getWishById` | Display list, open detail |
| **Update** | `update` | Edit title/description |
| **Delete** | `delete` | Swipe-to-delete |

Also: `Flow` for reactive observation, `Graph` singleton for dependency injection, `SwipeToDismiss` for UX.

## Recap / cheat sheet

- **Room** = SQLite + compile-time safety + `Flow`.
- **CRUD** = Create, Read, Update, Delete — all via `Dao` methods.
- **Architecture:** Entity → Dao → Database → Repository → ViewModel → UI (`Flow` + `collectAsState`).
