# Understanding and Using a Repository

---

## Overview

The **Repository** is a thin wrapper around the `Dao` that the `ViewModel` calls. It isolates the data source (Room today, network tomorrow) from the UI, making the `ViewModel` testable and source-agnostic — the pattern strongly recommended in Android Architecture Components.

---

## The class

`WishRepository.kt`:

```kotlin
class WishRepository(private val wishDao: WishDao) {

    suspend fun addWish(wish: Wish) {
        wishDao.addWish(wish)
    }

    fun getWishes(): Flow<List<Wish>> = wishDao.getAllWishes()

    fun getWishById(id: Long): Flow<Wish> = wishDao.getWishById(id)

    suspend fun updateWish(wish: Wish) {
        wishDao.updateWish(wish)
    }

    suspend fun deleteWish(wish: Wish) {
        wishDao.deleteWish(wish)
    }
}
```

| Member | Delegates to | Type |
| :--- | :--- | :--- |
| `addWish` / `updateWish` / `deleteWish` | `wishDao.*` | `suspend` → `ViewModel` calls on `Dispatchers.IO` |
| `getWishes` / `getWishById` | `wishDao.getAllWishes` / `getWishById` | `Flow` → `ViewModel` exposes as `Flow`, UI `collectAsState` |

> The lecture stresses naming: `wishDao.addWish` wraps `Wish` — the `wishEntity` parameter name in the `Dao` could be any name; the field is the `Wish` object.

---

## Where it is created (Graph, next)

```kotlin
val db = Room.databaseBuilder(context, WishDatabase::class.java, "wishlist.db").build()
val wishRepository = WishRepository(wishDao = db.wishDao())
```

The `Repository` is what the `ViewModel` holds — never the `Dao` directly.

---

## Recap / cheat sheet

- **Repository:** `class WishRepository(private val wishDao: WishDao) { suspend add/update/delete, Flow get* }`.
- **ViewModel** talks to **Repository**, not **Dao** — indirection = testability + source swapping.
