# Update An Existing Item

---

## Overview

The previous lecture already branched on `id` for update vs add, but `updateWish` was not yet exercised against a real row. This lecture verifies that editing a wish's title/description and pressing **Update Wish** writes the changed `Wish` (with the same `id`) back to Room and the list reflects the new values without a duplicate row.

---

## The update path

`WishDao`:

```kotlin
@Update
suspend fun updateWish(wishEntity: Wish) // matches by PK
```

`WishRepository`:

```kotlin
suspend fun updateWish(wish: Wish) = wishDao.updateWish(wish)
```

`WishViewModel`:

```kotlin
fun updateWish(wish: Wish) = viewModelScope.launch(Dispatchers.IO) {
    wishRepository.updateWish(wish)
}
```

`AddEditDetailView` (inside Button `onClick`):

```kotlin
if (id != 0L) {
    viewModel.updateWish(Wish(id = id, title = title.trim(), description = description.trim()))
} else {
    viewModel.addWish(Wish(title = title.trim(), description = description.trim()))
}
navController.navigateUp()
```

| Detail | Why |
| :--- | :--- |
| `Wish(id = id, ...)` | Must carry the original `id`; Room matches `UPDATE wishlist SET ... WHERE id=:id` |
| `trim()` | Removes accidental whitespace before persistence |
| `viewModelScope.launch(Dispatchers.IO)` | Disk write off main thread |
| `navigateUp()` after update | Return to `HomeView` where `collectAsState` recomposes the list |

---

## Verification

1. Tap an existing wish (*"Google Watch 2"*).
2. Change title to *"Google Watch 3"*.
3. Tap **Update Wish**.
4. List shows *"Google Watch 3"* in place — no second row, same `id`.

The lecture uses this as proof that `autoGenerate` + `@Update` + `id` propagation work together.

---

## Recap / cheat sheet

- **Update:** `Wish(id, newTitle, newDesc)` → `viewModel.updateWish` → `wishDao.updateWish` → Room `UPDATE` by PK.
- **Never** create a new `Wish` without `id` when updating — that would `INSERT` a duplicate.
