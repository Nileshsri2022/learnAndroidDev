## 🔧 Functions

### Anatomy

```kotlin
fun makeCoffee(sugarCount: Int, name: String): String {
    val result = "Coffee with $sugarCount spoons of sugar for $name"
    return result
}
```

| Part | Role |
| :--- | :--- |
| **`fun`** | Declares a function |
| **`makeCoffee`** | Name — **camelCase** in Kotlin |
| **`( )`** | **Parameters** — what goes in |
| **`: String`** | **Return type** — what comes out |
| **`{ }`** | Body — runs on every call |

### Calling

```kotlin
makeCoffee(1, "Amy")        // name + parentheses
```

* Definition **order doesn't matter** — `main` can call a function declared below it.
* **Argument order must match** parameter order.
* Adding a parameter **breaks every existing call** — the compiler lists them all.

### Naming conventions

Kotlin uses **camelCase**. C# capitalises from the first letter. Conventions **vary by
company**, so check the local style guide when you join a team.

---

## 📥 Parameters

```kotlin
fun makeCoffee(sugarCount: Int, name: String) { ... }
```

* Format: **`name: Type`** — the type is **mandatory**
* Multiple parameters are **comma-separated**, and may be **mixed types**
* Inside the body they behave like ordinary local variables, including in `$templates`

### Terminology

* **Parameter** = the variable declared in the definition
* **Argument** = the actual value passed at the call site

## 📤 Return Types

### Printing vs returning

| | Effect |
| :--- | :--- |
| `println(x)` | Shows a value to a human; it stays **inside** the function |
| `return x` | Hands the value **back to the caller** for further use |

Only **returned** values can be composed:

```kotlin
val total = add(add(1, 2), add(3, 4))     // 10
```

### The rules

1. Declare the type **after the parentheses**: `fun add(a: Int, b: Int): Int`
2. Declaring one makes **`return` mandatory** — *"A 'return' expression required in a
   function with a block body."*
3. A call to a returning function **is a value** — assign it, pass it, chain it
4. A function with no return type returns **`Unit`** (nothing)

## ⚠️ Integer Division Truncates

The day's most dangerous gotcha:

| Input | Expected | Actual |
| :--- | :--- | :--- |
| 3 ÷ 2 | 1.5 | **1** |
| 5 ÷ 3 | 1.666… | **1** |

**`Int / Int` discards the fractional part — it does not round.** No error, no warning; just
a quietly wrong answer.

#### The fix

```kotlin
fun divide(num1: Double, num2: Double): Double = num1 / num2

val num1 = readln().toDouble()      // not toInt()
```

Converting **one** operand to `Double` is enough — if any operand is a `Double`, the result
is a `Double`.

> Also: **rename variables when their type changes.** A `Double` called `num1Int` will
> mislead you later.

## 🧱 Classes and Objects

### The blueprint story

**Jimbo** draws a blueprint requiring a door, windows and a roof. **Frankie** and everyone
else build their own houses from it — each different in detail, all sharing the same
structure.

| Story | Kotlin |
| :--- | :--- |
| Blueprint | **Class** |
| A built house | **Object** (instance) |
| Required features | **Properties** and **functions** |

### A real class

```kotlin
class Dog(
    val name: String,
    val breed: String,
    var age: Int = 0
) {
    init {
        bark(name)
    }

    fun bark(name: String) {
        println("$name says woof woof")
    }
}
```

```kotlin
fun main() {
    val daisy = Dog("Daisy", "Dwarf Poodle")     // age defaults to 0
    val rocky = Dog("Rocky", "German Shepherd", 2)
}
```

### Key mechanics

| Concept | Meaning |
| :--- | :--- |
| **Primary constructor** | The parameter list in the class header |
| **`val` / `var` in the header** | Turns a parameter into an accessible **property** |
| **`init { }`** | Runs **automatically** the moment an object is created |
| **Default value** (`= 0`) | Used when the caller omits that argument |
| **Member function** | A function defined inside the class |

**Class names are PascalCase and singular** — `Dog`, not `dogs`.

## 🔑 Properties — Access and Mutation

```kotlin
daisy.age = 2              // ✅ var — can change
daisy.name = "Rex"         // ❌ val cannot be reassigned
```

| Declaration | Set at creation | Changeable later |
| :--- | :--- | :--- |
| `val name: String` | ✅ | ❌ |
| `var age: Int` | ✅ | ✅ |

**Rule of thumb:** fixed facts → `val`; evolving state → `var`.

Note the distinction:

```kotlin
val daisy = Dog(...)
daisy.age = 2               // ✅ mutate the object's property
daisy = Dog("Rex", "Lab")   // ❌ can't point at a different object
```

### String templates with properties

```kotlin
println("${daisy.name} is a ${daisy.breed}")   // ✅ braces required
println("$daisy.name")                         // ❌ only interpolates $daisy
```

## 📦 Data Classes

The reason the whole detour happened: a function returns **exactly one type**, but a coffee
needs a **name AND a sugar count**. The answer is an object.

```kotlin
data class CoffeeDetails(
    val sugarCount: Int,
    val name: String,
    val size: String,
    val creamAmount: Int
)

fun makeCoffee(coffeeDetails: CoffeeDetails) {
    println("Coffee with ${coffeeDetails.sugarCount} spoons of sugar " +
            "for ${coffeeDetails.name}")
}

fun main() {
    val coffeeForDennis = CoffeeDetails(
        sugarCount = 0, name = "Dennis", size = "XL", creamAmount = 0
    )
    makeCoffee(coffeeForDennis)
}
```

`data class` auto-generates:

| Method | Purpose |
| :--- | :--- |
| **`.toString()`** | Readable output: `CoffeeDetails(sugarCount=0, name=Dennis, …)` |
| **`.equals()` / `==`** | Compares by **value**, not identity |
| **`.copy()`** | Duplicates while changing selected properties |

**Where to put it:** same file if used locally; its own `CoffeeDetails.kt` if shared.

## ✅ Key Takeaways

1. **`fun name(params): ReturnType { }`** — write once, call anywhere.
2. **`return` hands a value back**; `println` only displays it. Returning enables
   composition.
3. **`Int / Int` truncates silently.** Use `Double` for division.
4. A **class is a blueprint**; an **object is an instance** of it.
5. **`val`/`var` in the constructor** creates properties; **`init`** runs on creation.
6. **`data class`** bundles several values so a function can return them as one.
7. **`${object.property}`** needs braces in string templates.
8. Day 4 = **lists and `for` loops**. Day 5 = back to Android with the **Unit Converter**.
