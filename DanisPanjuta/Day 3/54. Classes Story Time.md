Here is a clear, structured breakdown of the lecture that introduces **classes and objects**
through a story — the conceptual foundation for everything that follows.

---

### **1. The Story**

For most of history humans were **hunter-gatherers**, living in tents. Then winter came, and
tents weren't enough.

A man called **Jimbo** had an idea: *"We should build houses. I've drawn a **blueprint** —
build houses that follow it. You have some freedom, but each one must have a **door**,
**windows** and a **roof**."*

**Frankie** built one and lived comfortably. Others saw that and built their own — all
following Jimbo's blueprint. Soon there were houses everywhere, each different in detail but
all sharing the same essential structure.

---

### **2. The Mapping**

| Story | Kotlin |
| :--- | :--- |
| Jimbo's **blueprint** | **Class** |
| Each **house** actually built | **Object** (instance) |
| Required features — door, windows, roof | **Properties** and **functions** the class defines |
| Freedom in the details | Each object holds **different values** |

```kotlin
class House {            // the blueprint
    // door, windows, roof
}

val frankiesHouse = House()   // an actual house built from it
val yourHouse     = House()   // another one — same design, different instance
```

---

### **3. Why Blueprints Matter**

A class is a **contract**. It guarantees that every object created from it:

* has the same **properties**
* can do the same **things**

So code that works with one `House` works with **all** of them. That's what makes large
programs manageable — you reason about the blueprint, not the thousand instances.

---

### **4. Where This Sits in OOP**

Object-oriented programming has **three core pillars**. This lecture starts the first and
most basic one:

| Pillar | Idea |
| :--- | :--- |
| **1. Classes & objects** ← today | Bundle data and behaviour into reusable blueprints |
| **2. Inheritance** | A class builds on another's definition |
| **3. Polymorphism** | Different classes respond differently to the same call |

You already met inheritance on Day 1 without knowing it: `class MainActivity : ComponentActivity()`
— the colon means `MainActivity` inherits from `ComponentActivity`.

### **Key Takeaways**

1. A **class is a blueprint**; an **object is a thing built from it**.
2. One blueprint → **many objects**, each with its own values.
3. Classes are a **contract**: every instance has the same properties and capabilities.
4. Creating classes is the **first of three OOP pillars**; inheritance and polymorphism come
   later.
