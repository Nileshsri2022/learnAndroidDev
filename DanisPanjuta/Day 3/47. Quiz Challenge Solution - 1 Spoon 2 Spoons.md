Here is a clear, structured breakdown of the **quiz solution** for the singular/plural sugar
problem.

---

### **1. The Challenge**

The previous lecture printed:

```text
Coffee with 1 spoons of sugar
```

**"1 spoons"** is wrong. Fix the grammar.

> The instructor insists you **pause and try it first**: *"If you don't do it, you will not
> learn coding."* The struggle is where the aha-moment comes from — even a slow, messy attempt
> teaches more than watching.

---

### **2. The Solution**

Add a branch for the special case of exactly one:

```kotlin
fun makeCoffee(sugarCount: Int) {
    if (sugarCount == 1) {
        println("Coffee with one spoon of sugar")
    } else {
        println("Coffee with $sugarCount spoons of sugar")
    }
}
```

Output:

```text
Coffee with one spoon of sugar
Coffee with 2 spoons of sugar
Coffee with 30 spoons of sugar
```

Note the first branch hardcodes the word **"one"** rather than interpolating `$sugarCount` —
either works, but writing the number out reads better.

---

### **3. The Alternative Approach**

You could invert the condition:

```kotlin
if (sugarCount >= 2) {
    println("Coffee with $sugarCount spoons of sugar")
} else {
    println("Coffee with one spoon of sugar")
}
```

Both are correct. The instructor prefers the first because it isolates the **single special
case** and lets `else` handle everything else.

> If your code looks a little different but produces the same output — **that's fine**. There
> is rarely one right answer.

---

### **4. The Edge Cases**

| Input | Output | Correct? |
| :--- | :--- | :--- |
| `1` | one spoon | ✅ |
| `2` | 2 spoons | ✅ |
| `0` | 0 spoons | ✅ — English says "0 spoons", not "0 spoon" |
| `30` | 30 spoons | ✅ |
| `-5` | -5 spoons | ✅ grammatically, though nonsensical as an input |

The elegance of the chosen structure: **only `1` is special.** Zero and negatives both
correctly fall into the plural branch, which is how English actually works.

---

### **5. What This Teaches**

Small as it is, this is the pattern behind **all** output formatting:

* Identify the case that breaks the general rule
* Handle it explicitly
* Let the default branch cover everything else

You'll use exactly this reasoning for currency symbols, item counts in shopping lists and
notification text throughout the course.

---

### **Key Takeaways**

1. Special-case the value that **breaks the general rule** (`1`), and let `else` handle the
   rest.
2. **0 and negatives take the plural** — matching English, not arithmetic intuition.
3. There are **multiple valid solutions**; correctness matters more than matching the video.
4. **Always attempt exercises before watching the solution.** That is where learning happens.
