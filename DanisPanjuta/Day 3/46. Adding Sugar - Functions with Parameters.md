Here is a clear, structured breakdown of the lecture on **function parameters** — making a
function configurable instead of fixed.

---

### **1. The Problem**

Amy's machine makes the **same coffee every time**. She still has to add sugar by hand. Her
machine is too generic — it needs **input**.

The fix that makes everyone love it: let each person choose **sugar**, **cream** and **size**.
In Kotlin terms, those choices are **parameters**.

---

### **2. Parameter Syntax**

```kotlin
fun makeCoffee(sugarCount: Int) {
    println("Coffee with $sugarCount spoons of sugar")
}
```

| Part | Meaning |
| :--- | :--- |
| **`sugarCount`** | The parameter's **name** |
| **`:`** | Separator |
| **`Int`** | The parameter's **type** — required, always |

> **Parameter** = the variable you declare *inside* the function definition.
> **Argument** = the actual value you pass *when you call* it.

---

### **3. Adding a Parameter Breaks Existing Calls**

The moment you add `sugarCount`, every previous `makeCoffee()` call **stops compiling** — the
IDE flags them immediately. You must supply a value:

```kotlin
fun main() {
    makeCoffee(1)      // for Amy
    makeCoffee(2)      // for Jimmy
    makeCoffee(30)     // for Candice — mostly sugar, barely coffee
}
```

This is a **feature**: changing a function's signature forces you to update every caller, so
nothing silently keeps using the old behaviour.

---

### **4. Any Type, Any Value**

Because the parameter is typed `Int`, you can pass **any integer** — anything from
−2,147,483,648 to 2,147,483,647. Passing `"one"` would be a compile-time error.

---

### **5. Using the Parameter Inside**

The parameter behaves exactly like a local variable — including in **string templates**:

```kotlin
println("Coffee with $sugarCount spoons of sugar")
```

Output:

```text
Coffee with 1 spoons of sugar
Coffee with 2 spoons of sugar
Coffee with 30 spoons of sugar
```

---

### **6. Two Bugs Left — Your Exercises**

The instructor deliberately leaves two flaws and assigns them as quizzes:

1. **Grammar:** `"1 spoons"` should be `"1 spoon"` — singular vs plural.
2. **Who is it for?** The output never says whose coffee it is — which needs a **second
   parameter**, of type `String`.

Both are solved in the next two lectures.

---

### **Key Takeaways**

1. A **parameter** is declared as **`name: Type`** inside the parentheses — the type is
   **mandatory**.
2. Parameters make a function **reusable with different inputs** instead of hard-coded
   behaviour.
3. Adding a parameter **breaks every existing call** — the compiler tells you exactly which.
4. Inside the body, a parameter works like any other variable, including in
   **`$stringTemplates`**.
5. You can have **multiple parameters of different types** — that's the next lecture.
