Here is a clear, structured breakdown of the lecture on **return types** — making a function
give a value back instead of just printing.

---

### **1. Printing vs Returning**

These are different things:

| | What it does |
| :--- | :--- |
| **`println(result)`** | Shows the value to a human, **inside** the function. The value stays trapped there. |
| **`return result`** | Hands the value **back to the caller**, which can store it and keep working with it. |

A function that prints can't be composed. A function that returns can.

---

### **2. The Example: An Adder**

```kotlin
fun add(num1: Int, num2: Int): Int {
    val result = num1 + num2
    return result
}
```

| Part | Role |
| :--- | :--- |
| **`(num1: Int, num2: Int)`** | What goes **in** |
| **`: Int`** (after the parentheses) | What comes **out** |
| **`return result`** | Actually sends it back |

---

### **3. Declaring a Return Type Forces You to Return**

The moment you write `: Int`, Kotlin demands a value:

```kotlin
fun add(num1: Int, num2: Int): Int {
    val result = num1 + num2
}
```

> ❌ *"A 'return' expression required in a function with a block body."*

Add `return result` and the error clears.

---

### **4. A Function Call Behaves Like a Value**

Because `add` returns an `Int`, **the call itself is an `Int`** — you can assign it directly:

```kotlin
fun main() {
    val myResult = add(5, 10)     // myResult is Int, holding 15
    println(myResult)             // 15
}
```

> 💡 **Hover over any function** to see its full signature: parameter names and types, and
> the return type after the colon.

---

### **5. Unused Functions Are Greyed Out**

The instructor moves `makeCoffee` into a helper function `askCoffeeDetails()` that nothing
calls yet. Android Studio **greys out both** — a visual signal that the code exists but is
never reached. Useful for spotting dead code.

---

### **6. Why Return Types Matter**

Returning unlocks **composition** — feeding one function's output into another:

```kotlin
val total = add(add(1, 2), add(3, 4))    // 10
```

Every real app is built this way: small functions that each return a value, chained together.
The Day 4 BankAccountApp and every ViewModel later in the course depend on it.

---

### **Key Takeaways**

1. Declare the return type **after the parentheses**: `fun add(a: Int, b: Int): Int`.
2. Declaring one makes **`return` mandatory** — the compiler enforces it.
3. **Printing shows; returning hands back.** Only returned values can be reused.
4. A call to a returning function **is a value** — assign it, pass it, chain it.
5. **Hover** a function to read its signature.
6. Greyed-out code means **nothing calls it**.
7. A function with no return type returns **`Unit`** (effectively nothing).
