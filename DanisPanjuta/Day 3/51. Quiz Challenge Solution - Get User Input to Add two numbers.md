Here is a clear, structured breakdown of the **quiz solution** that feeds user input into the
`add` function.

---

### **1. The Challenge**

The adder worked, but with hard-coded numbers. Make it ask the user for both values.

---

### **2. The Solution**

```kotlin
fun main() {
    println("Enter the first number")
    val num1Str = readln()
    val num1Int = num1Str.toInt()

    println("Enter the second number")
    val num2Str = readln()
    val num2Int = num2Str.toInt()

    val myResult = add(num1Int, num2Int)
    println("The result is $myResult")
}

fun add(num1: Int, num2: Int): Int {
    val result = num1 + num2
    return result
}
```

Session:

```text
Enter the first number
25
Enter the second number
231
The result is 256
```

---

### **3. The Pattern — Twice Over**

Every numeric input follows the same three steps, which is why the `Str` / `Int` naming
convention is worth adopting:

```
1. prompt   →  println("...")
2. read     →  val xStr = readln()          // String
3. parse    →  val xInt = xStr.toInt()      // Int
```

---

### **4. Two Warnings From the Lecture**

#### Watch out when copy-pasting

The instructor copies the first block for the second number and nearly leaves the variable
named `num1`:

> *"When you copy, be careful."*

Copy-paste bugs — two variables with the same name, or one never updated — are among the most
common beginner errors, precisely because the code *looks* right.

#### Label your output

The first version printed a bare `3`. Adding context makes it usable:

```kotlin
println("The result is $myResult")     // "The result is 256"
```

A number with no label is meaningless to whoever reads the console.

---

### **5. What's New Here**

Nothing — and that's the point. This exercise **combines** things you already know:

* `readln()` + `.toInt()` — from Day 2
* A function with **parameters** and a **return type** — from the last two lectures

Being able to compose known pieces without new syntax is the actual skill being built.

---

### **Key Takeaways**

1. The **prompt → read → parse** pattern applies to every numeric input.
2. Name intermediate variables clearly (`num1Str`, `num1Int`) so the type is obvious.
3. **Copy-paste carefully** — renaming every occurrence is part of the job.
4. **Always label output.** `The result is 256`, not `256`.
5. Real programs are **compositions of things you already know**, not constant new syntax.
