Here is a clear, structured breakdown of the lecture on **accessing and changing an object's
properties** — the lecture that sits between *Constructors* and *Data Classes*.

---

### **1. Setup**

From the previous lecture:

```kotlin
class Dog(
    val name: String,
    val breed: String,
    var age: Int = 0
) {
    init {
        bark(name)
    }

    fun bark(name: String) {
        println("$name says woof woof")
    }
}
```

```kotlin
fun main() {
    val daisy = Dog("Daisy", "Dwarf Poodle", 1)
    println("${daisy.name} is a ${daisy.breed} and is ${daisy.age} years old")
}
```

---

### **2. Changing a `var` Property**

```kotlin
daisy.age = 2
println("A year has passed")
println("${daisy.name} is a ${daisy.breed} and is ${daisy.age} years old")
```

Output:

```text
Daisy says woof woof
Daisy is a Dwarf Poodle and is 1 years old
A year has passed
Daisy is a Dwarf Poodle and is 2 years old
```

**Dot notation** (`object.property`) both **reads** and **writes**. Assignment works from
outside the class because `age` is a `var`.

---

### **3. Trying to Change a `val` Property**

```kotlin
daisy.name = "Hello World"     // ❌ Val cannot be reassigned
```

Kotlin refuses. This is the same `val` / `var` rule from Day 2, now applied to object
properties.

---

### **4. The Design Rule This Gives You**

| Declaration | Set at creation? | Changeable later? |
| :--- | :--- | :--- |
| **`val name: String`** | ✅ | ❌ **Never** |
| **`var age: Int`** | ✅ | ✅ **Anytime** |

Choose per property:

* A dog's **name and breed** are fixed at birth → `val`
* A dog's **age** changes every year → `var`

This is how you **control access** to an object's state. It applies identically inside and
outside the class — you can't reassign `name` from within a member function either, because
it's only settable during initialisation.

---

### **5. Why It Matters**

This is the seed of **encapsulation**, which the Day 4 BankAccountApp builds on:

* `accountHolder` and `balance` are `var` — they legitimately change
* `transactionHistory` is `private` — it can't be touched from outside at all

Together, `val`/`var` and `private` let a class decide **exactly** what the outside world may
read and modify.

---

### **6. The Same Rule Applies to the Object Reference**

Note that `daisy` itself is a `val`:

```kotlin
val daisy = Dog("Daisy", "Dwarf Poodle", 1)
daisy.age = 2              // ✅ changing a property of the object
daisy = Dog("Rex", "Lab")  // ❌ val cannot be reassigned — can't point at a different dog
```

**`val` on the variable** freezes *which* object you're referring to.
**`var` on the property** controls whether that object's data can change.

---

### **Key Takeaways**

1. **Dot notation reads and writes**: `daisy.age` retrieves, `daisy.age = 2` updates.
2. A **`val` property cannot be reassigned** — the compiler blocks it, inside or outside the
   class.
3. A **`var` property can change** at any time.
4. Pick per property: fixed facts → `val`, evolving state → `var`.
5. `val daisy = ...` prevents **replacing the object**, not mutating it.
6. This is the foundation of **encapsulation**, developed fully in Day 4's BankAccountApp.
