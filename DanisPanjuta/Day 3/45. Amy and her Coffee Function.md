Here is a clear, structured breakdown of the lecture where you **write your first function** —
using the story of Amy and her coffee machine.

---

### **1. The Story**

**Amy** is a developer who cannot write a single line of code without coffee. She used to make
it the hard way — buy beans, grind them, heat the water, pour it through. Then she got a
**coffee machine**: press one button, and a function does all of that work for her.

That button press **is** a function call. Everything the function contains runs, and Amy just
collects the result.

---

### **2. Anatomy of a Function**

```kotlin
fun makeCoffee() {
    println("Buy beans")
    println("Grind beans")
    println("Heat water to 90°C")
    println("Add water")
    println("Push hot water through the ground beans")
}
```

| Part | Role |
| :--- | :--- |
| **`fun`** | The Kotlin keyword that declares a function |
| **`makeCoffee`** | The function's name |
| **`( )`** | The **parameter list** — how information gets passed in (empty for now) |
| *(no return type)* | This function returns nothing |
| **`{ }`** | The **body** — runs every time the function is called |

---

### **3. Defining vs Calling**

```kotlin
fun main() {
    makeCoffee()      // ← CALLING the function
}

fun makeCoffee() {    // ← DEFINING the function
    // ...
}
```

Calling is just **the name followed by parentheses**. Definition order doesn't matter —
`makeCoffee` can live below `main`.

---

### **4. Naming Conventions**

Kotlin uses **camelCase**: lowercase first word, capitalised words after —
`makeCoffee`, not `MakeCoffee` or `make_coffee`.

> ⚠️ Conventions **differ by language and by company**. C# capitalises from the first letter.
> When you join a team, check their style guide for functions, variables, classes and
> interfaces, then follow it.

---

### **5. The Point: Reuse**

Running the code once prints the five steps. But you can call it **as many times as you
like**:

```kotlin
fun main() {
    makeCoffee()
    makeCoffee()
    makeCoffee()
}
```

Each call re-executes the whole body.

#### Why not just put the `println`s in `main`?

Because then you'd have to **duplicate them every time**. With a function:

* You write the logic **once**
* You call it **anywhere**, as often as you need
* You fix a bug in **one place**

That is the entire value proposition of functions.

---

### **6. An Empty Function Does Nothing**

Before adding the `println` statements, calling `makeCoffee()` ran successfully and produced
**no output** — the body was empty. A function that does nothing is perfectly legal, which is
why the next lecture adds a parameter to make it actually useful.

---

### **Key Takeaways**

1. **`fun name() { }`** declares a function; **`name()`** calls it.
2. A function's body runs **every time** it is called — that's the reuse.
3. Kotlin naming is **camelCase**; other languages and companies differ, so check the local
   style guide.
4. Functions replace **copy-pasted code** with a single named block.
5. Definition **order doesn't matter** — `main` can call a function declared below it.
6. The next step is making the function **configurable** via parameters.
