### Why State Management is on Day 6
- Although our layout looks complete, clicking items does not yet update the UI dynamically.
- In declarative UI (Jetpack Compose), the UI is a direct reflection of **State**:
  - `state` drives `UI`.
  - User interactions change `state`.
  - Compose performs **Recomposition** to redraw only the affected widgets.
- Denis deliberately dedicated all of Day 6 to state management (`remember`, `mutableStateOf`, custom conversion logic) so beginners can grasp this foundational reactive concept without feeling rushed.

## ❓ Q&A

**Q: Why doesn't the button click update the text yet?**  
A: Because standard Kotlin variables inside a composable function are reset every time the function runs. To remember values across recompositions, we need Compose's `remember { mutableStateOf(...) }`, which is the core subject of Day 6.

**Q: Can I run today's project on my physical phone?**  
A: Yes! You can run today's layout on your physical phone or emulator immediately to inspect how the buttons, text fields, and dropdowns look and feel on real hardware.
