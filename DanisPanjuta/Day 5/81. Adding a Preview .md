Here is a structured breakdown and explanation of everything covered in this lesson on using Compose Previews.

---

### 1. What is `@Preview` and Why Use It?
* **Instant Feedback:** Normally, seeing changes in an Android app requires compiling, building the APK, and launching it on an emulator or physical device (which can be slow).
* **Split/Design View:** The `@Preview` annotation lets Android Studio render your UI directly inside the IDE in real-time, refreshing whenever you make changes to your composables.

---

### 2. Creating a Custom Preview Function

To set up a preview for your custom composable:

```kotlin
@Preview(showBackground = true)
@Composable
fun UnitConverterPreview() {
    UnitConverter()
}
```

* **Annotations Required:**
  * `@Preview`: Tells Android Studio to render this function in the preview canvas.
  * `@Composable`: Indicates this is a composable function that builds UI.
* **Naming Convention:** It is standard practice to name the function after the component it previews with the `Preview` suffix (e.g., `UnitConverter` $\rightarrow$ `UnitConverterPreview`).
* **No Parameters:** Preview functions cannot accept required parameters (unless using special preview parameter providers). They should call your target composable with sample/default data.

---

### 3. Key Preview Parameters: `showBackground`
By default, the Compose Preview renders transparent backgrounds, which can make white or dark elements hard to see.

* **`showBackground = true`:** Draws a standard background (white in light theme) behind your composables so you can clearly see margins, borders, and text contrast.

### Summary Checklist of Key Takeaways
1. **`@Preview` saves time:** Test and tweak UI layouts without waiting for the emulator to build and run.
2. **Preview Functions are private/standalone:** They simply wrap your actual UI composable to provide mock data and preview settings.
3. **`showBackground = true`:** Essential for viewing outlines, borders, and text contrast clearly against a solid background.
