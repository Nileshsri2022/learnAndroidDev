# Preparing The Models Based On The API

---

## Overview

Converts the OpenWeatherMap JSON into **Kotlin data classes** (package `models`) that GSON/Retrofit can fill. All implement `Serializable` so the response can later be stored.

---

## Models

```kotlin
data class WeatherResponse(
    val coord: Coord,
    val weather: List<Weather>,
    val base: String,
    val main: Main,
    val visibility: Int,
    val wind: Wind,
    val clouds: Clouds,
    val dt: Int,
    val sys: Sys,
    val id: Int,
    val name: String,
    val cod: Int
) : Serializable

data class Coord(val lon: Double, val lat: Double) : Serializable

data class Weather(val id: Int, val main: String, val description: String, val icon: String) : Serializable

data class Main(
    val temp: Double,
    val pressure: Double,
    val humidity: Int,
    val temp_min: Double,
    val temp_max: Double,
    val sea_level: Double,
    val grnd_level: Double
) : Serializable

data class Wind(val speed: Double, val deg: Int) : Serializable
data class Clouds(val all: Int) : Serializable

data class Sys(
    val type: Int,
    val message: Double,
    val country: String,
    val sunrise: Long,
    val sunset: Long
) : Serializable
```

- JSON object → data class; JSON array → `List<…>`.
- Names match the JSON keys exactly (`temp_min`, `grnd_level`).
- Missing keys are left at default/null by GSON — mark such fields nullable in production code.

---

## Recap / cheat sheet

- One data class per JSON object; `WeatherResponse` is the root.
- `sunrise/sunset` are Unix timestamps (`Long`).
