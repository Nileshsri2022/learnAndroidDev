# Nested and Inner Classes

---

## Overview

A class declared inside another class is either **nested** (default) or **inner** (with the `inner` keyword). The difference is whether it can access members of the outer class. Both are used later — e.g. a `ViewHolder` inside a RecyclerView adapter.

---

## Nested class

- Declared inside another class **without** `inner`.
- Behaves like a **static** class — you can use it **without an instance of the outer class**.
- **Cannot access** the outer class's members (one-way relationship).

```kotlin
class OuterClass {
    private var name: String = "Mr X"

    class NestedClass {
        var description: String = "code inside nested class"
        private var id: Int = 101
        fun foo() {
            // print("name is $name")  // ERROR — cannot access outer member
            println("Id is $id")
        }
    }
}

fun main() {
    println(OuterClass.NestedClass().description)   // no OuterClass instance needed
    val obj = OuterClass.NestedClass()
    obj.foo()                                      // Id is 101
}
```

---

## Inner class

- Declared with the keyword **`inner`**.
- Holds a reference to an outer instance → **can access outer members, even private ones**.
- Requires an instance of the outer class to be created.
- Cannot be declared inside interfaces or non-inner nested classes.

```kotlin
class OuterClass {
    private var name: String = "Mr X"

    inner class InnerClass {
        var description: String = "code inside inner class"
        private var id: Int = 101
        fun foo() {
            println("name is $name")   // OK — accesses outer private member
            println("Id is $id")
        }
    }
}

fun main() {
    println(OuterClass().InnerClass().description)
    val obj = OuterClass().InnerClass()
    obj.foo()
}
```

---

## Comparison

| | Nested | Inner |
| :--- | :--- | :--- |
| Keyword | none | `inner` |
| Needs outer instance | No — `Outer.Nested()` | Yes — `Outer().Inner()` |
| Accesses outer members | No | Yes |

> Prefer separate files for classes; use nested/inner only when the helper class is really only meaningful within the outer class.

---

## Recap / cheat sheet

- **Nested:** `class A { class B }` → `A.B()`, no access to `A`.
- **Inner:** `class A { inner class B }` → `A().B()`, full access to `A`.
