# Exception Handling With Try And Catch

---

## Overview

An **exception** is a runtime problem that would terminate the program — on a phone, the app freezes or closes. **Exception handling** catches these problems so the program keeps running (even if it can't do exactly what was intended).

---

## Typical exceptions

- Out of memory
- Array index out of bounds
- Divide by zero (`ArithmeticException`)
- No internet connection / I/O failure
- Parsing a non-number string (`NumberFormatException`)

---

## The four keywords

| Keyword | Role |
| :--- | :--- |
| `try` | Block containing code that might throw |
| `catch` | Handles a specific exception type thrown in `try` |
| `finally` | Always executes — whether or not an exception occurred (clean-up) |
| `throw` | Explicitly raises an exception |

All Kotlin exceptions descend from **`Throwable`**.

---

## Syntax

```kotlin
try {
    // code that may throw
} catch (e: SomeException) {
    // handle
} finally {
    // optional — always runs
}
```

---

## Example — divide by zero

```kotlin
fun main() {
    try {
        val data = 20 / 0          // ArithmeticException
    } catch (e: ArithmeticException) {
        println(e)                 // java.lang.ArithmeticException: / by zero
    } finally {
        println("finally block always executes")
    }
    println("code below exception...")   // program continues
}
```

---

## `try` is an expression

```kotlin
val number: Int? = try { input.toInt() } catch (e: NumberFormatException) { null }
```

---

## throw — custom validation

```kotlin
fun validate(age: Int) {
    if (age < 18) throw ArithmeticException("under age")
    else println("eligible for drive")
}
```

Custom exceptions: `class MyException(msg: String) : Exception(msg)`.

---

## Recap / cheat sheet

- **try / catch / finally / throw.**
- Catch **specific** exceptions; `finally` for cleanup.
- `try` can return a value.
- Handling ≠ fixing — show the user a meaningful message.
