# Overview Collections

---

## Overview

A **collection** is a group of values stored in one variable. Kotlin has two families:

1. Classes that hold **one primitive type** only (`IntArray`, `BooleanArray`, …).
2. Generic classes that can hold **one type or mixed types** (`Array`, `List`, `Set`, `Map`).

---

## Primitive array classes

| Class | Holds |
| :--- | :--- |
| `IntArray` | `Int` |
| `BooleanArray` | `true` / `false` |
| `DoubleArray` | `Double` |
| `FloatArray` | `Float` |
| `ByteArray` | `Byte` |
| `LongArray` / `ShortArray` | `Long` / `Short` |

What about `String`? → use the generic **`arrayOf(...)`**, which can hold any type (strings, custom classes, even mixed types).

---

## Generic collections

| Read-only (immutable) | Read / write (mutable) | Characteristic |
| :--- | :--- | :--- |
| `listOf()` | `mutableListOf()`, `arrayListOf()` | Ordered, index-based, duplicates allowed, many helper methods |
| `setOf()` | `mutableSetOf()`, `hashSetOf()` | **No duplicates**, unordered |
| `mapOf()` | `mutableMapOf()`, `hashMapOf()` | **Key → value** pairs |

```kotlin
val days = mapOf(1 to "Sunday", 2 to "Monday", 3 to "Tuesday")
```

---

## Why both flavours?

Having separate read-only and mutable types lets you **expose** a read-only view publicly while keeping the mutable version **private**:

```kotlin
private val _items = mutableListOf<String>()
val items: List<String> get() = _items
```

(This is exactly the pattern later used with `MutableState` / `LiveData` in ViewModels.)

---

## Recap / cheat sheet

- **Typed arrays:** `IntArray`, `DoubleArray`, `BooleanArray`…
- **Generic:** `arrayOf`, `listOf`, `setOf`, `mapOf` (read-only).
- **Mutable:** `mutableListOf`, `arrayListOf`, `mutableSetOf`, `hashSetOf`, `mutableMapOf`, `hashMapOf`.
- **Set = unique values; Map = key/value.**
