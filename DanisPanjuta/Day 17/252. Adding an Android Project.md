## 📝 Summary

Creating a Firebase project is only half the connection; you must register your Android client application with Firebase so Google's servers authorize requests originating from your app.

In this crucial setup lecture, Denis guides students through obtaining their exact Android package name from `build.gradle.kts`, generating their local developer machine's **SHA-1 certificate fingerprint** using the Gradle `signingReport` task, registering the app in the Firebase Console, downloading the generated `google-services.json` configuration file, placing it into the `app/` folder, and configuring the **Google Services Gradle plugin**.

## 📒 Detailed Instructions

### 1. Verifying the Package Name
In your project's `app/build.gradle.kts`:
```kotlin
android {
    defaultConfig {
        applicationId = "eu.tutorials.chatroomapp" // <-- MUST MATCH EXACTLY
        // ...
    }
}
```
The `applicationId` declared in Gradle must match the package name entered into Firebase character-for-character (case-sensitive). If they do not match, the Firebase SDK will throw an `IllegalStateException: Default FirebaseApp is not initialized`.

### 2. Generating the Debug SHA-1 Fingerprint
Certain Firebase authentication services (including Google Sign-In and Phone Auth) and security checks require verifying the cryptographic signature of the APK.

To generate your debug signing certificate fingerprint in Android Studio:
1. Open the **Gradle** tab on the far right tool strip of Android Studio.
2. Navigate to: **app → Tasks → android → signingReport** (or in modern Studio: run `./gradlew signingReport` in the built-in terminal).
3. Double-click **signingReport**.
4. The Gradle execution console will output:
   ```
   Variant: debugUnitTest
   Config: debug
   Store: /home/user/.android/debug.keystore
   Alias: AndroidDebugKey
   MD5:  2F:65:E8:4A:...
   SHA1: 4B:7C:19:92:DF:3A:8E:71:02:44:B6:81:AA:5D:88:E2:03:91:7F:C0
   SHA-256: 8D:41:A2:...
   ```
5. Copy the 20-byte **`SHA1:`** string.

### 3. Registering App in Firebase Console
1. In your Firebase Project Overview dashboard, click the **Android icon** (`</>`).
2. **Android package name:** Paste `eu.tutorials.chatroomapp`.
3. **App nickname:** Optional (e.g., `Chat Room Android`).
4. **Debug signing certificate SHA-1:** Paste the copied SHA-1 string.
5. Click **Register app**.

### 4. Downloading and Placing `google-services.json`
1. Click **Download google-services.json**.
2. **Where to place it:** Move the downloaded file into your Android project's **`app/` directory** (the module root folder, right next to `app/build.gradle.kts`).
   ```
   learnAndroidDev/
   └── TheChatRoom/
       ├── app/
       │   ├── google-services.json   <-- MUST BE PLACED HERE!
       │   ├── build.gradle.kts
       │   └── src/
       └── build.gradle.kts
   ```
3. ⚠️ **Critical Rules:**
   - Do **NOT** rename the file (do not let your browser save it as `google-services (1).json`).
   - Do **NOT** place it in the project root directory; it must be inside `app/`.

### 5. Configuring the Google Services Gradle Plugin
The `google-services.json` file is parsed at build time by Google's Gradle plugin, which extracts API keys and injects them into Android resources.

#### Top-level `build.gradle.kts` (Project):
```kotlin
plugins {
    alias(libs.plugins.android.application) apply false
    alias(libs.plugins.jetbrains.kotlin.android) apply false
    id("com.google.gms.google-services") version "4.4.1" apply false
}
```

#### Module-level `app/build.gradle.kts` (App):
```kotlin
plugins {
    alias(libs.plugins.android.application)
    alias(libs.plugins.jetbrains.kotlin.android)
    id("com.google.gms.google-services") // Apply Google services plugin
}
```

6. Click **Sync Now** in the top-right banner of Android Studio.

## 📌 Important Terms

| Term | Definition |
| :--- | :--- |
| **`google-services.json`** | Configuration manifest containing client IDs, API keys, and project URLs required by Firebase client SDKs. |
| **Google Services Plugin** | Gradle compiler plugin that reads `google-services.json` and generates `values.xml` resource keys at build time. |
| **`signingReport`** | Gradle task that prints the SHA-1 and SHA-256 cryptographic signatures of keystore signing keys. |
| **`debug.keystore`** | Default cryptographic key file automatically created by Android Studio to sign development builds. |

## ❓ Q&A

**Q: Should I commit `google-services.json` to GitHub?**  
A: For open-source public repositories with paid backend services, it is best practice to add `google-services.json` to `.gitignore` to prevent unauthorized quota consumption. For educational or private projects on the free tier, it is safe to commit.

**Q: What happens if I change my computer or work on a team?**  
A: Each developer computer has a unique `debug.keystore` with a different SHA-1 fingerprint. Team members can simply add their respective SHA-1 fingerprints to the same Android app in the Firebase Console under **Project Settings → Your apps**.

## ✅ Key Takeaways

1. 🎯 **Exact package match:** The package name in Firebase Console must match `applicationId` in `build.gradle.kts`.
2. 🔐 **SHA-1 links trust:** Generating the SHA-1 fingerprint via `signingReport` authorizes Google authentication flows.
3. 📁 **Correct file placement:** `google-services.json` belongs inside the `app/` module folder.
4. 🔌 **Plugin processes configuration:** The `com.google.gms.google-services` plugin translates the JSON into native Android resources at compile time.
