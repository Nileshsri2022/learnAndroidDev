## 📝 Summary

User authentication is essential for multi-user chat applications so messages can be attributed to specific senders. In this lecture, students enable the **Email/Password sign-in provider** in the Firebase Console and integrate the official **Firebase Android SDK** into their app via Gradle.

Denis demonstrates the modern recommended approach of using the **Firebase BoM (Bill of Materials)** to manage dependency versioning, imports `firebase-auth-ktx` (or modern `firebase-auth`), and explains the security rules that govern user creation on Google's cloud servers.

## 📒 Detailed Instructions

### 1. Enabling Email/Password in the Firebase Console
1. In the Firebase Console, expand the **Build** section in the left sidebar navigation.
2. Click **Authentication**.
3. If this is the first time using Auth in this project, click the **Get started** button.
4. Select the **Sign-in method** tab.
5. In the *Native providers* list, click on **Email/Password**.
6. Switch the first toggle **Enable** to **ON**.
   - *Note on Email Link (passwordless sign-in):* Leave the second switch (*Email link / passwordless sign-in*) disabled; we are using standard password credentials.
7. Click **Save**.
8. The provider status now displays **"Enabled"** with `0` registered users under the *Users* tab.

### 2. Adding Gradle Dependencies with Firebase BoM
Historically, managing versions across multiple Firebase libraries (Auth, Firestore, Storage, Messaging) was error-prone due to version incompatibilities. Google solved this with the **Firebase Bill of Materials (BoM)**.

In `app/build.gradle.kts`:
```kotlin
dependencies {
    // Import the Firebase BoM
    implementation(platform("com.google.firebase:firebase-bom:32.8.0"))

    // Firebase Authentication (no version number required — BoM decides compatible version)
    implementation("com.google.firebase:firebase-auth")

    // Cloud Firestore (for database storage in Day 18)
    implementation("com.google.firebase:firebase-firestore")

    // Kotlin Coroutines Play Services integration (enables .await() on Tasks)
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-play-services:1.7.3")

    // Jetpack Compose dependencies
    implementation(libs.androidx.activity.compose)
    implementation(platform(libs.androidx.compose.bom))
    implementation(libs.androidx.ui)
    implementation(libs.androidx.material3)
    implementation("androidx.lifecycle:lifecycle-viewmodel-compose:2.7.0")
    implementation("androidx.navigation:navigation-compose:2.7.7")
}
```

### 3. Understanding `kotlinx-coroutines-play-services`
- The standard Firebase Android SDK returns `Task<AuthResult>` callbacks using `.addOnSuccessListener` and `.addOnFailureListener`.
- While functional, callback-based code quickly results in unreadable nested callback pyramids ("callback hell").
- By importing `kotlinx-coroutines-play-services`, we unlock the **`.await()`** extension function:
  ```kotlin
  // Callback approach:
  auth.createUserWithEmailAndPassword(email, password)
      .addOnSuccessListener { result -> ... }
      .addOnFailureListener { exception -> ... }

  // Idiomatic Coroutines approach:
  val result = auth.createUserWithEmailAndPassword(email, password).await()
  ```
- This transforms asynchronous cloud calls into clean, sequential, suspendable Kotlin code!

## 📌 Important Terms

| Term | Definition |
| :--- | :--- |
| **Firebase BoM** | Bill of Materials — a Gradle dependency management platform that automatically selects compatible versions for all Firebase libraries. |
| **`FirebaseAuth`** | The entry point for the Firebase Authentication SDK in Android. |
| **`Task<T>`** | Google Play Services class representing an asynchronous operation that completes in the future. |
| **`.await()`** | Kotlin Coroutines extension that suspends execution until a Google Play Services `Task` finishes. |

## ❓ Q&A

**Q: Does Firebase enforce password rules out of the box?**  
A: Yes! Firebase Authentication enforces that all passwords must be **at least 6 characters long** by default. Submitting a 5-character password automatically throws a `FirebaseAuthWeakPasswordException`.

**Q: Can I add Google Sign-In or Phone Auth later?**  
A: Absolutely! You can return to the *Sign-in method* tab in the Firebase Console at any time and enable additional providers without breaking existing email/password accounts.
