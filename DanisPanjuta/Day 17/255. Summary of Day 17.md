## 📝 Day 17 Executive Summary

Day 17 marked the course's transition into **cloud-connected Android engineering**. Students moved beyond standalone offline applications to integrate Google Firebase as a comprehensive Backend as a Service (BaaS). 

Over the course of Day 17, we provisioned a cloud project in the Firebase Console, registered our Android application using its unique package name and cryptographic SHA-1 debug signing fingerprint, wired `google-services.json` and the Google Services Gradle plugin, enabled Email/Password authentication, and built clean MVVM registration and sign-in screens in Jetpack Compose powered by Kotlin Coroutines.

## ❓ Self-Check Questions

??? question "Why does Firestore require default values for all properties in data classes?"
    When Firestore retrieves a document from the cloud, it uses reflection to instantiate the data class via a zero-argument default constructor before populating its fields. Providing default values (e.g. `val email: String = ""`) automatically generates this default constructor in Kotlin.

??? question "What is the benefit of using `kotlinx-coroutines-play-services`?"
    Google Play Services Tasks use callback listeners (`addOnSuccessListener`, `addOnFailureListener`). The `kotlinx-coroutines-play-services` library provides `.await()`, allowing developers to suspend coroutines sequentially instead of nesting callbacks.

??? question "Where should `google-services.json` be located in the Android project tree?"
    It must be placed in the **`app/` module directory** (as a sibling to `app/build.gradle.kts`), NOT in the root project folder.
