# Reusing our LocationUtils from the previous lectures

---

## Overview

Location code is **boilerplate-heavy but stable**. The permission check and the `FusedLocationProviderClient` flow built on Day 11 look identical in every app that needs coordinates. Rather than re-typing them, this lecture copies `LocationUtils` wholesale into the Shopping List project — and discovers the missing `play-services-location` dependency in the process.

---

## Step 1 — open the Day 11 project side-by-side

Keep the **LocationApp** from Day 11 open (or open it in a **New Window** via *Recent Projects*). Locate `LocationUtils.kt`:

```text
LocationApp/
  app/src/main/java/eu/tutorials/locationapp/
    LocationData.kt
    LocationViewModel.kt
    LocationUtils.kt   ← copy from here
    MainActivity.kt
```

Select the entire file content — including the `package` header and all `import` statements — and **Copy**.

---

## Step 2 — create `LocationUtils` in the Shopping List project

In the **Shopping List** project (now the maps project):

**Right-click package → New → Kotlin File/Class → Class → `LocationUtils` →** replace its body with the copied text and let Android Studio adjust the package.

The file at this point typically looks like:

```kotlin
package eu.tutorials.myshoppinglistapp // ← updated to this module's package

import android.Manifest
import android.annotation.SuppressLint
import android.content.Context
import android.content.pm.PackageManager
import android.location.Address
import android.location.Geocoder
import android.os.Looper
import androidx.core.content.ContextCompat
import com.google.android.gms.location.FusedLocationProviderClient
import com.google.android.gms.location.LocationCallback
import com.google.android.gms.location.LocationRequest
import com.google.android.gms.location.LocationResult
import com.google.android.gms.location.LocationServices
import com.google.android.gms.location.Priority
import com.google.android.gms.maps.model.LatLng
import java.util.Locale

class LocationUtils(val context: Context) {

    private val _fusedLocationClient: FusedLocationProviderClient =
        LocationServices.getFusedLocationProviderClient(context)

    fun hasLocationPermission(context: Context): Boolean {
        return ContextCompat.checkSelfPermission(
            context, Manifest.permission.ACCESS_FINE_LOCATION
        ) == PackageManager.PERMISSION_GRANTED &&
                ContextCompat.checkSelfPermission(
                    context, Manifest.permission.ACCESS_COARSE_LOCATION
                ) == PackageManager.PERMISSION_GRANTED
    }

    @SuppressLint(\"MissingPermission\")
    fun requestLocationUpdates(viewModel: LocationViewModel) {
        val locationCallback = object : LocationCallback() {
            override fun onLocationResult(locationResult: LocationResult) {
                super.onLocationResult(locationResult)
                locationResult.lastLocation?.let {
                    val location = LocationData(
                        latitude = it.latitude,
                        longitude = it.longitude
                    )
                    viewModel.updateLocation(location)
                }
            }
        }

        val locationRequest = LocationRequest.Builder(
            Priority.PRIORITY_HIGH_ACCURACY, 1000
        ).build()

        _fusedLocationClient.requestLocationUpdates(
            locationRequest, locationCallback, Looper.getMainLooper()
        )
    }

    fun reverseGeocodeLocation(location: LocationData): String {
        val geocoder = Geocoder(context, Locale.getDefault())
        val coordinate = LatLng(location.latitude, location.longitude)
        val addresses: MutableList<Address>? =
            geocoder.getFromLocation(coordinate.latitude, coordinate.longitude, 1)
        return if (addresses?.isNotEmpty() == true) {
            addresses[0].getAddressLine(0)
        } else {
            \"Address not found\"
        }
    }
}
```

### What the class gives for free

| Member | Purpose |
| :--- | :--- |
| `hasLocationPermission(context)` | `ContextCompat.checkSelfPermission` against both fine and coarse — reused in the shopping list's **Address** button |
| `requestLocationUpdates(viewModel)` | Starts `FusedLocationProviderClient` with `Priority.PRIORITY_HIGH_ACCURACY` and `1000ms`, delivers via `LocationCallback` → `viewModel.updateLocation` |
| `reverseGeocodeLocation(location)` | Synchronous `Geocoder` → `getAddressLine(0)`. Not exercised in the Day 12 *Geocoding API* flow (Retrofit does remote geocoding), but harmless to keep and useful for fallback |
| `_fusedLocationClient` | Lazily bound to the passed `Context`; needs a valid activity context (`LocalContext.current`) |

## Step 3 — fix the missing dependency

If `LocationCallback`, `LocationRequest`, `Priority`, or `FusedLocationProviderClient` are red after pasting, `play-services-location` is missing (it was not among the dependencies added two lectures ago).

Add it to `app/build.gradle.kts`:

```kotlin
dependencies {
    implementation(\"com.google.android.gms:play-services-location:21.0.1\")
}
```

Click **Sync Now**. All red imports resolve.

> This side-by-side comparison is exactly how dependencies reveal themselves: the Day 11 file compiled, the same text fails here — the difference is the library that must be added.

---

## Do we still need `reverseGeocodeLocation`?

Day 12's authoritative address comes from the **Geocoding HTTP API** (`GeocodingApiService` + `RetrofitClient`), not from `Geocoder`. The method can be:

- **Kept** — costs nothing, useful as a local fallback;
- **Commented out** — to avoid lint warnings;
- **Deleted** — re-added later if needed.

The lecture keeps it in place and never calls it — the new `LocationViewModel.fetchAddress` is the active path.

## Where it is used next

`ShoppingListApp` will need four collaborating objects:

```kotlin
@Composable
fun ShoppingListApp(
    locationUtils: LocationUtils,       // ← this class, needs Context
    viewModel: LocationViewModel,       // ← previous lecture
    navController: NavController,       // ← navigation
    context: Context,                   // ← LocalContext.current
    address: String                     // ← derived from viewModel.address
)
```

The constructor argument `LocationUtils(context)` explains why `LocalContext.current` is needed wherever the shopping list is hosted — the utils cannot request permissions or start location updates without knowing *which* activity's permission window to use.

## Recap / cheat sheet

- **Copy** the entire `LocationUtils.kt` (including imports) from Day 11's LocationApp.
- **Package:** update to the Shopping List module's package.
- **Missing imports** → add `implementation(\"com.google.android.gms:play-services-location:21.0.1\")` and sync.
- **Kept members:** `hasLocationPermission`, `requestLocationUpdates` (active), `reverseGeocodeLocation` (harmless, unused).
- **Usage:** `LocationUtils(LocalContext.current)` → passed into `ShoppingListApp` alongside the shared `ViewModel` and `NavController`.
