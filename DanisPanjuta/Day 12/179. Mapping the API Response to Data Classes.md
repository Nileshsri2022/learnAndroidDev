# Mapping the API Response to Data Classes

---

## Overview

Retrofit can only deserialize JSON into Kotlin types that already exist. This lecture inspects the Geocoding JSON obtained in the browser test and creates three small **data classes** that match exactly the subset of fields the app cares about: the chosen coordinate, the envelope of the response, and the single formatted address string inside each result.

---

## The JSON shape (reference)

A successful Geocoding response (pretty-printed, trimmed):

```json
{
  \"results\": [
    {
      \"formatted_address\": \"1600 Amphitheatre Parkway, Mountain View, CA 94043, USA\",
      \"geometry\": {
        \"location\": { \"lat\": 37.422, \"lng\": -122.084 },
        \"location_type\": \"ROOFTOP\"
      },
      \"place_id\": \"ChIJ2eUgeAK6j4ARbn5u_wAGqWA\",
      \"types\": [\"street_address\"]
    }
  ],
  \"status\": \"OK\"
}
```

| JSON level | Kotlin mapping |
| :--- | :--- |
| The whole document | `GeocodingResponse` |
| Each entry in `results` | `GeocodingResult` |
| The single string `formatted_address` | `GeocodingResult.formatted_address: String` |
| The diagnostic `status` | `GeocodingResponse.status: String` |
| The user's chosen coordinate (not from this JSON) | `LocationData` |

Every other field (`geometry`, `place_id`, `types`) is ignored — the data classes need not declare it.

---

## Data class 1 — `LocationData`

The latitude/longitude chosen on the map. Created as a new Kotlin file/class → **Data class**:

```kotlin
data class LocationData(
    val latitude: Double,
    val longitude: Double
)
```

- Two `Double`s, no default values.
- `data` gives `equals`, `copy`, and `toString` for free, which is convenient when passing locations through `onLocationSelected` and logging.

> Name and fields are exactly as used on Day 11 — the class is recreated here so the Shopping List module is self-contained.

---

## Data class 2 — `GeocodingResult`

Only the formatted address is needed:

```kotlin
data class GeocodingResult(
    val formatted_address: String
)
```

- The JSON key uses **snake_case** (`formatted_address`). The Kotlin property keeps the same name so Gson maps it without an extra annotation.
- Alternative would be `@SerializedName(\"formatted_address\") val formattedAddress: String`, but the course keeps the underscore to stay literal and avoid the annotation.

---

## Data class 3 — `GeocodingResponse`

The envelope that wraps the array and the status:

```kotlin
data class GeocodingResponse(
    val results: List<GeocodingResult>,
    val status: String
)
```

- `results` is a `List<GeocodingResult>` — even when only one address is returned, the JSON always wraps it in an array.
- `status` lets the caller distinguish `OK` from `ZERO_RESULTS` or `REQUEST_DENIED` (the view model logs errors but otherwise treats non-OK as empty).

---

## How the three fit together

```text
User taps map
      │
      ▼
LocationData(latitude, longitude)          ← created from LatLng on click
      │
      ▼  passed as \"lat,lng\" string to Retrofit @Query
Geocoding API
      │
      ▼  JSON
GeocodingResponse
      ├── results: List<GeocodingResult>
      │         └── [0].formatted_address  ← \"1600 Amphitheatre Parkway, ...\"
      └── status: \"OK\"
```

The lecture deliberately shows a *garbage* formatted address for a nonsense coordinate (mid-ocean) — the structure is correct even when the string is not a real street.

## Recap / cheat sheet

- **LocationData:** `data class LocationData(val latitude: Double, val longitude: Double)`.
- **GeocodingResult:** `data class GeocodingResult(val formatted_address: String)` — keep snake_case.
- **GeocodingResponse:** `data class GeocodingResponse(val results: List<GeocodingResult>, val status: String)`.
- **Principle:** declare *only* fields that are used; Gson ignores the rest.
- **Flow:** `LocationData` → `latlng` query → `GeocodingResponse` → `results[0].formatted_address`.
