# Changing our ShoppingItems

---

## Overview

Before maps, each shopping entry was just `id + name + quantity + isEditing`. To attach a location, a fifth field — the **human-readable address** — is added to the data class, and the row composable (`ShoppingListItem`) is redesigned to show it with a location pin icon. `ShoppingListApp` itself is also changed from a parameter-less composable to one that explicitly takes the collaboration objects it will need for permission handling and navigation.

> A frozen emulator caused by the new Maps work briefly interrupts the recording — the emulator is wiped and recreated to restore a clean state.

---

## Step 1 — extend the data class

Open the file that defines the shopping model (typically `ShoppingList.kt` or `ShoppingItem.kt`).

Before:

```kotlin
data class ShoppingItem(
    val id: Int,
    var name: String,
    var quantity: Int,
    var isEditing: Boolean = false
)
```

After — add `address`:

```kotlin
data class ShoppingItem(
    val id: Int,
    var name: String,
    var quantity: Int,
    var isEditing: Boolean = false,
    var address: String = \"\"
)
```

| Property | Type | Default | Meaning |
| :--- | :--- | :--- | :--- |
| `id` | `Int` | — | Stable identity for `LazyColumn` keys |
| `name` | `String` | — | e.g. *Milk*, *Shoes* |
| `quantity` | `Int` | — | Units |
| `isEditing` | `Boolean` | `false` | Row editing mode |
| `address` | `String` | `\"\"` (or *No Address*) | Formatted address from `GeocodingResult.formatted_address` |

Defaulting `address` to `\"\"` keeps existing list construction working while the address dialog is being wired — new items simply start with an empty address until a location is chosen.

## Step 2 — redesign `ShoppingListItem` (the row)

Each list row (`ShoppingListItem` or `ShoppingItem`) previously showed `name` + `quantity` and two `IconButton`s (Edit, Delete). The lecture re-stacks that into a `Column` with two `Row`s.

### New structure

```kotlin
@Composable
fun ShoppingListItem(
    item: ShoppingItem,
    onEditClick: () -> Unit,
    onDeleteClick: () -> Unit
) {
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .padding(8.dp)
            .border(
                border = BorderStroke(2.dp, Color(0xFF018786)),
                shape = RoundedCornerShape(20)
            ),
        verticalAlignment = Alignment.CenterVertically
    ) {
        Column(
            modifier = Modifier
                .weight(1f)
                .padding(8.dp)
        ) {
            // Row 1 — name + quantity
            Row(modifier = Modifier.padding(8.dp)) {
                Text(text = item.name, modifier = Modifier.padding(8.dp))
                Text(text = \"Qty: ${item.quantity}\", modifier = Modifier.padding(8.dp))
            }
            // Row 2 — pin icon + address
            Row(modifier = Modifier.fillMaxWidth()) {
                Icon(
                    imageVector = Icons.Default.LocationOn,
                    contentDescription = null
                )
                Text(text = item.address)
            }
        }

        // Actions stay at the trailing edge — weightless, so they wrap content
        Row(modifier = Modifier.padding(8.dp)) {
            IconButton(onClick = onEditClick) {
                Icon(imageVector = Icons.Default.Edit, contentDescription = null)
            }
            IconButton(onClick = onDeleteClick) {
                Icon(imageVector = Icons.Default.Delete, contentDescription = null)
            }
        }
    }
}
```

Key details:

- **`weight(1f)`** on the `Column` gives the texts priority — the trailing `Row` of icons takes only the space it needs.
- **`Icons.Default.LocationOn`** is the pin icon (import `androidx.compose.material.icons.filled.LocationOn`). `contentDescription = null` is fine for a decorative icon alongside the text address.
- The inner `Row` with `fillMaxWidth()` for the address ensures the text can wrap below the name row.

Visual result (per row):

```text
┌────────────────────────────────────────────────┐
│  Milk         Qty: 2                [Edit][Del]│
│  📍 1600 Amphitheatre Pkwy, Mountain View, CA  │
└────────────────────────────────────────────────┘
```

### `ShoppingItemEditor` alignment

The inline editor used when `isEditing == true` takes `item.name` / `item.quantity` (`it.name`, `it.quantity`). A later bug fix sets the missing `address = address` in both the editor and the `AlertDialog` construction — otherwise edited items silently drop their address. The fix is covered in the integration video.

## Step 3 — change `ShoppingListApp`'s signature

The shopping list used to be self-contained:

```kotlin
@Composable
fun ShoppingListApp() { ... }
```

It now explicitly needs the collaboration objects that the map flow depends on:

```kotlin
@Composable
fun ShoppingListApp(
    locationUtils: LocationUtils,
    viewModel: LocationViewModel,
    navController: NavController,
    context: Context,
    address: String
) { ... }
```

| Parameter | Why it is needed |
| :--- | :--- |
| `locationUtils` | `hasLocationPermission(context)` and `requestLocationUpdates(viewModel)` |
| `viewModel` | Holds the chosen `LocationData` and the Retrofit-fetched `address` list |
| `navController` | `navigate(\"location_screen\")` from the **Address** button |
| `context` | Required for permission checks and `LocalContext.current` at call site |
| `address` | The rendered address string — `viewModel.address.value.firstOrNull()?.formatted_address ?: \"No Address\"` — passed in rather than read inside |

> Until `Navigation` supplies these arguments, `ShoppingListApp()` calls turn red. That is expected and resolved once the `NavHost` is added in `MainActivity`.

## Recap / cheat sheet

- **Data class:** add `var address: String = \"\"` to `ShoppingItem`.
- **Row UI:** `Row` (card) → `Column(weight=1f)` → `Row` (name + qty) + `Row` ( `Icon(LocationOn)` + `Text(item.address)` ) → trailing `Row` (Edit/Delete `IconButton`s).
- **Editor / Dialog:** remember to forward `address = address` when creating or updating a `ShoppingItem`.
- **ShoppingListApp params:** `(locationUtils, viewModel, navController, context, address: String)`.
- **Why:** weight gives text priority, the trailing action row wraps, and the hoisted parameters make the composable testable and navigation-aware.
