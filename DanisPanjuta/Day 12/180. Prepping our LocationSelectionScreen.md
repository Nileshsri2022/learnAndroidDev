# Prepping our LocationSelectionScreen

---

## Overview

The shopping list should let the user **choose** where to buy each item. This lecture adds a new composable — `LocationSelectionScreen` — that will become the map picker. It does not yet show a map; it prepares the **state** the map will need: the selected coordinate (`LatLng`) and the camera position that frames the map around that coordinate.

---

## The contract

`LocationSelectionScreen` is a reusable pop-up. Its parent (the navigation graph) decides what happens once a location is chosen.

```kotlin
@Composable
fun LocationSelectionScreen(
    location: LocationData,
    onLocationSelected: (LocationData) -> Unit
)
```

| Parameter | Type | Role |
| :--- | :--- | :--- |
| `location` | `LocationData` | The coordinate the map should centre on when first opened — usually the phone's current position or the last chosen point |
| `onLocationSelected` | `(LocationData) -> Unit` | Callback invoked with the **new** `LocationData` when the user taps **Set Location**. The parent decides how to store and geocode it |

This callback pattern is the same hoisting seen in Navigation (Day 10): screens do not navigate or persist themselves — they call a lambda handed to them.

## Step 2 — remember the selected coordinate as `LatLng`

Google Maps models a point as `LatLng` (from `com.google.android.gms.maps.model`), not as the app's own `LocationData`.

```kotlin
val userLocation = remember {
    mutableStateOf(LatLng(location.latitude, location.longitude))
}
```

- `LatLng(double latitude, double longitude)` — the Maps SDK's value type for any point.
- `remember { mutableStateOf(...) }` keeps the tapped point across recompositions.
- Initial value is the incoming `location` — so the map opens centred on the current/last position.
- Hovering over `LatLng` confirms the contract: *\"LatLng(latitude: Double, longitude: Double)\"*.

> `remember` must be imported from `androidx.compose.runtime.remember` and `mutableStateOf` from the same package. Android Studio's autocomplete offers the correct one.

---

## Step 3 — remember the camera position

A Google Map is viewed through a **camera**. Its position is a `CameraPosition` that combines a target `LatLng` and a **zoom level**.

```kotlin
val cameraPositionState = rememberCameraPositionState {
    position = CameraPosition.fromLatLngZoom(userLocation.value, 10f)
}
```

- `rememberCameraPositionState { ... }` is the Maps Compose wrapper that survives recomposition.
- `CameraPosition.fromLatLngZoom(userLocation.value, 10f)` frames the map around `userLocation` at zoom `10f`.

### What does zoom `10f` mean?

Open `https://www.google.com/maps` and drag the zoom control. The number in the URL (or in the `maps-compose` camera) maps to:

| Zoom | View |
| :--- | :--- |
| `2f` | Continent |
| `10f` | City/district — the default used in the lecture |
| `15f` | Streets and building footprints |
| `18f` | Individual buildings |

`10f` is a comfortable default for picking a store; higher values can be used if street names must be legible without pinch-zooming.

## Why both states?

```text
Incoming LocationData (lat, lng)
        │
        ▼
userLocation: MutableState<LatLng>     ← changes on every map tap (onMapClick)
        │
        ▼
cameraPositionState                   ← initialized from userLocation, animates the viewport
```

- `userLocation` is the **selection** — the red marker follows it.
- `cameraPositionState` is the **viewport** — where the map looks. Because it is derived from `userLocation` at creation and then updated by user interaction, the map animates naturally when `userLocation` changes.

On the emulator a drag or `Ctrl + scroll` (on macOS `⌘ + scroll`) zooms the map; `userLocation` is completely independent of that gesture-based camera movement.

- **File:** `LocationSelectionScreen.kt`.
- **Signature:** `fun LocationSelectionScreen(location: LocationData, onLocationSelected: (LocationData) -> Unit)`.
- **State:** `val userLocation = remember { mutableStateOf(LatLng(location.latitude, location.longitude)) }`.
- **Camera:** `val cameraPositionState = rememberCameraPositionState { position = CameraPosition.fromLatLngZoom(userLocation.value, 10f) }`.
