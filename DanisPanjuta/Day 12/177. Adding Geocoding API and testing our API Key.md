# Adding Geocoding API and testing our API Key

---

## Overview

Displaying a map is only half the feature. Turning a latitude/longitude into a human-readable street address requires the **Geocoding API**. This lecture enables that second API for the same Cloud project (*The Shopper*), then tests the key by issuing a raw HTTP call from a browser — proving whether the key is valid, whether it is restricted, and what JSON it returns.

---

## Step 1 — enable the Geocoding API

1. In the Cloud Console, ensure **The Shopper** project is selected (header dropdown).
2. Go to **APIs & Services → Enabled APIs & services → + Enable APIs and Services**.
3. Search for **`Geocoding API`** (under the Places/Maps family). If not visible on the landing cards, use the search bar.
4. Click **Enable**.

Now two APIs are enabled for this project:

| API | Purpose |
| :--- | :--- |
| **Maps SDK for Android** | Renders `GoogleMap` inside the app |
| **Geocoding API** | Converts `lat,lng ↔ address` via `https://maps.googleapis.com/maps/api/geocode/json` |

Both are metered against the same API key and the same $200 free quota.

---

## Step 2 — build the test URL

The Geocoding endpoint is a plain HTTP GET:

```
https://maps.googleapis.com/maps/api/geocode/json?latlng=LAT,LNG&key=YOUR_API_KEY
```

Example from the lecture:

```
https://maps.googleapis.com/maps/api/geocode/json?latlng=37.422,-122.084&key=AIza...YourKey
```

| Segment | Meaning |
| :--- | :--- |
| `maps/api/geocode/json` | The geocoding product, JSON format |
| `latlng=37.422,-122.084` | A sample coordinate (Googleplex, Mountain View) — any comma-separated `latitude,longitude` works |
| `key=AIza...` | The API key copied from **Credentials → Show key** |

Paste the assembled URL into a desktop browser address bar and press Enter.

---

## Step 3 — read the response (or the error)

### If the key has an Android restriction

The browser is not an Android app, so the response is an error:

```json
{
  \"error_message\" : \"This IP, site or mobile application is not authorized to use this API key.\",
  \"results\" : [],
  \"status\" : \"REQUEST_DENIED\"
}
```

**This is the correct behaviour** — it proves the Android package + SHA-1 restriction works. A stolen key cannot be exercised from the web.

To continue testing, temporarily remove the restriction:

- **Credentials → Edit API key → Application restrictions → None → Save.**
- A yellow banner appears: *\"Unrestricted. To prevent unauthorized use and quota theft, restrict your key.\"* — expected and temporary.

Reload the browser URL.

### If the key is unrestricted (or correctly restricted for Android after testing)

The response is a successful geocoding payload:

```json
{
  \"results\" : [
    {
      \"formatted_address\" : \"1600 Amphitheatre Parkway, Mountain View, CA 94043, USA\",
      \"geometry\" : {
        \"location\" : { \"lat\" : 37.422, \"lng\" : -122.084 },
        \"location_type\" : \"ROOFTOP\"
      },
      \"place_id\" : \"ChIJ2eUgeAK6j4ARbn5u_wAGqWA\",
      \"types\" : [ \"street_address\" ]
    }
  ],
  \"status\" : \"OK\"
}
```

Important fields:

| Field | Meaning |
| :--- | :--- |
| `results` | An **array** of matches — often one element, but can be many |
| `results[0].formatted_address` | The human-readable line the app will display — the only field the app keeps |
| `geometry.location` | Echo of the queried `lat/lng` |
| `status` | `OK`, `ZERO_RESULTS`, `REQUEST_DENIED`, `OVER_QUERY_LIMIT`, etc. |

Even a nonsensical coordinate returns valid JSON — only `formatted_address` is garbled or empty, which is why the lecture briefly shows a weird address for an arbitrary test lat/lng.

---

## Step 4 — re-restrict the key

Once the browser test has confirmed the JSON structure, restore the protection:

- **Credentials → Edit API key → Application restrictions → Android apps → Done → Save.**

The key is now restricted again and the earlier browser URL will return `REQUEST_DENIED` — which is fine, because the **Android app** will now be the only authorized caller.

---

## Why test in the browser at all?

- It verifies **without running the app** that billing is wired, the key is copied correctly, and the Geocoding API is enabled.
- It reveals the **shape of the JSON** that the Kotlin data classes must match in the next video.
- It demonstrates **quota theft**: any unrestricted key visible on the web can be copied by scanners and burned through.

---

## Recap / cheat sheet

- **Enable:** Cloud Console → **Geocoding API** → **Enable** (in addition to Maps SDK for Android).
- **Test URL:** `https://maps.googleapis.com/maps/api/geocode/json?latlng=LAT,LNG&key=KEY`.
- **Android-restricted key** in browser → `REQUEST_DENIED` → proves restriction works → set to **None** to test JSON → **re-restrict** to Android apps after.
- **Success JSON:** `{ results: [ { formatted_address, geometry } ], status: \"OK\" }`.
- **App keeps:** `results[i].formatted_address` only; everything else is ignored.
