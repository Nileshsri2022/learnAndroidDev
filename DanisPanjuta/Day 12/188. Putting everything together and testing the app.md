# Putting everything together and testing the app

---

## Overview

All the pieces exist in isolation — data classes, `LocationSelectionScreen`, `LocationViewModel`, `LocationUtils`, the Retrofit service, the redesigned `ShoppingItem`, and the permission launcher — but `MainActivity` still hosts the old shopping list directly, so nothing connects. This long integration lecture builds a **`Navigation` composable** with a `NavHost` that hosts both the shopping list **and** the map picker (as a `dialog`), wires the shared `ViewModel`, `Context`, `LocationUtils`, and the resolved address together, adds the required **manifest permissions**, and fixes two bugs discovered while live-testing.

---

## Step 1 — create the `Navigation` composable

In `MainActivity.kt` (or a new `Navigation.kt`) add:

```kotlin
@Composable
fun Navigation() {
    val navController = rememberNavController()
    val viewModel: LocationViewModel = viewModel()
    val context = LocalContext.current
    val locationUtils = LocationUtils(context)

    NavHost(navController = navController, startDestination = \"shoppingList\") {
        composable(\"shoppingList\") {
            ShoppingListApp(
                locationUtils = locationUtils,
                viewModel = viewModel,
                navController = navController,
                context = context,
                address = viewModel.address.value.firstOrNull()?.formatted_address ?: \"No Address\"
            )
        }
        dialog(\"location_screen\") { backStackEntry ->
            viewModel.location.value?.let { it1 ->
                LocationSelectionScreen(
                    location = it1,
                    onLocationSelected = { locationData ->
                        viewModel.fetchAddress(\"${locationData.latitude},${locationData.longitude}\")
                        navController.popBackStack()
                    }
                )
            }
        }
    }
}
```

### Pieces explained

| Piece | Why it exists |
| :--- | :--- |
| `rememberNavController()` | Owns the back stack; must be `NavHostController` for `NavHost` |
| `viewModel()` | Single `LocationViewModel` scoped to the activity — shared by both destinations so the address survives navigation |
| `LocalContext.current` | Provides the activity context that `LocationUtils` needs to request permissions and to create the fused location client |
| `LocationUtils(context)` | The Day 11 helper — created once here and handed to the shopping list |
| `NavHost(startDestination = \"shoppingList\")` | The graph — the shopping list is what the user sees on launch |
| `composable(\"shoppingList\") { }` | The main destination — hosts `ShoppingListApp` with **all five** required arguments |
| `dialog(\"location_screen\")` | A **navigation dialog** — appears as a pop-up over the current destination, not a full-screen replacement. Import `androidx.navigation.compose.dialog`, not the Material `Dialog` |
| `address = viewModel.address.value.firstOrNull()?.formatted_address ?: \"No Address\"` | Derives the rendered string. `firstOrNull()` safely handles an empty result list; the elvis operator supplies the placeholder until a location is selected |
| `viewModel.location.value?.let { it1 -> }` | Guards the map: it only opens if a location was already obtained (via `requestLocationUpdates`). `it1` (renamed from `it` for clarity) is the `LocationData` to centre the map |
| `onLocationSelected = { locationData -> viewModel.fetchAddress(\"${it.latitude},${it.longitude}\"); navController.popBackStack() }` | Converts the map pick back to a query string, triggers the Retrofit call, and **dismisses the dialog** as if the system Back button was pressed |
| `popBackStack()` | Pops the `location_screen` entry, revealing the underlying `shoppingList` destination — the **definition** of a dialog in Navigation Compose |

#### Naming confusion inside the lambdas

Two `it`s are in scope: `it1` (outer `let` on `viewModel.location.value`) and `it` (inner `onLocationSelected` parameter = `LocationData`). The lecture renames the outer one to `it1` and the inner to `locationData` to keep them distinct:

```kotlin
viewModel.location.value?.let { it1 ->           // ← locationData of the phone, to centre the map
    LocationSelectionScreen(
        location = it1,
        onLocationSelected = { locationData ->  // ← new pick from the map
            viewModel.fetchAddress(\"${locationData.latitude},${locationData.longitude}\")
            navController.popBackStack()
        }
    )
}
```

## Step 2 — call `Navigation` from `onCreate`

`onCreate` becomes trivial — it no longer owns the shopping list directly:

```kotlin
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            MyShoppingListAppTheme {
                Surface(
                    modifier = Modifier.fillMaxSize(),
                    color = MaterialTheme.colorScheme.background
                ) {
                    Navigation() // ← instead of ShoppingListApp()
                }
            }
        }
    }
}
```

Only `Navigation` is hoisted to `setContent`; everything else is resolved inside it.

## Step 3 — manifest permissions

The maps dialog and the network call need declarations outside `<application>`:

```xml
<manifest xmlns:android=\"http://schemas.android.com/apk/res/android\">
    <uses-permission android:name=\"android.permission.ACCESS_COARSE_LOCATION\" />
    <uses-permission android:name=\"android.permission.ACCESS_FINE_LOCATION\" />
    <uses-permission android:name=\"android.permission.INTERNET\" />

    <application
        ... >
        <meta-data
            android:name=\"com.google.android.geo.API_KEY\"
            android:value=\"YOUR_API_KEY\" />
        <activity ... />
    </application>
</manifest>
```

| Permission | Needed for |
| :--- | :--- |
| `ACCESS_COARSE_LOCATION` / `FINE` | `FusedLocationProviderClient`; the permission flow already requests both |
| `INTERNET` | Retrofit's HTTP call to `maps.googleapis.com`; without it the response is a silent `UnknownHostException` |

## Step 4 — live-test and the two bug fixes

### Initial run

1. Tap **Add Item** → an empty `AlertDialog` appears with name, quantity, and **address** button.
2. Tap **address** → the system permission dialog appears: *Allow MyShoppingListApp to access this device's location?* → choose **While using the app**.
3. Tap **address** again → the **map** appears (may take 1–2 seconds to load tiles). `Ctrl + scroll` (or `⌘ + scroll` on macOS) zooms; drag pans.
4. Tap anywhere on the map → the red **Marker** jumps to that point.
5. Press **Set Location** → the dialog dismisses.

### Bug 1 — address never fills

After the first test, pressing **Set Location** dismisses the map but the address line under the item is still empty.

**Cause:** `ShoppingItemEditor` (the inline row editor, inside `ShoppingListItem` when `isEditing`) constructs a new `ShoppingItem` with only `name`, `quantity`, `isEditing` — it drops `address`.

**Fix** inside the editor:

```kotlin
// from
it.name / it.quantity branching
// to
ShoppingItemEditor(item = it) { editedName, editedQuantity ->
    sItems = sItems.map { item ->
        if (item.id == it.id) item.copy(name = editedName, quantity = editedQuantity, address = address)
        else item
    }
}
```

Set `address = address` — the hoisted address string that `Navigation` already computed.

### Bug 2 — new items have no address

Even after fixing the editor, adding a brand-new item still shows no address.

**Cause:** the `AlertDialog`'s **Add** path also constructs `ShoppingItem(id, name, quantity)` without `address`.

**Fix** in the `AlertDialog` `confirmButton`:

```kotlin
Button(onClick = {
    if (itemName.isNotBlank()) {
        val newItem = ShoppingItem(
            id = sItems.size + 1,
            name = itemName,
            quantity = itemQuantity.toIntOrNull() ?: 1,
            address = address // ← add this
        )
        sItems = sItems + newItem
        showDialog = false
        itemName = \"\"
        itemQuantity = \"\"
    }
}) { Text(\"Add\") }
```

### After both fixes — second test

1. **Add Item** → **address** → grant → map → tap a street (e.g. *Colony St*) → **Set Location** → address resolves to *\"1600 Amphitheatre Parkway...\"* (or the selected street).
2. Type **Pixel Fold**, quantity **1**, **Add** → the list row shows:

```text
Pixel Fold   Qty: 1       [Edit] [Delete]
📍 1600 Amphitheatre Parkway, Mountain View, CA
```

3. Add a second item — *Shoes* — panned to a different city (e.g. Latham St) → a different formatted address appears beneath it. The emulator's map tiles may blur briefly while panning — expected when dragging far on a debug build.

The lecture notes that a loading indicator for the 1–2 second map load would be nice but is not added — the blank dialog moment is acceptable for the course app.

## The complete call graph

```text
MainActivity.setContent → Navigation()
      ├── NavHost(startDestination = \"shoppingList\")
      │       ├── composable(\"shoppingList\")
      │       │        viewModel.address.value.firstOrNull()?.formatted_address ?: \"No Address\"
      │       │                 │
      │       │                 ▼
      │       │        ShoppingListApp(locationUtils, viewModel, navController, context, address)
      │       │             ├── AlertDialog → Button(\"address\")
      │       │             │         ├── hasPermission → requestLocationUpdates(viewModel) + navigate(\"location_screen\")
      │       │             │         └── !hasPermission → launcher.launch(arrayOf(FINE, COARSE))
      │       │             └── LazyColumn → ShoppingListItem → Column(weight=1f) → Row(name/qty) + Row(📍 address)
      │       │
      │       └── dialog(\"location_screen\") — pop-up
      │                viewModel.location.value?.let { it1 ->
      │                    LocationSelectionScreen(location = it1) { picked: LocationData ->
      │                        viewModel.fetchAddress(\"${picked.latitude},${picked.longitude}\")
      │                        navController.popBackStack()   // dismiss dialog, reveal list
      │                    }
      │                }
      │                    ├── GoogleMap(cameraPositionState, onMapClick = { userLocation.value = it })
      │                    │         └── Marker(state = MarkerState(position = userLocation.value))
      │                    └── Button(\"Set Location\") → onLocationSelected(LocationData(lat, lng))
      │
      └── Manifest permissions: COARSE + FINE + INTERNET, plus <meta-data geo.API_KEY>
```

## Recap / cheat sheet

- **Navigation graph:** `rememberNavController()` → `viewModel()` → `LocalContext.current` → `LocationUtils(context)` → `NavHost` → `composable(\"shoppingList\")` + `dialog(\"location_screen\")`.
- **Address projection:** `viewModel.address.value.firstOrNull()?.formatted_address ?: \"No Address\"`.
- **Map → list:** `LocationSelectionScreen(location = it1, onLocationSelected = { viewModel.fetchAddress(\"${it.latitude},${it.longitude}\"); popBackStack() })`.
- **Manifest:** `ACCESS_COARSE_LOCATION` + `ACCESS_FINE_LOCATION` + `INTERNET` + `<meta-data android:name=\"com.google.android.geo.API_KEY\" />`.
- **Bug fixes:** set `address = address` inside `ShoppingItemEditor` and inside `AlertDialog`'s `new ShoppingItem(...)`.
- **Emulator tip:** `Ctrl + scroll` (or `⌘ + scroll`) to zoom the map; drag to pan.
