# Adding the LocationViewModel

---

## Overview

Selection on the map is transient `LatLng` state inside one composable. To survive recomposition, screen rotation, and navigation to the address list, the app needs a **ViewModel** that owns two pieces of state: the chosen `LocationData` and the resolved human-readable **address** (`List<GeocodingResult>`). This lecture builds that `LocationViewModel`.

---

## Step 1 — create the file

**Right-click package → New → Kotlin File/Class → Class → `LocationViewModel`**

It extends `ViewModel` from `androidx.lifecycle`:

```kotlin
import androidx.lifecycle.ViewModel

class LocationViewModel : ViewModel() {
    // ...
}
```

Android Studio offers *Add dependency and import* on the `ViewModel` keyword — accept it. The dependency should already be present from the previous video: `lifecycle-viewmodel-compose`.

---

## Step 2 — hold the location

The same backing-property pattern from Day 11:

```kotlin
class LocationViewModel : ViewModel() {

    private val _location = mutableStateOf<LocationData?>(null)
    val location: State<LocationData?> = _location

    fun updateLocation(newLocation: LocationData) {
        _location.value = newLocation
    }
}
```

| Member | Visibility | Type | Role |
| :--- | :--- | :--- | :--- |
| `_location` | `private` | `MutableState<LocationData?>` | Write-only inside the ViewModel, initially `null` (no selection yet) |
| `location` | public | `State<LocationData?>` | Read-only from the UI |
| `updateLocation` | public | `(LocationData) -> Unit` | The single way in — called from `LocationUtils.requestLocationUpdates` or from the map's `onLocationSelected` path |

The correct `State` is **`androidx.compose.runtime.State`**. Other `State` types compile but break composition. The import to keep is:

```kotlin
import androidx.compose.runtime.State
import androidx.compose.runtime.mutableStateOf
```

`null` again means *no location yet* — prefer it over `(0.0, 0.0)`, which is a real coordinate in the Gulf of Guinea.

## Step 3 — hold the address (added here, fully wired later)

Retrofit will fetch the address asynchronously and produce `List<GeocodingResult>`. The same pattern is duplicated for that list (fully implemented in the Retrofit lecture; declared here for completeness):

```kotlin
private val _address = mutableStateOf<List<GeocodingResult>>(emptyList())
val address: State<List<GeocodingResult>> = _address

// later: fun fetchAddress(latlng: String) { ... _address.value = result.results }
```

- Starts as an **empty list**, not `null` — an idiomatic difference from `_location`. An empty list cleanly maps to \"no address\" via `firstOrNull()` at the call site.
- `address: State<List<GeocodingResult>>` exposes it read-only.
- Exposing a `State<List<GeocodingResult>>` keeps Compose recomposition automatic when the network call returns.

---

## Why a ViewModel at all?

The map picker (`LocationSelectionScreen`) and the shopping list (`ShoppingListApp`) are **two different destinations** on the `NavHost`. Plain `remember` state would be destroyed when navigating away. A `ViewModel` scoped to the Activity (`viewModel()` inside `setContent` or `Navigation`) survives navigation and rotation, so the selected coordinate and resolved address are both available wherever needed:

```kotlin
// In Navigation — single instance for the whole graph
val viewModel: LocationViewModel = viewModel()
```

```text
GoogleMap.onMapClick
      │
      ▼
LocationSelectionScreen → onLocationSelected(LocationData)
      │
      ▼
Navigation → viewModel.fetchAddress(\"lat,lng\")
      │
      ▼
viewModel._address.value = result.results
      │
      ▼  recomposition
ShoppingListApp renders viewModel.address.value.firstOrNull()?.formatted_address
```

## Recap / cheat sheet

- **File:** `LocationViewModel.kt`.
- **Extends:** `ViewModel` (`androidx.lifecycle`).
- **Location state:** `private val _location = mutableStateOf<LocationData?>(null)` / `val location: State<LocationData?> = _location` / `fun updateLocation(LocationData)`.
- **Address state:** `private val _address = mutableStateOf<List<GeocodingResult>>(emptyList())` / `val address: State<List<GeocodingResult>> = _address`.
- **Imports:** `androidx.compose.runtime.State` and `mutableStateOf` (not lifecycle State).
- **Scoping:** `val viewModel: LocationViewModel = viewModel()` in `Navigation` so both destinations share the same instance.
- **Null vs empty:** `null` for no location, `emptyList()` for no address — enables `firstOrNull()?.formatted_address ?: \"No Address\"`.
