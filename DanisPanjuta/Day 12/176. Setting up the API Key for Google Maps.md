# Setting up the API Key for Google Maps

---

## Overview

Google charges for the traffic its APIs serve, so every map or geocoding call must be authenticated. The credential is an **API key** — a long opaque string tied to a Cloud project and a billing account. This lecture creates the project **The Shopper**, enables **Maps SDK for Android**, generates the key, protects it, and stores it in `AndroidManifest.xml`.

---

## Why an API key?

| Concept | Meaning |
| :--- | :--- |
| **API key** | A per-project token that Google uses to meter usage |
| **Quota** | The first **$200/month** of Maps traffic is free; beyond that the billing account is charged |
| **Cloud project** | The container that groups enabled APIs, credentials, and billing |
| **Budget alert** | Automatically created at the $200 threshold — an email when the free credit is reached |

Any code that renders a `GoogleMap` or calls `https://maps.googleapis.com/maps/api/geocode/json` must present a valid key or the request is rejected.

---

## Step 1 — open the documentation

Navigate to:

```
https://developers.google.com/maps/documentation/android-sdk/get-api-key
```

Click **Set up in Cloud Console**. If not signed into a Google account, the page prompts for login/registration.

---

## Step 2 — create a billing account (required)

Google Cloud requires a **billing account** with a credit card before an API key can be used.

- Open **Billing** in the Cloud Console sidebar.
- Create or attach a billing account to the project.
- The $200 free tier means testing and course work never incurs a charge unless a loop spams the API.

> If a credit card is unavailable, a family member's card can be used with permission. Without billing the Maps features cannot be enabled.

---

## Step 3 — create the project

1. In the Cloud Console header, click the project dropdown → **New Project**.
2. Name it **The Shopper** (the lecture uses this name; the ID becomes `the-shopper-403909` and cannot be changed later).
3. Leave **Organization** as *No organization* if none is configured.
4. Click **Create**. The dashboard shows Project ID, Project number, and zero API requests so far.

---

## Step 4 — enable Maps SDK for Android

1. Open the **navigation menu** (hamburger, top-left) → **APIs & Services** → **Enabled APIs & services**.
2. Click **+ Enable APIs and Services**.
3. Search for **`Maps SDK for Android`**. Two results may appear — pick the Android one.
4. Click **Enable**. The button changes to **Manage** once active.

> Only enable APIs that are actually used. An exposed unrestricted key with many enabled APIs is an easy target for **quota theft**.

---

## Step 5 — obtain the API key

After enabling, the console presents the key (or: **APIs & Services → Credentials → Show key**).

- Click the **copy** icon.
- Never paste the key in a public chat, forum, or repository. The lecture stresses *hide your API key*.

If the key is lost, it is **not gone**: **APIs & Services → Credentials → Keys** lists it again; click **Show key** to copy.

---

## Step 6 — store the key in the manifest

Open `app/src/main/AndroidManifest.xml`. Inside `<application>` add a `<meta-data>` entry:

```xml
<manifest xmlns:android=\"http://schemas.android.com/apk/res/android\">

    <application
        ... >

        <!-- Google Maps API key -->
        <meta-data
            android:name=\"com.google.android.geo.API_KEY\"
            android:value=\"YOUR_API_KEY_HERE\" />

        <activity ... />
    </application>
</manifest>
```

Critical details:

| Attribute | Required value |
| :--- | :--- |
| `android:name` | `com.google.android.geo.API_KEY` — case-sensitive, underscore, dots exactly as shown |
| `android:value` | The copied key string, no extra whitespace |

The name must be typed precisely; Android Studio does not validate it, so a typo silently results in a blank map.

---

## Step 7 — (preview) restrict the key

Directly after creation the key is **unrestricted** — any app or website that knows the string can burn quota.

The console offers four restriction types:

| Type | When to use |
| :--- | :--- |
| **None** (unrestricted) | Never for production |
| **Websites** | key only valid from specific referrers |
| **IP addresses** | key only valid from specific IPs |
| **Android apps** | key only valid from a specific **package name** + **SHA-1 certificate fingerprint** |

The lecture initially protects the key as **Android apps**, enters:

- **Package name:** the app's package, e.g. `com.example.myshoppinglistapp` (taken from `MainActivity` header or `build.gradle` `applicationId`)
- **SHA-1:** obtained inside Android Studio — **Gradle panel → Execute Gradle Task → `signingReport`** → copy the `SHA1` line (not `SHA-256`).

Once restricted, a stolen key cannot be reused without both the correct package and signing certificate.

> The Geocoding REST call tested in the next video fails while the Android restriction is active (the browser is not an Android app). That is expected and proves the restriction works. For the HTTP test the restriction is temporarily lifted to **None**, then restored.

---

## Recap / cheat sheet

- **Console:** `developers.google.com/maps/documentation/android-sdk/get-api-key` → **Set up in Cloud Console**.
- **Billing:** required before any key works; $200/month free, budget alert automatic.
- **Project:** create **The Shopper** → enable **Maps SDK for Android**.
- **Key:** **APIs & Services → Credentials → Show key** to retrieve at any time.
- **Manifest:** `<meta-data android:name=\"com.google.android.geo.API_KEY\" android:value=\"...\" />` inside `<application>`.
- **Restrict:** **Android apps** → package name + **SHA-1** from `signingReport`. Temporarily lift to test browser geocoding, then re-restrict.
- **Security:** hide the key, restrict it, and never enable APIs that are not used.
