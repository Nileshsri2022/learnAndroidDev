# Adding the permission request

---

## Overview

`LocationUtils` can check a permission, but the UI still needs the Compose launcher that **asks** for it and the **Address** button that triggers either an immediate location read (if already granted) or the system dialog (if not). This lecture copies the `rememberLauncherForActivityResult` pattern from Day 11 into `ShoppingListApp` and adds that button inside the `AlertDialog`.

---

## Step 1 — copy the permission launcher

Open **LocationApp (Day 11)** side-by-side and copy the entire launcher block.

Paste it inside `ShoppingListApp`, near the top — above the `LazyColumn` and the `AlertDialog`, alongside the existing `itemName` / `itemQuantity` states:

```kotlin
@Composable
fun ShoppingListApp(
    locationUtils: LocationUtils,
    viewModel: LocationViewModel,
    navController: NavController,
    context: Context,
    address: String
) {
    var sItems by remember { mutableStateOf(listOf<ShoppingItem>()) }
    var showDialog by remember { mutableStateOf(false) }
    var itemName by remember { mutableStateOf(\"\") }
    var itemQuantity by remember { mutableStateOf(\"\") }

    // — copied from Day 11 —
    val requestPermissionLauncher = rememberLauncherForActivityResult(
        contract = ActivityResultContracts.RequestMultiplePermissions(),
        onResult = { permissions ->
            if (permissions[Manifest.permission.ACCESS_COARSE_LOCATION] == true &&
                permissions[Manifest.permission.ACCESS_FINE_LOCATION] == true) {
                // permission granted — caller will navigate
                locationUtils.requestLocationUpdates(viewModel)
            } else {
                val rationaleRequired = ActivityCompat.shouldShowRequestPermissionRationale(
                    context as MainActivity, Manifest.permission.ACCESS_FINE_LOCATION
                ) || ActivityCompat.shouldShowRequestPermissionRationale(
                    context as MainActivity, Manifest.permission.ACCESS_COARSE_LOCATION
                )

                if (rationaleRequired) {
                    Toast.makeText(
                        context,
                        \"Location Permission is required for this feature to work\",
                        Toast.LENGTH_LONG
                    ).show()
                } else {
                    Toast.makeText(
                        context,
                        \"Location Permission is required. Please enable it in the Android Settings\",
                        Toast.LENGTH_LONG
                    ).show()
                }
            }
        }
    )

    // ... alert dialog and lazy column follow
}
```

| Piece | Role |
| :--- | :--- |
| `ActivityResultContracts.RequestMultiplePermissions()` | Returns `Map<String, Boolean>` of permission → granted |
| `onResult` | Checks both `COARSE` and `FINE` are `true` → calls `requestLocationUpdates`; otherwise shows rationale vs. settings `Toast` |
| `shouldShowRequestPermissionRationale` | `true` = first or soft denial (explain); `false` = permanent denial (point to Settings) |

Reuse note: nothing in this block is specific to maps — the same launcher handles any runtime permission.

## Step 2 — add the **Address** button inside the dialog

The `AlertDialog` already has two `OutlinedTextField`s (name, quantity) inside a `Column`. Insert a `Button` **below** those fields:

```kotlin
AlertDialog(
    onDismissRequest = { showDialog = false },
    title = { Text(\"Add Shopping Item\") },
    text = {
        Column {
            OutlinedTextField(
                value = itemName,
                onValueChange = { itemName = it },
                singleLine = true,
                modifier = Modifier.fillMaxWidth().padding(8.dp),
                label = { Text(\"Item Name\") }
            )
            OutlinedTextField(
                value = itemQuantity,
                onValueChange = { itemQuantity = it },
                singleLine = true,
                modifier = Modifier.fillMaxWidth().padding(8.dp),
                label = { Text(\"Quantity\") }
            )
            Button(
                onClick = {
                    if (locationUtils.hasLocationPermission(context)) {
                        locationUtils.requestLocationUpdates(viewModel)
                        navController.navigate(\"location_screen\") {
                            launchSingleTop = true
                        }
                    } else {
                        requestPermissionLauncher.launch(
                            arrayOf(
                                Manifest.permission.ACCESS_FINE_LOCATION,
                                Manifest.permission.ACCESS_COARSE_LOCATION
                            )
                        )
                    }
                }
            ) {
                Text(\"address\")
            }
        }
    },
    confirmButton = {
        Row(/* ... Add / Edit button ... */) { /* ... */ }
    },
    dismissButton = {
        Button(onClick = { showDialog = false }) { Text(\"Cancel\") }
    }
)
```

### Behaviour

```text
Tap \"address\"
      │
      ├── hasLocationPermission == true
      │         ├── requestLocationUpdates(viewModel) → ViewModel.location updated
      │         └── navController.navigate(\"location_screen\") { launchSingleTop = true }
      │                    → map picker opens, marker at current location
      │
      └── hasLocationPermission == false
                └── requestPermissionLauncher.launch(arrayOf(FINE, COARSE))
                          └── onResult above → if granted → requestLocationUpdates
```

| Property | Meaning |
| :--- | :--- |
| `launchSingleTop = true` | At most one copy of `location_screen` on the back stack — repeated taps do not stack duplicates |
| `arrayOf(FINE, COARSE)` | Requests both permissions in one prompt; the user sees a single dialog with the **Precise** toggle |

The button text is literally `\"address\"` (lowercase in the recording). Capitalization can be changed without functional effect.

## Recap / cheat sheet

- **Launcher:** copy `rememberLauncherForActivityResult(ActivityResultContracts.RequestMultiplePermissions(), onResult = { ... })` from Day 11.
- **Inside `onResult`:** `if (COARSE == true && FINE == true) requestLocationUpdates(viewModel)` else `shouldShowRequestPermissionRationale` → rationale vs. settings `Toast`.
- **Button:** inside `AlertDialog`'s `Column` (below the two `OutlinedTextField`s): `Button(onClick = { if (hasLocationPermission) { requestLocationUpdates; navigate(\"location_screen\") } else { launcher.launch(arrayOf(FINE, COARSE)) } }) { Text(\"address\") }`.
- **Navigation flag:** `launchSingleTop = true` prevents multiple map screens on the stack.
- **Location of code:** the launcher lives at the top of `ShoppingListApp`, not inside the `AlertDialog` lambda — it must survive recomposition of the dialog.
