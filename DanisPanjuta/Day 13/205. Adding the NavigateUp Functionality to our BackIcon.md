# Adding the NavigateUp Functionality to our BackIcon

---

## Overview

The `AppBarView`'s `onBackNavClicked` was hoisted but never implemented for the detail screen. This lecture makes the `ArrowBack` icon actually return to the list via `navController.navigateUp()`.

---

## The fix

Inside `AddEditDetailView`'s `Scaffold.topBar`:

```kotlin
AppBarView(
    title = if (id != 0L) "Update Wish" else "Add Wish",
    onBackNavClicked = { navController.navigateUp() }
)
```

`navigateUp()` = *attempt to navigate up in the navigation hierarchy* — equivalent to the user pressing the system Up button. It pops the `AddScreen` entry, revealing the underlying `HomeScreen`.

| Call | Behaviour |
| :--- | :--- |
| `navController.navigateUp()` | Pop current entry; if at start destination, does nothing |
| `navController.popBackStack()` | Unconditionally pop (alternative) |
| `navController.navigate(Screen.HomeScreen.route)` | Would push a *second* HomeScreen — wrong; would duplicate the back stack |

---

## Conditional visibility (revisited)

`HomeView` already hides the icon:

```kotlin
AppBarView(title = "Wishlist", showBackIcon = false) // no navigationIcon emitted
```

`AddEditDetailView` shows it:

```kotlin
AppBarView(title = "...", showBackIcon = true, onBackNavClicked = { navigateUp() })
```

Now both the system back and the bar's arrow return to the list, and tapping a `WishItem` → detail → back works end-to-end.

---

## Recap / cheat sheet

- **Detail topBar:** `onBackNavClicked = { navController.navigateUp() }`.
- **Don't** use `navigate(HomeScreen)` to go back — it pushes, not pops.
- **Icon visibility:** `HomeView` `false`, detail `true`.
