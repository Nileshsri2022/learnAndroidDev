# FloatingActionButton (FAB)

---

## Overview

The **FAB** is the circular `+` button that creates a new wish. It lives in the `Scaffold`'s `floatingActionButton` slot, not inside the `LazyColumn`, so it hovers above the list even while scrolling.

---

## The code

Inside `HomeView`, supply the FAB:

```kotlin
Scaffold(
    topBar = { AppBarView(title = "Wishlist", showBackIcon = false) },
    floatingActionButton = {
        FloatingActionButton(
            modifier = Modifier.padding(all = 20.dp),
            contentColor = Color.White,
            backgroundColor = Color.Black,
            onClick = {
                navController.navigate(Screen.AddScreen.route + "/0L")
            }
        ) {
            Icon(imageVector = Icons.Default.Add, contentDescription = null)
        }
    }
) { paddingValues ->
    LazyColumn(modifier = Modifier.padding(paddingValues)) { /* wishes */ }
}
```

| Property | Value | Role |
| :--- | :--- | :--- |
| `FloatingActionButton` | Material FAB | Elevated circular button, default 56.dp |
| `Icons.Default.Add` | `+` | Universal *create* affordance |
| `onClick` | `navigate(AddScreen/0L)` | `0L` = *no existing wish* → add mode; any other id → edit mode |
| `contentColor` | `Color.White` | Icon tint |
| `backgroundColor` | `Color.Black` | FAB fill |
| `Modifier.padding(20.dp)` | Outer margin | Keeps FAB off the screen edge |

> The lecture passes `"/0L"` as a string suffix; the navigation argument is later read as `navArgument("id") { type = NavType.LongType }`.

---

## Why `0L` means *add*?

`Wish` primary key is auto-generated starting at `1`. `0` can never be a real `id`, so it cleanly signals *create new* versus *edit existing* (`id > 0`).

---

## Recap / cheat sheet

- **Slot:** `Scaffold(floatingActionButton = { FloatingActionButton(...) { Icon(Add) } })`.
- **Nav:** `navController.navigate(Screen.AddScreen.route + "/0L")` → add mode.
- **Style:** `backgroundColor = Black`, `contentColor = White`, `padding(20.dp)`.
