# Welcome to Day 13

---

## Overview

Day 13 starts the **Wishlist app** — a real-world CRUD list where wishes survive app restarts. The day focuses on the **Scaffold** as the structural shell (top bar, content, floating action button) and sets up the project with Room + Navigation dependencies. The UI built today is in-memory only; persistence is added tomorrow with Room.

---

## Why Wishlist after Shopping List?

| Feature | Shopping List (Day 7/12) | Wishlist (Day 13/14) |
| :--- | :--- | :--- |
| Storage | In-memory `listOf<ShoppingItem>` — lost on kill | **Room** — survives reboot |
| Structure | `LazyColumn` with dialog | `Scaffold` + `TopAppBar` + `FloatingActionButton` + `LazyColumn` |
| Navigation | Dialog map picker | Two-screen navigation (`HomeView` ↔ `AddEditDetailView`) |

The Wishlist therefore teaches both **Scaffold** (required for any modern Material app) and **permanent storage**.

---

## What you will build today

1. **Scaffold** containing a `TopAppBar` (with conditional back icon) and a **FAB** that navigates to the add screen.
2. **Wish** data class + **WishItem** row composable.
3. **Dummy data** displayed in a `LazyColumn` to verify the list before any database exists.
4. **Navigation** graph (`HomeView`, `AddEditDetailView`) and `navigateUp()` for the back icon.
5. `WishViewModel` that holds the list and exposes `addWish` (wired to the UI but not yet persisted).

## Recap / cheat sheet

- **Scaffold** is the skeleton: `Scaffold(topBar, floatingActionButton, content = { padding -> ... })`.
- **Dummy data** proves the `LazyColumn` before any database.
- **Navigation** is hoisted: `HomeView` and `AddEditDetailView` receive `navController` + `viewModel`.
- **Back icon** visibility is state-driven — only on detail screen.
