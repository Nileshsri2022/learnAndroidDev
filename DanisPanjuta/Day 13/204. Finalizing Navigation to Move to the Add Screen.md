# Finalizing Navigation to Move to the Add Screen

---

## Overview

`HomeView`'s **FAB** and `WishItem` taps should navigate to `AddEditDetailView`, but at this point the graph only hosts `HomeView`. This lecture registers the second destination and wires the FAB's `onClick` to actually move.

---

## Step 1 — register AddScreen in NavHost

`Navigation.kt`:

```kotlin
NavHost(navController, startDestination = Screen.HomeScreen.route) {
    composable(Screen.HomeScreen.route) {
        HomeView(viewModel = viewModel, navController = navController)
    }
    composable(
        Screen.AddScreen.route + "/{id}",
        arguments = listOf(navArgument("id") { type = NavType.LongType; defaultValue = 0L })
    ) { entry ->
        val id = entry.arguments?.getLong("id") ?: 0L
        AddEditDetailView(id = id, viewModel = viewModel, navController = navController)
    }
}
```

---

## Step 2 — FAB navigates

`HomeView.kt`:

```kotlin
FloatingActionButton(
    onClick = { navController.navigate(Screen.AddScreen.route + "/0L") },
    backgroundColor = Color.Black,
    contentColor = Color.White
) { Icon(Icons.Default.Add, null) }
```

- `"/0L"` suffix passes the sentinel `id = 0L` → add mode.

Also pass `navController` + `viewModel` into `HomeView` from `Navigation` (default parameters `viewModel: WishViewModel = viewModel()` and `navController: NavHostController = rememberNavController()` make `MainActivity` hosting simply `Navigation()`).

## Recap / cheat sheet

- **Register:** `composable(AddScreen/{id}, navArgument("id", LongType, 0L))`.
- **FAB:** `navController.navigate(Screen.AddScreen.route + "/0L")` → add; item click uses `"/${wish.id}"` → edit.
- **HomeView signature:** `(viewModel, navController)` — supplied by `Navigation`.
