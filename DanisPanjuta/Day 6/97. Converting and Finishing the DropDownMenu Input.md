# `convertUnits()` — Finishing the Input Dropdown

---

## Overview

This lecture adds the **logic** of the Unit Converter: a function that turns the typed number into a result.

Then every **input** dropdown item:

1. Closes the menu
2. Stores the chosen unit
3. Stores that unit’s conversion factor
4. Calls `convertUnits()`

The output dropdown is left for the next video.

---

## 1. Functions inside a composable

`convertUnits()` is declared **inside** `UnitConverter()`. That is allowed in Kotlin.

Why put it there?

* It can read `inputValue`, `conversionFactor`, and write `outputValue` without passing them as parameters
* It lives next to the state it uses

You would not always nest functions in other languages. In Compose it is common for small helpers that only exist for one screen.

```kotlin
@Composable
fun UnitConverter() {
    var inputValue by remember { mutableStateOf("") }
    var outputValue by remember { mutableStateOf("") }
    // ... other state ...

    fun convertUnits() {
        // uses inputValue / conversionFactor / outputValue from the outer scope
    }

    Column { /* UI */ }
}
```

Place it **under the state declarations** so those variables already exist.

## 2. Parse the text field safely — `toDoubleOrNull()` and Elvis

The text field holds a **String**. Math needs a **Double**.

```kotlin
val inputValueDouble = inputValue.toDoubleOrNull() ?: 0.0
```

| Piece | Meaning |
| :--- | :--- |
| `toDoubleOrNull()` | Parse the string as a double, or return `null` if it is not a number (`""`, `"qwer"`, `"12."` depending on locale, etc.) |
| `?:` | **Elvis operator** — a tiny if/else |
| `0.0` | Fallback when the parse failed |

Elvis in plain English:

> If the left side is not null, use it. If it *is* null, use the right side.

Without this, `"abc".toDouble()` would **crash**. With it, garbage input becomes `0.0` and the app keeps running.

## 3. The first conversion formula

At this stage there is only **one** conversion factor (input → meters). The first version is:

```kotlin
fun convertUnits() {
    val inputValueDouble = inputValue.toDoubleOrNull() ?: 0.0
    val result =
        (inputValueDouble * conversionFactor.value * 100.0).roundToInt() / 100.0
    outputValue = result.toString()
}
```

Step by step:

1. `inputValueDouble * conversionFactor.value` — convert the typed number **into meters**
2. `* 100.0` — shift two decimal places
3. `.roundToInt()` — round to a whole number (`kotlin.math.roundToInt` — Android Studio will add the import)
4. `/ 100.0` — shift back, so you keep **two decimal places** instead of a long ugly double
5. `.toString()` — `outputValue` is a `String` (it is shown in `Text(...)`)

### `.value` again

`conversionFactor` was created with `= remember { mutableStateOf(1.00) }`, **not** `by`.

That means it is a **chest** (`MutableState<Double>`). The coins are inside `.value`.

```kotlin
conversionFactor.value   // the Double
```

If you had used `by`, you would write `conversionFactor` directly.

## 4. Wire every input `DropdownMenuItem`

Pattern for each item:

```kotlin
iExpanded = false
inputUnit = "<Unit name>"
conversionFactor.value = <factor to meters>
convertUnits()
```

| Item | `inputUnit` | Factor (to meters) |
| :--- | :--- | :--- |
| Centimeters | `"Centimeters"` | `0.01` |
| Meters | `"Meters"` | `1.00`  (base unit) |
| Feet | `"Feet"` | `0.3048` |
| Millimeters | `"Millimeters"` | `0.001` |

```kotlin
DropdownMenu(
    expanded = iExpanded,
    onDismissRequest = { iExpanded = false }
) {
    DropdownMenuItem(
        text = { Text("Centimeters") },
        onClick = {
            iExpanded = false
            inputUnit = "Centimeters"
            conversionFactor.value = 0.01
            convertUnits()
        }
    )
    DropdownMenuItem(
        text = { Text("Meters") },
        onClick = {
            iExpanded = false
            inputUnit = "Meters"
            conversionFactor.value = 1.00
            convertUnits()
        }
    )
    DropdownMenuItem(
        text = { Text("Feet") },
        onClick = {
            iExpanded = false
            inputUnit = "Feet"
            conversionFactor.value = 0.3048
            convertUnits()
        }
    )
    DropdownMenuItem(
        text = { Text("Millimeters") },
        onClick = {
            iExpanded = false
            inputUnit = "Millimeters"
            conversionFactor.value = 0.001
            convertUnits()
        }
    )
}
```

Copy-paste is fine here, but **change the unit name and the factor** on every item. Forgetting that is the bug that shows up in the next lecture.

## 5. Why meters are the “middle ground”

Every unit is stored as “how many meters is 1 of this unit?”

```
input amount  ×  (meters per input unit)  =  amount in meters
```

Later, dividing by the **output** factor turns meters into the destination unit. That second factor does not exist yet — next lecture.

## Summary

* Nested `fun convertUnits()` holds the math
* `toDoubleOrNull() ?: 0.0` stops crashes on bad input (Elvis operator)
* Round via `* 100 → roundToInt() → / 100` for two decimal places
* `MutableState` without `by` needs `.value`
* Every input item: close menu, set unit, set factor, convert
