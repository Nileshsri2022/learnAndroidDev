### Overview: What was accomplished?
In this lesson, the instructor applied **State Management** (`remember` + `mutableStateOf`) to a practical **Unit Converter App**. 

Specifically, they:
1. Identified and declared all the **State variables** needed for the application.
2. Connected the first state variable (`inputValue`) to an **`OutlinedTextField`** to make it interactive.
3. Added a **`label`** to the text field.
4. Fixed a common UI bug where open dropdown menus were blocking user interactions.

---

### 1. The State Variables Defined

To make a Unit Converter work, the app needs to remember multiple pieces of dynamic data:

| Variable | Type | Default Value | Purpose |
| :--- | :--- | :--- | :--- |
| `inputValue` | `String` | `""` | Stores what the user types in the text box. |
| `outputValue` | `String` | `""` | Stores the calculated result. |
| `inputUnit` | `String` | `"Centimeters"` | The unit being converted *from*. |
| `outputUnit` | `String` | `"Meters"` | The unit being converted *to*. |
| `iExpanded` | `Boolean` | `false` | Controls whether the **input** dropdown menu is open or closed. |
| `oExpanded` | `Boolean` | `false` | Controls whether the **output** dropdown menu is open or closed. |
| `conversionFactor`| `Double` | `1.0` (or `0.01`) | The mathematical multiplier used for conversion. |

### 2. Declaring States with `by` and `var`

When using the `by` keyword for property delegation:
* You **must use `var`** (not `val`) if you want to modify the variable directly later (e.g., `inputValue = it`).
* You need specific imports to enable property delegation:
  ```kotlin
  import androidx.compose.runtime.remember
  import androidx.compose.runtime.mutableStateOf
  import androidx.compose.runtime.getValue
  import androidx.compose.runtime.setValue
  ```

#### State Declarations in Code:
```kotlin
var inputValue by remember { mutableStateOf("") }
var outputValue by remember { mutableStateOf("") }
var inputUnit by remember { mutableStateOf("Centimeters") }
var outputUnit by remember { mutableStateOf("Meters") }
var iExpanded by remember { mutableStateOf(false) }
var oExpanded by remember { mutableStateOf(false) }
val conversionFactor = remember { mutableStateOf(1.00) } 
// Note: In the video, the instructor used '=' for conversionFactor, but 'by' can be used as well.
```

### 3. Making `OutlinedTextField` Interactive

In Jetpack Compose, text fields follow a **unidirectional data flow** pattern (also called a controlled component):
1. **`value`**: Defines what text is currently displayed inside the field.
2. **`onValueChange`**: A callback that triggers every time the user types, deletes, or pastes text. It provides the updated string as an implicit parameter named `it`.
3. **`label`**: An optional parameter that takes a composable lambda (e.g., `Text("...")`) to display floating placeholder text.

```kotlin
OutlinedTextField(
    value = inputValue,
    onValueChange = {
        // 'it' represents the new text entered by the user
        inputValue = it
    },
    label = { 
        Text("Enter Value") 
    }
)
```

### 4. The UI Blocking Bug & Solution

#### The Problem:
When the app ran, clicking on the `OutlinedTextField` did nothing because the screen was completely unresponsive.

#### The Cause:
Both `DropdownMenu` components had their `expanded` property hardcoded to `true`:
```kotlin
DropdownMenu(expanded = true, onDismissRequest = { /* ... */ })
```
When a dropdown is expanded, Jetpack Compose creates a full-screen invisible layer to detect clicks outside the menu (to dismiss it). Having both dropdowns open simultaneously trapped all touch events and blocked the text field.

#### The Fix:
Set the dropdowns' `expanded` parameter to `false` (or bind them to `iExpanded` / `oExpanded`):
```kotlin
DropdownMenu(expanded = false, onDismissRequest = { /* ... */ })
```
