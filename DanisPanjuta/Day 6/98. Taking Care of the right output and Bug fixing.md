# Output Dropdown, Live Conversion, and Bug Fixing

---

## Overview

This is the lecture where the Unit Converter **starts working**.

You will:

1. Default both units to **Meters**
2. Add a second factor: `oConversionFactor` (output)
3. Update the formula so input **and** output units are used
4. Copy the dropdown-item pattern onto the **output** menu
5. Show the selected unit on each button (not the word `"Select"`)
6. Recalculate whenever the user types
7. Hunt down a copy-paste bug that made every result wrong

---

## 1. Defaults and a second conversion factor

Both sides should start as meters, with factor `1.00`:

```kotlin
var inputUnit by remember { mutableStateOf("Meters") }
var outputUnit by remember { mutableStateOf("Meters") }

val conversionFactor = remember { mutableStateOf(1.00) }      // input → meters
val oConversionFactor = remember { mutableStateOf(1.00) }     // output → meters
```

You need **two** factors because the left unit and the right unit are independent. One multiplier cannot describe “feet → millimeters”.

---

## 2. The real formula (through meters)

```
typed value  ×  inputFactor  ÷  outputFactor  =  result
```

Example: `10` meters → millimeters

* input factor = `1.00` (already meters)
* output factor = `0.001` (1 mm = 0.001 m)
* `10 * 1.00 / 0.001 = 10000`

```kotlin
fun convertUnits() {
    val inputValueDouble = inputValue.toDoubleOrNull() ?: 0.0
    val result =
        (inputValueDouble * conversionFactor.value * 100.0 / oConversionFactor.value)
            .roundToInt() / 100.0
    outputValue = result.toString()
}
```

Same two-decimal rounding as before; the new piece is `/ oConversionFactor.value`.

---

## 3. Output dropdown items

Same four actions as the input side, but:

* `oExpanded` (not `iExpanded`)
* `outputUnit` (not `inputUnit`)
* `oConversionFactor.value` (not `conversionFactor.value`)

| Item | `outputUnit` | `oConversionFactor` |
| :--- | :--- | :--- |
| Centimeters | `"Centimeters"` | `0.01` |
| Meters | `"Meters"` | `1.00` |
| Feet | `"Feet"` | `0.3048` |
| Millimeters | `"Millimeters"` | `0.001` |

```kotlin
DropdownMenuItem(
    text = { Text("Centimeters") },
    onClick = {
        oExpanded = false
        outputUnit = "Centimeters"
        oConversionFactor.value = 0.01
        convertUnits()
    }
)
```

Repeat for Meters / Feet / Millimeters.

---

## 4. Show the chosen unit on the button

Hardcoded `"Select"` is useless once a unit is chosen. Bind the button text to state:

```kotlin
Button(onClick = { iExpanded = true }) {
    Text(inputUnit)   // was Text("Select")
    Icon(Icons.Default.ArrowDropDown, contentDescription = "Arrow Down")
}

Button(onClick = { oExpanded = true }) {
    Text(outputUnit)
    Icon(Icons.Default.ArrowDropDown, contentDescription = "Arrow Down")
}
```

After a click, recomposition puts `"Feet"` (or whatever) on the button automatically.

---

## 5. Convert while typing

Call `convertUnits()` inside `onValueChange` so the result updates on every keystroke — not only when a dropdown changes:

```kotlin
OutlinedTextField(
    value = inputValue,
    onValueChange = {
        inputValue = it
        convertUnits()
    },
    label = { Text("Enter Value") }
)
```

Type `1` → `10` → `100` and the result line should follow.

## 6. The copy-paste bug

Symptoms in the video:

* `100` meters → feet showed `30.48` (that is feet → meters, inverted)
* Changing the **output** unit often did nothing useful

Cause: the output items still wrote to **`conversionFactor`** (the input one) because the block was copied from the input menu.

```kotlin
// WRONG — this updates the left-hand factor
conversionFactor.value = 0.01

// RIGHT — output items must update the right-hand factor
oConversionFactor.value = 0.01
```

After fixing every output item, checks that should pass:

| Input | Output | Expected |
| :--- | :--- | :--- |
| `10` Meters | Meters | `10` |
| `10` Meters | Feet | ~`32.81` |
| `10` Meters | Millimeters | `10000` |
| `10` Meters | Centimeters | `1000` |
| `10` Centimeters | Millimeters | `100` |

Debugging lesson from the lecture: sometimes you stare at the formula, but the bug is **which variable you assigned**. Copy-paste across two similar menus is a classic way to do that.

---

## 7. What “working” looks like

After this lecture, **any** of these should refresh the result:

* Typing in the text field
* Changing the input unit
* Changing the output unit

That is state doing its job: three different events, one function, one result `Text`.

---

## Summary

* Two factors: `conversionFactor` (in) and `oConversionFactor` (out)
* Formula: `(input × inFactor / outFactor)` rounded to 2 decimals
* Output menu mirrors the input menu — different variables
* Button labels = `inputUnit` / `outputUnit`
* `convertUnits()` also runs in `onValueChange`
* Watch copy-paste: output clicks must set **`oConversionFactor`**
