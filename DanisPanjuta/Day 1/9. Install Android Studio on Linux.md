This item has **no spoken transcript** in the course material — it is a supplementary
walkthrough for Linux users rather than part of the main recorded flow. The notes below
cover what the Linux installation involves, so the day reads continuously whether you are
on Windows, macOS or Linux.

---

### **1. How the Linux Install Differs**

The Windows and macOS downloads are **installers**. The Linux download is a
**compressed archive** (`.tar.gz`) that you unpack and run yourself — there is no setup
wizard.

---

### **2. Typical Steps**

1. **Download** the Linux build from the
   [release archive](https://developer.android.com/studio/archive) — pick the same
   version as the course (**Hedgehog 2023.1.1 RC1**).
2. **Extract** the archive, e.g.:
   ```bash
   tar -xzf android-studio-2023.1.1.23-linux.tar.gz
   ```
3. **Move** the extracted `android-studio/` folder somewhere permanent:
   ```bash
   sudo mv android-studio /opt/
   ```
4. **Run** the launcher script:
   ```bash
   /opt/android-studio/bin/studio.sh
   ```
5. From inside Android Studio, use **Tools → Create Desktop Entry** to add a launcher to
   your application menu, so you don't have to run the script by hand each time.

---

### **3. Things That Bite Linux Users**

| Problem | Cause / Fix |
| :--- | :--- |
| The emulator won't start | Hardware acceleration (KVM) isn't enabled or your user isn't in the `kvm` group |
| `studio.sh` isn't executable | Run `chmod +x android-studio/bin/studio.sh` |
| Emulator is extremely slow | Enable **KVM** in BIOS and install `qemu-kvm` |
| No desktop icon | Use **Tools → Create Desktop Entry** after first launch |

---

### **Key Takeaways**

1. On Linux you **extract and run a script** — there is no installer wizard.
2. Put the folder somewhere stable (`/opt/`) before first launch, or the desktop entry
   will point at a path you later delete.
3. **KVM hardware acceleration** is the difference between a usable emulator and an
   unusable one.
4. Everything **after** installation — the welcome screen, project setup, emulator — is
   identical to the Windows lectures in this day.
