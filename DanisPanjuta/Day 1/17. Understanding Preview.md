Here is a clear, structured breakdown of the lecture on Android Studio's **Preview pane** —
and why the word `Android` appeared in two different places in `MainActivity.kt`.

---

### **1. What the Preview Is**

The **Split / Design** button at the top-right of the editor opens a pane that **renders
your UI inside Android Studio**, without installing or running anything.

Change the text → the preview updates **instantly**.

---

### **2. Why It Exists**

Running the app on an emulator is a multi-step pipeline:

```
edit code → Gradle builds → app installs → emulator launches the app → you see the result
```

That takes **seconds to minutes** depending on your hardware, every single time. For a
complex app it can take many minutes.

The preview **skips the whole pipeline**. You get immediate visual feedback while iterating
on layout and styling — which is exactly when you make the most changes.

---

### **3. The Mystery Solved: Two `Android`s**

This lecture answers the confusion left by the previous one. `MainActivity.kt` contains:

```kotlin
// 1. What the RUNNING APP shows
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    setContent {
        MyFirstAppTheme {
            Surface(...) {
                Greeting("Dennis")     // ← appears on the emulator
            }
        }
    }
}

// 2. What the PREVIEW shows
@Preview(showBackground = true)
@Composable
fun GreetingPreview() {
    MyFirstAppTheme {
        Greeting("Android")            // ← appears only in the preview pane
    }
}
```

They are **two independent call sites** of the same function. Changing one does not change
the other — which is why the app said *Welcome Dennis* while the preview still said
*Welcome Android*.

---

### **4. The Underlying Idea: Functions Let You Write Once, Reuse Twice**

The instructor uses this to introduce the concept of a **function**:

> A function clusters code so you write it **once** and reuse it **anywhere** by name.

Calling `Greeting("Dennis")` is equivalent to pasting the entire body of `Greeting` at that
spot. Because it is a function, the same UI can appear:

* inside `onCreate` → on the **real app**
* inside `GreetingPreview` → in the **preview**

…without duplicating a single line. This is the foundation of Jetpack Compose, where an
entire screen is built by composing small reusable functions.

---

### **5. When to Use Which**

| Situation | Use |
| :--- | :--- |
| Tweaking layout, colours, spacing, text | **Preview** — instant |
| Testing behaviour: clicks, navigation, network, permissions | **Run** on the emulator — the preview doesn't execute logic |

---

### **Key Takeaways**

1. **Preview** renders your UI inside the editor with **no build and no emulator**.
2. It exists to avoid the **slow rebuild-install-launch cycle** during visual iteration.
3. `MainActivity.kt` has **two separate `Greeting(...)` calls** — one drives the app, one
   drives the preview. Update both when you want them to match.
4. **Functions = write once, reuse everywhere.** Calling `Greeting("Dennis")` is the same
   as inlining its whole body.
5. The preview shows **appearance only** — behaviour still needs a real run.
