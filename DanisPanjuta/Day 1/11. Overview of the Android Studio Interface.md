Here is a clear, structured breakdown of the lecture touring the **Android Studio user
interface** — the lecture the previous note (*Setting up our First Project*) points forward
to.

---

### **1. Overview**

The goal is **orientation, not memorisation**. The instructor is explicit that you should not
try to remember every panel — familiarity comes from using the tool over a week or two.

---

### **2. The Right-Hand Sidebar**

| Icon | What it does |
| :--- | :--- |
| **Assistant** | "What's new in Hedgehog" — only useful if you used an older Android Studio. Close it. |
| **Running Devices** | Shows the emulator/phone currently attached, so you can see the app while coding |
| **Device Manager** | Create and manage **Android Virtual Devices** (emulators). Empty on a fresh install. |
| **Gradle** | Status of the build system |
| **Notifications** | Reports things like how long the Gradle sync took |

---

### **3. The Project Panel (Left) — What Was Generated For You**

Choosing the **Empty Activity** template created ~43 lines of code you never typed:

```
app/
├── manifests/
│   └── AndroidManifest.xml      ← app metadata: target version, permissions
├── kotlin+java/
│   ├── MainActivity.kt          ← your main screen
│   └── ui/theme/                ← colours, typography, shapes
├── androidTest/                 ← instrumented tests (run on a device)
├── test/                        ← unit tests (run on the JVM)
├── res/                         ← resources: drawables, values, strings
└── Gradle Scripts/              ← build configuration
```

* **`AndroidManifest.xml`** — declares which Android version the app targets and which
  **permissions** it needs (internet, file system, location…). Android gates these.
* **`ui/theme/`** — default colours and fonts for buttons, text, etc.
* **`res/`** — everything visual or textual that isn't code.
* **Gradle Scripts** — the instructor explicitly says **don't try to understand these yet**;
  they aren't needed until around Day 20.

---

### **4. The Bottom Toolbar**

| Panel | Purpose |
| :--- | :--- |
| **Resource Manager** | Manages images, icons, colours, layouts. Ships with `ic_launcher_background` + `ic_launcher_foreground`, which combine into your app icon. |
| **Logcat** | Runtime logs — see crashes and anything you print yourself |
| **App Quality Insights** | Crash reporting; needs connecting to a service |
| **Terminal** | A shell inside the IDE — used from Day 2 onward |
| **Version Control** | Connect the project to **Git** so it lives in the cloud and can be shared |

---

### **5. The Centre: Where You Actually Work**

The **code editor** is where ~90% of your time goes. Two practical notes:

* The font is small by default — fixed in the *Changing the Scaling* lecture.
* The **Resource Manager** and **Assistant** panels can be toggled off to reclaim
  horizontal space for code.

At the top sits the **Run ▶ button**, greyed out until a device or emulator is attached.

The status bar at the bottom shows the full path to the open file — right-click it and use
**Show in Explorer** to jump to it on disk.

---

### **Key Takeaways**

1. **Close the Assistant** and collapse side panels — the code area is what matters.
2. The template already wrote `MainActivity.kt`, a manifest, theme files and test folders
   for you.
3. **`AndroidManifest.xml`** = version + permissions. **`res/`** = resources.
   **Gradle Scripts** = build config (ignore until ~Day 20).
4. **Device Manager** (right sidebar) is how you create an emulator; **Logcat** is how you
   see why something broke.
5. You do **not** need to memorise this layout — it becomes second nature with use.
