Here is a clear, structured breakdown of the lecture on **setting up the Android Virtual
Device (AVD)** — the emulator used for the entire course.

---

### **1. Why Use an Emulator?**

An **AVD** is an Android phone simulated on your PC. Compared with plugging in a physical
phone it is:

* **Faster to iterate** — no cable, no manual install each time
* **Reproducible** — the same screen size and Android version every run
* **Able to simulate hardware you don't own** — e.g. a foldable or a tablet

Some things do render slightly differently on real hardware, which the course covers later
when setting up a physical device.

---

### **2. Opening the Device Manager**

Two ways:

* The **Device Manager** icon in the right-hand sidebar, or
* **Hamburger menu (☰) → Tools → Device Manager**

On a fresh install the list is **empty**.

---

### **3. Choosing the Hardware**

| Category | Options | Course choice |
| :--- | :--- | :--- |
| **Phone** | Small Phone, **Medium Phone**, Pixel 6/7/7 Pro, Pixel 8… | **Pixel 7** — big enough, current enough |
| **Other form factors** | Tablet, Wear OS, Desktop, TV, Automotive, Legacy | Not used |

The Pixel 7 is the **Medium Phone** preset. A **6.31" screen, 1080 × 2400 px, 420 dpi**.

---

### **4. Choosing the System Image**

* Select **Upside Down Cake = API level 34 = Android 14** — the same version the course
  targets.
* If it is not downloaded yet, Android Studio offers to **download the image** first.
* This image **supports Google Play**, so you can sign in and install real apps on the
  emulator — handy if you have no Android phone at all.
* Other images exist for testing against **older Android versions**; you can create extra
  AVDs for that later.

---

### **5. AVD Configuration Screen**

| Setting | Choice | Why |
| :--- | :--- | :--- |
| **AVD name** | `Pixel 7 API 34 emulator` | Just a label |
| **Startup orientation** | **Portrait** | Matches a normal phone |
| **Emulated performance** | **Automatic** | Lets Android Studio pick based on your hardware |
| **Show device frame** | ✅ **On** | Draws the phone bezel, giving more controls around the screen |
| **Camera** (Advanced) | **Virtual Scene** | Fine for now; webcam testing is covered when building camera apps |
| **Boot option** (Advanced) | **Quick Boot** | Restores a snapshot so the emulator starts fast instead of cold-booting |

Click **Finish**. The device now appears in Device Manager with type **virtual**.

---

### **6. Running the App For the First Time**

1. The new AVD appears in the **device dropdown** at the top.
2. Press **Run ▶** (or **Shift + F10**).
3. Watch the bottom bar: **Gradle build runs → app installs → emulator boots**.
4. Accept the Windows security prompt if one appears.
5. The emulator opens and the app launches automatically.

> 💡 The **play button next to the device name** starts the emulator *without* running the
> app. Pressing **Run** does both.

You can also drag the emulator out of the **Running Devices** panel into its **own window**
for more room, and use the **+** button to zoom into it.

The first app shows **"Hello Android"** — that string comes from the `Greeting("Android")`
call in `MainActivity.kt`.

---

### **Key Takeaways**

1. **Device Manager** (right sidebar, or Tools menu) is where AVDs are created.
2. Course setup: **Pixel 7** + **API 34 / Android 14 (Upside Down Cake)**.
3. **Quick Boot** and **Automatic performance** make the emulator start fast.
4. **Run (Shift + F10)** builds via Gradle, installs, boots the emulator and launches the
   app in one action.
5. A Google Play–enabled image means the emulator doubles as a **spare Android device** if
   you don't own one.
