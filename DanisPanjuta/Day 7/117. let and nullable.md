# `let` and Nullable Types

---

## Overview

`find` on a list returns `ShoppingItem?` — maybe the item, maybe `null`. `let` runs a block only when the value is non-null. Third of the three tools (`map`, `copy`, `let`) used when saving an edit.

---

## Story (Sefton)

Ella’s glimmering orb wraps a secret in a bubble so she can work on it without touching the outside world. `let` is a **small scope** around a value.

---

## Nullable types

```kotlin
val name: String? = "Ella"
```

`String?` = `String` **or** `null`. A plain `String` cannot be null.

---

## Safe transform with `?.let`

```kotlin
name?.let {
    println(it.uppercase())  // ELLA
}
```

| Piece | Meaning |
| :--- | :--- |
| `?.` | If `name` is null, **stop**. Do not call `let` |
| `let { }` | If it was not null, run this block |
| `it` | The non-null value inside the block |

If `name = null`, nothing prints — no crash.

(The video uses deprecated `toUpperCase()`; `uppercase()` is the current API.)

---

## Why the shopping list needs it

```kotlin
val editedItem = sItems.find { it.id == item.id }  // ShoppingItem?
editedItem?.let {
    it.name = editedName
    it.quantity = editedQuantity
}
```

`find` might miss (deleted row, bad id). `?.let` only writes name/qty when something was found.
