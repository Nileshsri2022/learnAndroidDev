# Lambda Expressions — Short Functions You Can Pass Around

---

## Overview

Last lecture rushed `() -> Unit`. This one slows down: a story, then a tiny example on the Add Item button, then how that maps to `onEditClick`.

---

## Story (Cordelia)

Laura sells “magic scrolls”: compact spells. Whisper `5`, get `10`. No long spell book — just “take a number, double it.”

That scroll is a **lambda**: a small function without a full `fun name(...) { }` declaration.

---

## Syntax

```kotlin
val doubleNumber: (Int) -> Int = { it * 2 }
```

| Piece | Meaning |
| :--- | :--- |
| `doubleNumber` | Variable that **holds a function** |
| `(Int)` | Input type |
| `-> Int` | Return type |
| `{ it * 2 }` | Body. `it` = the single argument |

Call it like a function:

```kotlin
Text(doubleNumber(5).toString())  // "10"
```

The instructor temporarily put that on the **Add Item** button to prove it, then **reverted** to `Text("Add Item")`.

---

## Do not put heavy work in UI

The doubling demo is only for teaching. Complex math inside `Text(...)` runs on the **UI thread** and can freeze the app. Keep composables about *displaying*; keep heavy logic out.

---

## Back to `onEditClick`

```kotlin
onEditClick: () -> Unit
```

Same idea, emptier:

| | `doubleNumber` | `onEditClick` |
| :--- | :--- | :--- |
| Input | `Int` | none `()` |
| Output | `Int` | `Unit` (nothing) |
| Body | `{ it * 2 }` | whatever the **caller** writes: `{ sItems = ... }` |

So `ShoppingListItem` does not know *how* to edit. It only calls `onEditClick()` when the icon is pressed. The parent supplies the body.

You already wrote this every time you did:

```kotlin
Button(onClick = { showDialog = true }) { ... }
```

`onClick` is `( ) -> Unit` too.

---

## Summary

* Lambda = function value: `(In) -> Out = { body }`
* One parameter can be called `it`
* `() -> Unit` = “run some code, no args, no return”
