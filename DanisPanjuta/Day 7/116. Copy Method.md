# The `copy` Method — Duplicate a Data Class

---

## Overview

Data classes get `.copy(...)` for free. Change a few properties; keep the rest. You need this because you should not secretly mutate a list item and hope Compose notices — you replace the item with a slightly different copy.

---

## Story (Colonia)

Cleo’s Mirror of Duplication: put a blue-rose vase in front of it, paint the **duplicate** red. Original stays blue.

---

## Code

```kotlin
data class Vase(val color: String, val design: String)

val blueRoseVase = Vase(color = "Blue", design = "Rose")
val redRoseVase = blueRoseVase.copy(color = "Red")

println(blueRoseVase)  // Vase(color=Blue, design=Rose)
println(redRoseVase)   // Vase(color=Red, design=Rose)
```

`copy(color = "Red")` keeps `design = "Rose"`.

Named arguments: only list what **changes**.

---

## Why not always construct a new `Vase(...)`?

In this toy example you could. In the app you get objects from a list (later: a database). You may not want to retype every field. `copy` is “same object, these overrides.”

---

## With `map` (preview)

```kotlin
sItems = sItems.map { it.copy(isEditing = it.id == item.id) }
```

For each shopping item, make a copy. `isEditing` is `true` only when ids match. Other fields (`name`, `quantity`, `id`) stay.

Compose sees a **new list of new objects** → recomposition.
