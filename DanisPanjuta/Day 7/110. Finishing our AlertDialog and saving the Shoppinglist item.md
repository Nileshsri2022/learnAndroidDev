# Add / Cancel Buttons and Saving a `ShoppingItem`

---

## Overview

`confirmButton` is supposed to be **one** button. You put a **`Row` of two buttons** in that slot instead — another “misuse” that Compose allows because the slot is a composable.

**Cancel** only closes. **Add** builds a `ShoppingItem` and appends it to `sItems`. The list still does not *draw* rows — that is the next UI lecture. After Add, the item is in memory.

---

## 1. Two buttons with `SpaceBetween`

```kotlin
confirmButton = {
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .padding(8.dp),
        horizontalArrangement = Arrangement.SpaceBetween
    ) {
        Button(onClick = { /* Add — below */ }) {
            Text("Add")
        }
        Button(onClick = { showDialog = false }) {
            Text("Cancel")
        }
    }
}
```

`Arrangement.SpaceBetween` pins Add to the **left** edge and Cancel to the **right**, maximum gap in the middle — matches the demo.

---

## 2. Add: only if the name is not blank

```kotlin
Button(onClick = {
    if (itemName.isNotBlank()) {
        val newItem = ShoppingItem(
            id = sItems.size + 1,
            name = itemName,
            quantity = itemQuantity.toInt()
        )
        sItems = sItems + newItem
        showDialog = false
        itemName = ""
    }
}) {
    Text("Add")
}
```

| Step | Why |
| :--- | :--- |
| `itemName.isNotBlank()` | Ignore empty / whitespace names |
| `id = sItems.size + 1` | First item id `1`, second `2`, … |
| `name = itemName` | Whatever was typed |
| `quantity = itemQuantity.toInt()` | String → Int. **Can crash** on `"abc"` — the course skips `try/catch` / `toIntOrNull` for now |
| `isEditing` | Omitted; default is `false` |
| `sItems = sItems + newItem` | New list → Compose notices. Do **not** mutate a `listOf` in place |
| `showDialog = false` | Close popup |
| `itemName = ""` | Clear the name so the next open is empty |

The instructor does **not** reset `itemQuantity` in the video; you can (`itemQuantity = ""`) if you want both fields empty next time.

---

## 3. IDs and a limitation

`size + 1` is simple and fine while you only **add**. If you **delete** item `2` of three, size becomes 2, and the next add also gets id `2` — a duplicate. Fine for this lesson; a running counter would be safer later.

## Summary

* `confirmButton` holds a `Row` + `SpaceBetween` + Add + Cancel
* Cancel → `showDialog = false`
* Add → `ShoppingItem(...)` then `sItems = sItems + newItem`
* Replace the list (`+`), don’t try to `add()` on an immutable `List`
* Next: design one row (name, later quantity and icon buttons)
