# `LazyColumn` and the `ShoppingItem` Data Class

---

## Overview

Two pieces:

1. A **data class** — the shape of one grocery row
2. A **state list** of those objects, fed into `LazyColumn`

Nothing visible in the list yet. You *will* see the **Add Item** button jump to the top, because the lazy list takes the leftover space.

---

## 1. `data class ShoppingItem`

```kotlin
data class ShoppingItem(
    val id: Int,
    var name: String,
    var quantity: Int,
    var isEditing: Boolean = false
)
```

| Property | Type | Role |
| :--- | :--- | :--- |
| `id` | `Int` | Which row this is (later: find / edit / delete) |
| `name` | `String` | e.g. `"Apple"` |
| `quantity` | `Int` | How many |
| `isEditing` | `Boolean` | `true` → show the editor row instead of the normal row. Default `false` so new items are not in edit mode |

`isEditing` is how one row switches UI without a second list.

---

## 2. State is now a **list**

Until now, state was `String` / `Boolean` / `Double`. Here the whole shopping list is one state value:

```kotlin
var sItems by remember { mutableStateOf(listOf<ShoppingItem>()) }
```

Read it as:

* `sItems` — “shopping items”
* `remember { mutableStateOf(...) }` — survive recomposition, notify Compose on change
* `listOf<ShoppingItem>()` — empty list, **typed** as `ShoppingItem` (not `String`)
* `by` — need `getValue` / `setValue` imports (Alt+Enter)

When you later write `sItems = sItems + newItem`, Compose sees a **new list** and redraws.

---

## 3. `LazyColumn` under the button

```kotlin
LazyColumn(
    modifier = Modifier
        .fillMaxSize()
        .padding(16.dp)
) {
    items(sItems) { item ->
        // row UI comes later
    }
}
```

| Piece | Why |
| :--- | :--- |
| `fillMaxSize()` | Take all leftover space → pushes **Add Item** to the top |
| `padding(16.dp)` | Gap between button and list |
| `items(sItems)` | Lazy-list helper: one child per element. Import **`LazyListScope.items`** (the extension), not a random `items` |

`items { }` is a **LazyListScope** lambda, not a normal `Column` child slot. That is why the import matters.

You can write the modifier on one line or split it; same result.

---

## 4. Why the button moved

The column is still `Arrangement.Center`, but the lazy list now claims **the rest of the screen** (even while empty). The button is no longer the only child with height, so it sits at the top. That matches the finished design.
