# Move the Shopping List into Its Own File

---

## Overview

`MainActivity` should stay small: theme + `setContent`. The shopping UI belongs in another file. Same behavior, cleaner structure.

---

## 1. New Kotlin file

Right-click the package → **New → Kotlin File/Class** → File named **`ShoppingList`**.

Put in that file:

* `data class ShoppingItem`
* A new `@Composable fun ShoppingListApp() { ... }` containing the `sItems` state, `Column`, button, and `LazyColumn`

Android Studio usually adds the Compose imports for you when you paste.

```kotlin
// ShoppingList.kt
@Composable
fun ShoppingListApp() {
    var sItems by remember { mutableStateOf(listOf<ShoppingItem>()) }

    Column(
        modifier = Modifier.fillMaxSize(),
        verticalArrangement = Arrangement.Center
    ) {
        Button(
            onClick = { },
            modifier = Modifier.align(Alignment.CenterHorizontally)
        ) {
            Text("Add Item")
        }
        LazyColumn(
            modifier = Modifier
                .fillMaxSize()
                .padding(16.dp)
        ) {
            items(sItems) { }
        }
    }
}
```

---

## 2. Call it from `MainActivity`

```kotlin
setContent {
    MyShoppingListAppTheme {
        Surface(modifier = Modifier.fillMaxSize()) {
            ShoppingListApp()
        }
    }
}
```

Run: **Add Item** still at the top. You only moved code.

---

## Why bother

Later you will add `AlertDialog`, `ShoppingListItem`, and `ShoppingItemEditor`. All of that in `MainActivity` becomes unreadable. One composable per screen (or per feature) is the habit from here on.
