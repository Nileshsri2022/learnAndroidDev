# Seeing Permissions under the hood in the Android Settings

---

## Overview

A short but important lecture: it walks through what the permission code actually produces in the
phone's Settings, and why an app sometimes stops being able to ask.

Understanding this is what makes the two-branch toast from the previous lecture make sense.

---

## Where the grant lives

`Settings → Apps → LocationApp → Permissions`

| Setting in the UI | What it maps to |
| :--- | :--- |
| **Allow** / **Don't allow** | Whether `ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION` is granted |
| **Use precise location** toggle | `ACCESS_FINE_LOCATION` specifically — turning it off leaves only coarse |
| **Ask every time** | The app may prompt again on every launch |

After choosing *While using the app* in the dialog, Settings shows the location permission as
allowed and nothing denied. Turning off "Use precise location" here is exactly the case where
`hasLocationPermission` returns `false` for fine but `true` for coarse — one reason to check both.

---

## The state machine behind the prompts

```text
                ┌──────────────────────────────┐
                │  Never asked                 │
                └──────────────┬───────────────┘
                               │ launch(arrayOf(...))
                               ▼
                ┌──────────────────────────────┐
                │  System dialog appears       │
                └──────┬───────────────┬───────┘
             "Allow"   │               │  "Don't allow"
                       ▼               ▼
        ┌────────────────────┐  ┌─────────────────────────────┐
        │ Granted            │  │ rationaleRequired == true   │
        │ → read location    │  │ → "required for this feature"│
        └────────────────────┘  └──────────────┬──────────────┘
                                               │ denied again
                                               ▼
                                ┌─────────────────────────────┐
                                │ rationaleRequired == false  │
                                │ No more dialogs. Toast:     │
                                │ "enable it in the Settings" │
                                └──────────────┬──────────────┘
                                               │ user must act manually
                                               ▼
                                ┌─────────────────────────────┐
                                │ Settings → Ask every time   │
                                │ → the app can prompt again  │
                                └─────────────────────────────┘
```

---

## What the lecture demonstrates

1. **Allow, then revoke.** Set the permission to *Don't allow* in Settings, tap **Get Location** — the
   dialog appears again (because *Ask every time* is effectively in force), and refusing it shows the
   first toast: *"Location permission is required for this feature to work."*
2. **Refuse twice.** Deny again and the dialog stops appearing. Now the second toast shows:
   *"Please enable it in the Android Settings."* — `rationaleRequired` is `false`, so Android will not
   let the app prompt again.
3. **Restore.** Switch the setting back to *Ask every time* and the app can request once more.

The user has to leave the app and go into the global Android settings to undo a permanent denial.
That is mildly annoying, and it is deliberate.

---

## Why Android behaves this way

> It's a safety feature, because Android doesn't want the situation where this popup appears all the
> time — "activate, activate, activate".

Two protections sit behind it:

- The user's decision is respected: once they have clearly refused, the app cannot keep nagging.
- The app still has to tell the user what to do, which is why the rationale branch exists.

Design consequence: assume permission will sometimes be permanently denied, and make the feature
**degrade gracefully** — a clear message plus a way forward, never a crash or a blank screen.

---

## Recap / cheat sheet

- Grants are visible (and editable) in `Settings → Apps → <app> → Permissions`.
- **Use precise location** off = coarse granted, fine not granted.
- First denial → `rationaleRequired == true` → explain the feature.
- Second denial → `rationaleRequired == false` → the dialog is gone; direct the user to Settings.
- *Ask every time* in Settings re-enables prompting.
- Build UIs that survive a permanent "no".
