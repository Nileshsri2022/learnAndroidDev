## What you built and learned

- **Project setup:** Created the `LocationApp` and declared `ACCESS_COARSE_LOCATION` and `ACCESS_FINE_LOCATION` in `AndroidManifest.xml`.
- **Runtime permission checks:** Used `ContextCompat.checkSelfPermission` against `PackageManager.PERMISSION_GRANTED`.
- **Understood Context:** The vital handle into Android's environment, avoiding context leaks and appreciating activity vs. base context.
- **Compose Permission Launcher:** Used `rememberLauncherForActivityResult` with `ActivityResultContracts.RequestMultiplePermissions()`.
- **Permission rationales and Android settings:** Handled first-time requests, soft rejections with `shouldShowRequestPermissionRationale`, and permanent rejections directing the user to Android device Settings.
- **MVVM integration:** Built `LocationData` and `LocationViewModel` with a backing property `_location` and public `State<LocationData?>`.
- **Fused Location Provider Client:** Connected to Google Play Services to request live coordinates with high accuracy and specified intervals.
- **Emulator simulation:** Used extended controls to set single coordinates and simulate live walking/driving routes.
- **Reverse Geocoding:** Converted numerical latitude and longitude coordinates into human-readable street addresses using `Geocoder`.

---

## Key architectural takeaway

Notice how clean the division of responsibilities remains:

| Component | Responsibility |
| :--- | :--- |
| `LocationUtils` | System bridge: handles permissions, fused location provider, and geocoding |
| `LocationViewModel` | State holder: holds current `LocationData` across recompositions |
| `LocationDisplay` | Composable UI: observes state, triggers actions, handles launcher dialogs |
| `MainActivity` | Entry point: sets up context, view model, and surface |

The code written today is directly reusable. Whenever any future app needs location, you can copy
`LocationUtils`, `LocationData`, and the launcher pattern without starting from scratch.

## Recap / cheat sheet

- Runtime permissions are mandatory for sensitive sensors like GPS.
- The `rememberLauncherForActivityResult` pattern handles Compose permission flows smoothly.
- `FusedLocationProviderClient` abstracts away GPS vs. Wi-Fi triangulation.
- `Geocoder` turns coordinates into addresses.
- Architecture matters: keep sensor and platform utilities isolated in helper classes and pass data via ViewModels.
