# Reading the Latitude and Longitude and displaying it

---

## Overview

Everything is in place: permissions are checked, a view model is waiting, and the UI has a button.
This lecture writes the core location logic: creating a `FusedLocationProviderClient`, requesting
updates through a callback, feeding them into `LocationViewModel`, and rendering latitude and
longitude on screen.

---

## Step 1 — initialize the client

In `LocationUtils`:

```kotlin
class LocationUtils(val context: Context) {

    private val _fusedLocationClient: FusedLocationProviderClient =
        LocationServices.getFusedLocationProviderClient(context)

    // ...
}
```

Imported from `com.google.android.gms.location`.

The **fused location provider** is Google Play Services' location client. It "fuses" GPS, Wi-Fi, and
cellular signals to deliver the best possible fix without the app having to decide which sensor to
read. It requires the context passed to the constructor.

---

## Step 2 — request location updates

Add `requestLocationUpdates` to `LocationUtils`:

```kotlin
@SuppressLint("MissingPermission")
fun requestLocationUpdates(viewModel: LocationViewModel) {
    val locationCallback = object : LocationCallback() {
        override fun onLocationResult(locationResult: LocationResult) {
            super.onLocationResult(locationResult)
            locationResult.lastLocation?.let {
                val location = LocationData(latitude = it.latitude, longitude = it.longitude)
                viewModel.updateLocation(location)
            }
        }
    }

    val locationRequest = LocationRequest.Builder(
        Priority.PRIORITY_HIGH_ACCURACY, 1000
    ).build()

    _fusedLocationClient.requestLocationUpdates(
        locationRequest,
        locationCallback,
        Looper.getMainLooper()
    )
}
```

There are four parts here:

### 1. The anonymous callback object

```kotlin
val locationCallback = object : LocationCallback() {
    override fun onLocationResult(locationResult: LocationResult) { ... }
}
```

`object : LocationCallback()` creates an anonymous object directly implementing/overriding
`LocationCallback` on the spot, rather than creating a whole named subclass.

Inside `onLocationResult`, `locationResult.lastLocation` is unpacked using `.let { ... }`.
`it.latitude` and `it.longitude` are extracted, wrapped into a `LocationData` instance, and sent to
the view model via `viewModel.updateLocation(location)`.

### 2. The `LocationRequest` builder

```kotlin
val locationRequest = LocationRequest.Builder(
    Priority.PRIORITY_HIGH_ACCURACY, 1000
).build()
```

The builder configures:

| Setting | Value | Meaning |
| :--- | :--- | :--- |
| Priority | `Priority.PRIORITY_HIGH_ACCURACY` | Uses GPS; highest precision, highest battery usage |
| Interval | `1000` ms | Asks the provider for updates roughly every 1 second |

Other priority options:

- `PRIORITY_BALANCED_POWER_ACCURACY` — good accuracy with less battery drain (Wi-Fi / cell).
- `PRIORITY_LOW_POWER` — minimal battery, coarse accuracy.
- `PRIORITY_PASSIVE` — receives updates only when other apps request them.

### 3. Registering the request

`_fusedLocationClient.requestLocationUpdates(locationRequest, locationCallback, Looper.getMainLooper())`

`Looper.getMainLooper()` ensures the callback runs on the **main (UI) thread**, so state updates
trigger recomposition smoothly.

### 4. `@SuppressLint("MissingPermission")`

Calling `requestLocationUpdates` triggers a compiler lint error: *Missing permissions: requires
`ACCESS_COARSE_LOCATION` or `ACCESS_FINE_LOCATION`*.

Android's lint tool warns because it cannot prove statically that permission was checked before
calling this method. We suppress it with:

```kotlin
@SuppressLint("MissingPermission")
```

The lint tool checks source files for correctness, security, performance, and accessibility. Here we
tell it: *we checked the permission ourselves before calling this function, ignore the warning.*

## Step 3 — connect to the UI

In `LocationDisplay` inside `MainActivity`:

```kotlin
@Composable
fun LocationDisplay(
    locationUtils: LocationUtils,
    viewModel: LocationViewModel,
    context: Context
) {
    val location = viewModel.location.value

    val requestPermissionLauncher = rememberLauncherForActivityResult(
        contract = ActivityResultContracts.RequestMultiplePermissions(),
        onResult = { permissions ->
            if (permissions[Manifest.permission.ACCESS_COARSE_LOCATION] == true &&
                permissions[Manifest.permission.ACCESS_FINE_LOCATION] == true) {
                // Permission granted through dialog
                locationUtils.requestLocationUpdates(viewModel = viewModel)
            } else {
                val rationaleRequired = ActivityCompat.shouldShowRequestPermissionRationale(
                    context as MainActivity,
                    Manifest.permission.ACCESS_FINE_LOCATION
                ) || ActivityCompat.shouldShowRequestPermissionRationale(
                    context as MainActivity,
                    Manifest.permission.ACCESS_COARSE_LOCATION
                )

                if (rationaleRequired) {
                    Toast.makeText(
                        context,
                        "Location Permission is required for this feature to work",
                        Toast.LENGTH_LONG
                    ).show()
                } else {
                    Toast.makeText(
                        context,
                        "Location Permission is required. Please enable it in the Android Settings",
                        Toast.LENGTH_LONG
                    ).show()
                }
            }
        }
    )

    Column(
        modifier = Modifier.fillMaxSize(),
        horizontalAlignment = Alignment.CenterHorizontally,
        verticalArrangement = Arrangement.Center
    ) {
        if (location != null) {
            Text(text = "Address: ${location.latitude} ${location.longitude}")
        } else {
            Text(text = "Location not available")
        }

        Button(onClick = {
            if (locationUtils.hasLocationPermission(context)) {
                // Permission already granted
                locationUtils.requestLocationUpdates(viewModel = viewModel)
            } else {
                requestPermissionLauncher.launch(
                    arrayOf(
                        Manifest.permission.ACCESS_FINE_LOCATION,
                        Manifest.permission.ACCESS_COARSE_LOCATION
                    )
                )
            }
        }) {
            Text(text = "Get Location")
        }
    }
}
```

Notice:

- When `location != null`, the `Text` displays latitude and longitude.
- When `hasLocationPermission(context)` is `true` on button tap, we immediately call `requestLocationUpdates(viewModel)`.
- When permission was just granted via the launcher dialog, we also call `requestLocationUpdates(viewModel)`.

## The complete flow

```text
User taps "Get Location"
         │
         ├── Permission already granted?
         │         │ YES: locationUtils.requestLocationUpdates(viewModel)
         │         ▼
         │   fusedLocationClient starts polling (every 1s)
         │         ▼
         │   onLocationResult receives LocationResult
         │         ▼
         │   viewModel.updateLocation(LocationData(lat, lng))
         │         ▼
         │   _location.value changes
         │         ▼
         │   Recomposition: UI displays "Address: <lat> <lng>"
         │
         └── NO: requestPermissionLauncher.launch(...)
                   │
                   ├── Granted → requestLocationUpdates(viewModel)
                   └── Denied → Show rationale or settings Toast
```

## Recap / cheat sheet

- `LocationServices.getFusedLocationProviderClient(context)` — entry point to location.
- `LocationCallback` object with `override fun onLocationResult(locationResult: LocationResult)`.
- `LocationRequest.Builder(Priority.PRIORITY_HIGH_ACCURACY, intervalMillis).build()`.
- `Looper.getMainLooper()` delivers updates on the UI thread.
- `@SuppressLint("MissingPermission")` tells lint the permission check is handled manually.
- `viewModel.location.value` drives Compose recomposition as updates arrive.
