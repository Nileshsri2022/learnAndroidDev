# Adding Permissions for Coarse and Fine Location in the AndroidManifest

---

## Overview

Every location app starts the same way: a new project and two lines in the manifest. Declaring a
permission tells Android *which* capabilities the app intends to use; it does not grant them. That
second half happens at runtime, in the next lecture.

---

## Step 1 — create the project

Create a new project from the **Empty Activity** template and name it `LocationApp` (the lecture also
suggests `LocationBasics`, which describes the scope just as well). Wait for the Gradle sync to
finish before touching any code.

---

## Step 2 — declare the permissions

Permissions go in `AndroidManifest.xml`, as children of the root `<manifest>` element — **outside**
`<application>`:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />

    <application ... >
        ...
    </application>
</manifest>
```

Android Studio autocompletes the permission names as you type `android.permission.` — pick from the
list rather than typing them from memory.

`INTERNET` is included because most apps end up needing it (reverse geocoding and maps both talk to
the network). If an app genuinely never goes online, leave it out.

> Only declare what you use. An auto-generated permission that the app does not need is not just
> noise — in the lecture an unwanted extra permission caused a small problem at runtime and had to be
> deleted again.

---

## Coarse vs fine location

| | `ACCESS_COARSE_LOCATION` | `ACCESS_FINE_LOCATION` |
| :--- | :--- | :--- |
| Accuracy | Rough — city or region level | Precise — a few meters / yards |
| Sources | Cell towers, connected Wi-Fi, nearby Wi-Fi networks | GPS and other satellite-based positioning |
| Hardware | No GPS radio needed | Activates the GPS receiver |
| Battery cost | Lower | Higher |
| Good for | "Which country/state is the user in?" | "Which house / which PokéStop?" |

Both are worth declaring together: when the user is asked for location access, the two are granted as
a pair, and code that checks for one usually checks for the other.

---

## Battery is a design decision

Location is one of the more expensive things an app can ask the hardware to do.

- Request the **least precise** permission that still makes the feature work.
- Only read the position while it is actually needed.
- Coarse avoids switching the GPS on at all; fine switches it on and drains the battery noticeably.

An app that leaves the GPS running for no reason gets uninstalled.

---

## Recap / cheat sheet

- Manifest permissions live under `<manifest>`, not inside `<application>`.
- `<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />`
- `<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />`
- **Coarse** = cell/Wi-Fi, approximate, cheap. **Fine** = GPS, precise, expensive.
- Declaring a permission is step one; the user still has to grant it at runtime.
