# RememberLauncherForActivityResult — Starting the Permission request

---

## Overview

With the permission declared and a helper to check it, the app needs a UI and a way to **ask**. This
lecture builds `LocationDisplay` and sets up the permission launcher; the next one finishes the
request logic.

---

## Step 1 — the composable

Delete the template `Greeting` composable and add a new one. It can live in `MainActivity` for now
(it could equally go into its own file):

```kotlin
@Composable
fun LocationDisplay(locationUtils: LocationUtils, context: Context) {
    Column(
        modifier = Modifier.fillMaxSize(),
        horizontalAlignment = Alignment.CenterHorizontally,
        verticalArrangement = Arrangement.Center
    ) {
        Text(text = "Location not available")

        Button(onClick = {
            if (locationUtils.hasLocationPermission(context)) {
                // permission already granted — update the location
            } else {
                // request the location permission
            }
        }) {
            Text(text = "Get Location")
        }
    }
}
```

Both parameters are needed: `locationUtils` performs the check and later the location request, and
`context` is what those calls require.

---

## Step 2 — the launcher

The permission dialog is an **activity for result**: something is launched, the user answers, and a
result comes back. `rememberLauncherForActivityResult` registers that round trip.

> It registers a request to start an activity for result, creating a record in the registry associated
> with its caller, managing the request code as well as conversions to and from `Intent` under the
> hood.

It goes **before** the `Column`, at the top of the composable:

```kotlin
val requestPermissionLauncher = rememberLauncherForActivityResult(
    contract = ActivityResultContracts.RequestMultiplePermissions(),
    onResult = { permissions ->
        val isGranted = permissions[Manifest.permission.ACCESS_COARSE_LOCATION] == true &&
                permissions[Manifest.permission.ACCESS_FINE_LOCATION] == true

        if (isGranted) {
            // we have access to the location
        } else {
            // ask for permission / explain why it is needed
        }
    }
)
```

---

## The two arguments

| Argument | Purpose |
| :--- | :--- |
| `contract` | Specifies the conversions to and from `Intent` — i.e. what kind of activity is being started |
| `onResult` | The lambda that runs when the launched activity returns; its parameter type is defined by the contract |

`ActivityResultContracts.RequestMultiplePermissions()` returns a **`Map<String, Boolean>`**: the
permission name as the key, and whether it was granted as the value.

```text
onResult receives:
┌────────────────────────────────────────────────┬───────────┐
│ "android.permission.ACCESS_COARSE_LOCATION"    │ true      │
│ "android.permission.ACCESS_FINE_LOCATION"      │ true      │
└────────────────────────────────────────────────┴───────────┘
```

That is why the map is read with the permission string as its key, and why the check ends in
`== true` — the lookup is nullable, so a missing key must not be mistaken for a grant.

---

## Activity ≠ always a full screen

An "activity for result" is usually another screen, but the permission dialog shows that this is not
a requirement. `MainActivity` is the whole screen; the dialog is a popup launched on top of it, and
its answer still comes back through `onResult`.

---

## Import gotcha

`Manifest.permission.ACCESS_COARSE_LOCATION` will not resolve until `android.Manifest` is imported.
The lecture hits exactly this: the code looks correct but the reference is red, and adding the
`Manifest` import fixes it.

---

## Recap / cheat sheet

- `rememberLauncherForActivityResult(contract, onResult)` — Compose's activity-for-result API.
- `ActivityResultContracts.RequestMultiplePermissions()` → `Map<String, Boolean>`.
- Read the map with the permission constant and compare to `true`.
- Declare the launcher at the top of the composable, before the layout.
- Import `android.Manifest`, or the permission constants will not resolve.
- One launcher can request many permissions in a single prompt.
