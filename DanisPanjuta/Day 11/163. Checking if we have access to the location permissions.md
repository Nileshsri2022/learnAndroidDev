# Checking if we have access to the location permissions

---

## Overview

Declaring a permission in the manifest says nothing about whether the user actually granted it. Before
reading a position the app must ask. Rather than repeating that check inside every composable, the
lecture puts it in a small helper class that can be called from anywhere.

---

## The helper class

Create a new Kotlin file/class called `LocationUtils`:

```kotlin
class LocationUtils(val context: Context) {

    fun hasLocationPermission(context: Context): Boolean {
        return ContextCompat.checkSelfPermission(
            context,
            Manifest.permission.ACCESS_FINE_LOCATION
        ) == PackageManager.PERMISSION_GRANTED &&
                ContextCompat.checkSelfPermission(
                    context,
                    Manifest.permission.ACCESS_COARSE_LOCATION
                ) == PackageManager.PERMISSION_GRANTED
    }
}
```

`Context` is covered in the next lecture — for now it is enough to know that it is the handle the
system APIs need in order to work.

---

## How the check works

`ContextCompat.checkSelfPermission(...)` takes a context and a permission name and returns an **Int**,
not a Boolean. That is why it is compared against `PackageManager.PERMISSION_GRANTED`:

| Piece | Type | Meaning |
| :--- | :--- | :--- |
| `ContextCompat.checkSelfPermission(context, permission)` | `Int` | The system's verdict for that permission |
| `PackageManager.PERMISSION_GRANTED` | `Int` | The constant meaning "granted" |
| `... == ...` | `Boolean` | What the function should return |

So the whole expression already *is* the answer.

---

## Letting Android Studio simplify it

Writing it as an `if` first makes the logic obvious:

```kotlin
if (ContextCompat.checkSelfPermission(context, Manifest.permission.ACCESS_FINE_LOCATION)
        == PackageManager.PERMISSION_GRANTED) {
    return true
} else {
    return false
}
```

Two quick-fixes then collapse it:

1. **Lift return out of `if`** — turn the branches into a single returned expression.
2. **Remove redundant `if` statement** — the expression is already a Boolean, so return it directly.

The result is the one-liner used above. Same behaviour, far less code.

---

## Why both permissions

The check is joined with `&&` so it only returns `true` when **both** coarse and fine have been
granted. In practice Android grants them together — the user sees one location prompt — but checking
both keeps the helper honest if a user later turns off "precise location" in Settings.

---

## Recap / cheat sheet

- Manifest = "I intend to use this." Runtime check = "may I use it right now?"
- `ContextCompat.checkSelfPermission(context, Manifest.permission.X)` returns an **Int**.
- Compare it to `PackageManager.PERMISSION_GRANTED` to get a Boolean.
- Return the comparison directly instead of an `if/else` — Android Studio offers the refactor.
- Keep the check in a helper (`LocationUtils`) so UI code stays clean.
- Check **coarse and fine** together with `&&`.
