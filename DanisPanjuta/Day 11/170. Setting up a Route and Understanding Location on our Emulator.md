# Setting up a Route and Understanding Location on our Emulator

---

## Overview

Physical devices have GPS sensors that respond to real-world movement. When running inside the
Android emulator on a development computer, there is no real GPS. This lecture shows how the
emulator simulates coordinates, how to set fake locations (like the Cologne Cathedral), and how to
replay simulated routes to watch real-time coordinate updates in the app.

---

## The Emulator Extended Controls

Click the **`...` (Extended controls)** icon on the emulator toolbar.

In the sidebar, select **Location**:

- The map shows the current simulated location (default is usually Googleplex in Mountain View, CA:
  `37.4220`, `-122.0841`).
- You can drag the map marker, search for a place, or type specific latitude and longitude coordinates.
- Click **Set Location** to apply the coordinates immediately to the running virtual device.

## Testing single points

In the lecture, Danis navigates on the map to Cologne, Germany:

- **Cologne Cathedral (Kölner Dom):** Latitude `50.9413`, Longitude `6.9583`.
- Clicking **Set Location** instantly updates the emulator's GPS receiver.
- Looking back at the app: the text changes almost immediately to `50.94...` and `6.95...`.
- Because `requestLocationUpdates` configured a `1000ms` (1 second) interval, the UI updates
  automatically without needing another button click.

## Simulating routes and movement

The emulator's **Routes** tab lets you simulate walking or driving along a path:

1. Select **Routes** in the Location panel.
2. Search for or select a starting point and destination points.
3. Save the route.
4. Set a playback speed (e.g., `1x`, `2x`, `5x`).
5. Click **Play Route**.

### What happens in the app

As the simulated route runs:

```text
Emulator moves along route
         │
         ▼
GPS coordinates emit updates every second
         │
         ▼
LocationCallback.onLocationResult triggered
         │
         ▼
viewModel.updateLocation(LocationData(lat, lng))
         │
         ▼
Compose recomposes Text with new coordinates live!
```

The app displays continuous coordinate changes, proving that:

- The `LocationCallback` is firing repeatedly.
- The `ViewModel` holds and updates state reliably.
- Compose is reacting and recomposing only the parts of the UI that depend on `location`.

## Recap / cheat sheet

- Open emulator **Extended controls (`...`) → Location**.
- **Single points:** pick a location or type coordinates → **Set Location**.
- **Routes:** add waypoints, choose playback speed (e.g. `5x`), click **Play Route**.
- Coordinates update in real-time in the app thanks to the 1000ms callback loop.
- Verification that the MVVM state pipeline (`FusedClient` → `Callback` → `ViewModel` → Compose UI) works end-to-end.
