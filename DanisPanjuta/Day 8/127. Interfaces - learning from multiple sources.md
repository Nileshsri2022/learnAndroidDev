# Interfaces — Learning From Multiple Sources

---

## The problem inheritance cannot solve

The House of Base Class has two separate talents:

* the **archers** — good with a bow
* the **singers** — good with music

Some offspring are great at **both**: shooting arrows with three fingers *while* singing.

You cannot get that with plain class inheritance. A class has exactly one direct parent, so it can
only inherit one bloodline. To learn from more than one source you need **interfaces**.

---

## The setup

First, `Secondary` must also be `open`, so it can be a parent:

```kotlin
open class BaseClass {
    fun coreValues() { println("Core values of House Base Class") }
    open fun role() { println("Member of the House of Base Class") }
}

open class Secondary : BaseClass() {
    override fun role() {
        super.role()
        println("Knight of the House of Base Class")
    }
}

class Tertiary : BaseClass() {
    override fun role() { println("Bard of the House of Base Class") }
}
```

Now the two "teachers" — these are **interfaces**, not classes:

```kotlin
interface Archer {
    fun archery()
}

interface Singer {
    fun sing()
}
```

> Small correction made during the lecture: the interface is called **`Archer`** (the *person*),
> while the *function* inside it is called **`archery`** (the *skill*).

---

## The offspring

```kotlin
class Offspring : Secondary(), Archer, Singer {

    override fun archery() {
        super.archery()                      // optional — runs the interface's own body
        println("Archery skills enhanced by Offspring")
    }

    override fun sing() {
        super.sing()                         // optional
        println("Singing skills enhanced by Offspring")
    }
}
```

The class header is the important part:

```
class Offspring : Secondary(), Archer, Singer
                  └── one real parent ──┘ └── any number of interfaces ──┘
```

* **`Secondary()`** — the bloodline. Gives `Offspring` everything `BaseClass` has too.
* **`Archer`** and **`Singer`** — extra skills learned from elsewhere (dad's archery, aunt
  Tertiary's singing).

Adding interfaces is a **comma-separated list** after the parent constructor.

---

## Why no `open` is needed

Notice `archery()` and `sing()` are overridden **without** the parent declaring `open`.

Interface members are implicitly overridable — an interface *wants* you to implement its
functions. That is the entire idea behind an interface: it is a contract saying "if you claim my
skill, you must provide these functions".

---

## What `Frank` can do

```kotlin
fun main() {
    val frank = Offspring()

    frank.archery()   // Archery skills from Sir Secondary
                      // Archery skills enhanced by Offspring

    frank.sing()      // Singing skills from Lady Tertiary
                      // Singing skills enhanced by Offspring

    frank.role()      // Member of the House of Base Class
                      // Knight of the House of Base Class

    frank.coreValues()// Core values of House Base Class
}
```

Four capabilities, three sources:

| Skill | Comes from |
| :--- | :--- |
| `archery()` | `Archer` interface |
| `sing()` | `Singer` interface |
| `role()` | overridden in `Secondary` |
| `coreValues()` | `BaseClass`, two levels up |

`Offspring` inherits from `Secondary`, which inherits from `BaseClass`, **and** implements two
interfaces — so it holds the whole family's skills plus its own improvements.

---

## `super.archery()` vs `super<Archer>.archery()`

Inside an interface implementation you can write either:

```kotlin
super.archery()          // works fine
super<Archer>.archery()  // more explicit, same thing
```

The second form names the interface directly. You will see it occasionally; it is not required.

## Why this matters later in the course

At this point in the app none of this is strictly necessary — the interfaces are there for the
lesson. But it prepares you for when the course *does* need a class to satisfy several contracts at
once, and it is the mechanism behind every Android callback and listener you will ever implement.
