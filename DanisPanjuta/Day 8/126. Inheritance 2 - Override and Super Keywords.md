# Inheritance 2 — `override` and `super`

---

## Overview

`Secondary` inherited `coreValues()` unchanged. But what if the child needs the *same* function to
do something *different*? That is what **`override`** is for, and **`super`** is how you still reach
the parent's version.

---

## The setup

Add a second function to the parent:

```kotlin
open class BaseClass {

    fun coreValues() {
        println("Core values of House Base Class")
    }

    open fun role() {
        println("Member of the House of Base Class")
    }
}
```

`role` is marked **`open`** — it must be, or it cannot be overridden. (Same rule as `open class`.)

Now the children get their own roles:

```kotlin
class Secondary : BaseClass() {

    override fun role() {
        super.role()   // execute the parent's version first
        println("Knight of the House of Base Class")
    }
}
```

```kotlin
class Tertiary : BaseClass() {

    override fun role() {
        println("Bard of the House of Base Class")
    }
}
```

---

## Running it

```kotlin
fun main() {
    val objectTwo = Secondary()
    objectTwo.role()      // Member of the House of Base Class
                          // Knight of the House of Base Class

    val objectThree = Tertiary()
    objectThree.role()    // Bard of the House of Base Class
}
```

Three different results from one function name:

| Object | Class has an `override`? | Output |
| :--- | :--- | :--- |
| `BaseClass()` | n/a | `Member of the House of Base Class` |
| `Secondary()` | yes, with `super.role()` | `Member…` **and** `Knight…` |
| `Tertiary()` | yes, without `super.role()` | `Bard of the House of Base Class` |

---

## `super.role()` explained

`super` means "the parent". `super.role()` says: *execute whatever the base class said should happen
for `role`* — i.e. run the code inside the parent's curly braces.

That is why the second line appears even though `Secondary`'s `role()` never writes
"Member of the House of Base Class" itself. It borrowed it from the parent.

It is **optional**. Delete `super.role()` and `Secondary` prints only `Knight of the House of Base
Class`. Keeping it is the normal choice when you want the parent's behaviour *plus* extra
behaviour.

---

## The dispatch rule

> When you call `role()` and the class has an override, run **my overridden** version.
> If the function does not exist in this class with the `override` keyword, run the **base class's**
> version.

Before `Tertiary` had an override, `objectThree.role()` printed
`Member of the House of Base Class` — it silently used the parent's. The moment the override
appeared, it printed `Bard…`.

---

## The analogy, restated

* By default, being born into the House of Base Class makes you a **member**.
* To get a special role — Knight, Archer, Bard — you must **override** the inherited function.
* `super.role()` is "and I still honour the house rules I was born with".

---

## Rules to remember

| Thing | Rule |
| :--- | :--- |
| `open fun role()` | required in the parent, otherwise overriding is impossible |
| `override fun role()` | required in the child |
| `super.role()` | calls the parent implementation; optional |
| No override | the parent's version is used |
