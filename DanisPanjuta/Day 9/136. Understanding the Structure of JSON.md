# Understanding the Structure of JSON

---

## Overview

A JSON document is made from objects, arrays, and primitive values. This lecture uses a small `Potion` model to connect a Kotlin list of objects with the JSON representation a server can return.

---

## Kotlin model and sample values

```kotlin
data class Potion(
    val name: String,
    val effect: String,
    val potency: Int
)

val potions = listOf(
    Potion("Healing Potion", "Restores health", 50),
    Potion("Invisibility Potion", "Grants invisibility", 40),
    Potion("Strength Potion", "Boosts strength", 60)
)
```

The JSON equivalent is an array of objects:

```json
[
  { "name": "Healing Potion", "effect": "Restores health", "potency": 50 },
  { "name": "Invisibility Potion", "effect": "Grants invisibility", "potency": 40 },
  { "name": "Strength Potion", "effect": "Boosts strength", "potency": 60 }
]
```

---

## Read it from the outside in

1. The square brackets mean the top-level value is an array.
2. Each comma-separated item in that array is an object in curly braces.
3. Each object has named properties such as `name` and `effect`.
4. Quoted values are strings; `50` is a number.
5. An object property can itself hold an array or another object, so nesting is allowed.

For example, a potion may include a list of permitted users:

```json
{
  "name": "Invisibility Potion",
  "allowedUsers": ["Rogue", "Scout"]
}
```

---

## JSON and XML

XML expresses the same information with opening and closing tags and document metadata. JSON commonly needs less markup, while both formats can represent nested structures. A client must know the expected schema in either case.

---

## Recap / cheat sheet

| JSON shape | Meaning | Kotlin concept |
| :--- | :--- | :--- |
| `{ "key": value }` | Object/property | Data class property |
| `[value, value]` | Ordered collection | `List<T>` |
| `"text"` | String | `String` |
| `50` | Number | `Int`, `Long`, etc. |
| `null` | Missing/empty value | Nullable type, e.g. `String?` |

The key skill is reading the response structure accurately before writing the matching data classes.
