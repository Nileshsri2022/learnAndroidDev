# Adding Internet Permission and Running the App

---

## Overview

Android apps need to declare Internet access in the manifest before making network requests. After adding the permission and verifying the endpoint URL, run the app to test loading, response parsing, and remote images together.

---

## Manifest permission

Add the permission as a child of the root `<manifest>` element, outside the `<application>` element:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

Internet access is a normal permission; unlike camera or location access, it does not trigger a runtime permission prompt. The app still needs a working connection and valid endpoint.

---

## Verify the URL

The Retrofit base URL must be a valid absolute URL, use HTTPS when supported, and end with `/`. The endpoint path is appended to the base URL:

```text
Base URL:  https://www.themealdb.com/api/json/v1/1/
Endpoint:  categories.php
Request:   https://www.themealdb.com/api/json/v1/1/categories.php
```

A missing scheme (`https://`), incorrect path, or malformed base URL can cause the request to fail. Confirm the endpoint in the provider documentation or a browser/API client.

---

## Run checklist

1. Confirm the app-module dependencies synced successfully.
2. Check that the manifest permission is outside `<application>`.
3. Confirm the `baseUrl` and `@GET` path combine correctly.
4. Launch the app with network access.
5. Expect a brief loading state, followed by category tiles, or a visible error state if the request fails.
6. Scroll the grid and confirm remote thumbnails load.

---

## Recap / cheat sheet

- Declare `android.permission.INTERNET` in `AndroidManifest.xml`.
- It is a normal permission, not a runtime prompt.
- Retrofit base URLs should end in `/`.
- Test loading, success, error, scrolling, and remote image behavior.
