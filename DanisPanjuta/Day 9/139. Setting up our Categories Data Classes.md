# Setting Up Our Categories Data Classes

---

## Overview

The API returns a top-level object containing a `categories` array. Each array element has an ID, display name, thumbnail URL, and description. Kotlin data classes describe this shape so the JSON converter can create useful objects from the response.

---

## Category model

The JSON property names matter. The course uses the API's field names directly:

```kotlin
data class Category(
    val idCategory: String,
    val strCategory: String,
    val strCategoryThumb: String,
    val strCategoryDescription: String
)
```

Use nullable properties or explicit serialization annotations if the server's schema permits missing fields or if Kotlin property names differ from JSON keys. Here, all four fields are modeled as strings to match the category response shown in the lecture.

---

## Top-level response model

```kotlin
data class CategoriesResponse(
    val categories: List<Category>
)
```

This class models the outer JSON object. The `categories` key maps to a Kotlin `List<Category>`; each object inside the array maps to one `Category` instance.

```json
{
  "categories": [
    {
      "idCategory": "1",
      "strCategory": "Beef",
      "strCategoryThumb": "https://example.test/beef.png",
      "strCategoryDescription": "..."
    }
  ]
}
```

---

## Mapping flow

```text
JSON object → CategoriesResponse → categories: List<Category>
                                     └─ Category(id, name, image URL, description)
```

The model is not a database or a UI. It is the typed representation of the server's response that later layers can pass along and display.

---

## Recap / cheat sheet

- Create one Kotlin type for each JSON object shape you need.
- The top-level class must reflect the response's outer object.
- Arrays map naturally to `List<T>`.
- Keep property names/types aligned with the API schema or annotate the mapping.
- Model only the fields the current feature uses.
