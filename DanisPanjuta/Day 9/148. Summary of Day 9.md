# Summary of Day 9 — JSON, Retrofit, and the Recipe App

The course's **Summary of Day 9** lecture has no transcript. This recap brings together the topics and recipe-app flow covered in the day's videos.

---

## Theme

Move from local-only UI to a data-driven Android screen: request JSON from a REST API, map it into Kotlin models, expose it as ViewModel state, and render the result in Compose.

---

## The application flow

```text
MainActivity
   │ displays
   ▼
RecipeScreen ── observes ── MainViewModel / RecipeState
                                  │ viewModelScope.launch
                                  ▼
                           ApiService (Retrofit)
                                  │ HTTP GET
                                  ▼
                              TheMealDB
                                  │ JSON response
                                  ▼
                    CategoriesResponse / Category
                                  │ state update
                                  ▼
                    LazyVerticalGrid + Coil images
```

---

## Core models

```kotlin
data class Category(
    val idCategory: String,
    val strCategory: String,
    val strCategoryThumb: String,
    val strCategoryDescription: String
)

data class CategoriesResponse(
    val categories: List<Category>
)

data class RecipeState(
    val isLoading: Boolean = true,
    val categories: List<Category> = emptyList(),
    val error: String? = null
)
```

The response models the provider's JSON shape. The UI state adds the information the screen needs to decide whether to show progress, an error, or the loaded categories.

---

## Retrofit service and request

```kotlin
interface ApiService {
    @GET("categories.php")
    suspend fun getCategories(): CategoriesResponse
}
```

Configure Retrofit with the API's HTTPS base URL and a compatible JSON converter, then create the service from the interface. A `suspend` endpoint can be called from coroutine code; it allows the request to wait without blocking the UI thread.

---

## ViewModel responsibilities

The ViewModel launches the request in `viewModelScope`, catches failures, and publishes updated state. The state transitions are:

| State | UI result |
| :--- | :--- |
| Loading | Centered progress indicator |
| Error message present | Error content (ideally with retry) |
| Loaded categories | Category grid |

The UI observes state; it does not build URLs or perform networking itself.

---

## JSON and HTTP quick reference

| Concept | Reminder |
| :--- | :--- |
| JSON object | `{}` named properties |
| JSON array | `[]` ordered values |
| API endpoint | Resource path appended to a base URL |
| HTTP GET | Request data from a service |
| Retrofit converter | Maps JSON response to Kotlin classes |
| Nullable property | `String?` can be `null` |

The app also needs the manifest declaration `android.permission.INTERNET`. Coil separately loads each thumbnail using the URL supplied by the category response.

---

## Important distinctions

- `suspend` marks a function that can suspend; it is not a universal background-thread switch for arbitrary blocking work.
- Retrofit's coroutine support makes network calls suspending; CPU-heavy or blocking work may need an appropriate dispatcher.
- JSON tells you the structure, while the API documentation tells you the meaning and contract of each field.
- `try`/`catch` prevents an unhandled failure from taking down the request flow, but the app should still show a useful recovery path.

---

## Recap / cheat sheet

- **Model the response:** JSON object/array structure → matching Kotlin data classes.
- **Request data:** Retrofit service + HTTP GET + a `suspend` endpoint.
- **Run without freezing:** call the endpoint in `viewModelScope`.
- **Represent the screen:** loading, error, and loaded data in observable state.
- **Render:** Compose reads state; `LazyVerticalGrid` lays out categories; Coil loads thumbnails.
- **Enable networking:** declare `android.permission.INTERNET` and verify the full HTTPS URL.
