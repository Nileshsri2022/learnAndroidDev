# Preparing Our RecipeScreen

---

## Overview

`RecipeScreen` is the top-level composable for the recipe browser. It reads the ViewModel's state and decides what the user should see: a loading indicator, an error message, or the category content.

---

## Observe the state

With Compose state delegation, the screen can read the current value directly:

```kotlin
@Composable
fun RecipeScreen(
    viewModel: MainViewModel,
    modifier: Modifier = Modifier
) {
    val viewState by viewModel.categoryState

    Box(modifier = modifier.fillMaxSize()) {
        when {
            viewState.isLoading -> {
                CircularProgressIndicator(
                    modifier = Modifier.align(Alignment.Center)
                )
            }
            viewState.error != null -> {
                Text(
                    text = viewState.error,
                    modifier = Modifier.align(Alignment.Center)
                )
            }
            else -> {
                CategoryScreen(categories = viewState.categories)
            }
        }
    }
}
```

If using delegation, import the appropriate Compose `getValue` extension. The screen receives the ViewModel and reads state; the ViewModel remains responsible for fetching data.

---

## Three screen conditions

1. **Loading:** show a centered `CircularProgressIndicator` while the request is in progress.
2. **Failure:** show an error message when the state has an error.
3. **Content:** show the category screen once loading is complete and no error exists.

An explicit state model avoids mixing request logic into composables. A production screen can improve the error case with retry actions and accessibility-friendly messaging.

---

## Recap / cheat sheet

- `Box` is useful for positioning a progress indicator in the center.
- State reads inside a composable subscribe it to updates.
- Render based on state; do not make the UI perform HTTP work.
- Keep loading, error, and success/content paths visibly distinct.
