# Going Through the Whole Flow of Our Application

---

## Overview

This lecture traces how the recipe categories move from the remote service to the screen. Thinking through the complete path makes the responsibilities of the Activity, composables, ViewModel, Retrofit service, and data models easier to distinguish.

---

## End-to-end flow

```text
MainActivity
    ↓ shows
RecipeScreen
    ↓ observes
MainViewModel / RecipeState
    ↓ launches a coroutine
ApiService.getCategories()  -- Retrofit GET -->  TheMealDB
    ↓ JSON converter maps response
CategoriesResponse → List<Category>
    ↓ ViewModel publishes state
RecipeScreen → CategoryScreen → CategoryItem + remote image
```

1. **MainActivity** sets the app theme/surface and displays `RecipeScreen`.
2. **RecipeScreen** obtains or receives the ViewModel and observes its state.
3. **MainViewModel** starts loading categories when it is initialized.
4. **`viewModelScope`** launches a coroutine so the suspend network call is lifecycle-aware.
5. **Retrofit** combines the base URL and endpoint, sends the GET request, and uses a converter to map JSON into Kotlin objects.
6. **ViewModel** writes success or failure to `RecipeState`; Compose observes the new value.
7. **RecipeScreen** shows progress, error, or content based on the state.
8. **CategoryScreen** passes every `Category` to an item composable; Coil loads its thumbnail URL.

---

## Who owns what?

| Layer | Responsibility |
| :--- | :--- |
| Activity | App entry point and top-level Compose content |
| Screen composables | Render the state and arrange UI elements |
| ViewModel | Request orchestration and UI-related state |
| Retrofit service | Describe HTTP operations and endpoint paths |
| Data classes | Represent the JSON response as typed Kotlin values |
| Coil | Fetch and display remote images |
| TheMealDB | Provide the remote category/recipe data |

---

## Why state is the bridge

The service returns data, but it does not update Compose directly. The ViewModel places the category list in observable state. When that state changes, Compose recomposes the relevant UI. This keeps the presentation independent of the mechanics of the HTTP call.

---

## Recap / cheat sheet

- Request → parse → state update → recomposition → render.
- Retrofit handles the API request; the converter maps JSON.
- ViewModel state carries loading, error, and data.
- The grid iterates through typed category items.
- Coil fetches each image from its URL independently of the JSON request.
