# Setting Up Our MainViewModel and Fetching Data

---

## Overview

The ViewModel connects the API/data side to the UI. It owns a screen state containing loading status, category results, and an optional error. It launches the Retrofit suspend call in `viewModelScope`, catches failures, and publishes state changes for Compose to observe.

---

## Represent the screen state

```kotlin
data class RecipeState(
    val isLoading: Boolean = true,
    val categories: List<Category> = emptyList(),
    val error: String? = null
)
```

A single state object makes the possible screen conditions explicit. `String?` means the error may be absent (`null`). Data-class `copy()` creates an updated state while retaining fields that do not change.

---

## ViewModel request flow

```kotlin
class MainViewModel(
    private val apiService: ApiService
) : ViewModel() {

    private val _categoryState = mutableStateOf(RecipeState())
    val categoryState: State<RecipeState> = _categoryState

    init {
        fetchCategories()
    }

    private fun fetchCategories() {
        viewModelScope.launch {
            try {
                val response = apiService.getCategories()
                _categoryState.value = RecipeState(
                    isLoading = false,
                    categories = response.categories,
                    error = null
                )
            } catch (e: Exception) {
                _categoryState.value = RecipeState(
                    isLoading = false,
                    error = "Error fetching categories: ${e.message}"
                )
            }
        }
    }
}
```

The lecture instantiates its service directly in the project setup; constructor injection is shown here as a clean seam for tests. Adapt the construction/factory to your app architecture. The important flow remains the same: start loading, request, then publish success or failure.

---

## Why expose `State`?

The ViewModel keeps the mutable backing state private and exposes a read-only `State`. A Compose reader subscribes to changes; assigning a new state value triggers recomposition. The UI can render loading, error, or content without owning networking logic.

---

## State transitions

| Event | Loading | Categories | Error |
| :--- | :--- | :--- | :--- |
| Initial | `true` | empty list | `null` |
| Success | `false` | response list | `null` |
| Failure | `false` | empty/default list | message |

---

## Recap / cheat sheet

- `viewModelScope.launch {}` starts lifecycle-aware coroutine work.
- The service's suspend endpoint is called inside the coroutine.
- `try`/`catch` converts failures into UI state.
- Publish a new state object to trigger Compose updates.
- Keep mutable state private; expose a read-only view where possible.
