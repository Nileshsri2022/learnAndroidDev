# JSON — What It Really Stands For

---

## Overview

**JSON** means **JavaScript Object Notation**. It began with syntax familiar from JavaScript, but it is now a language-independent text format used broadly to exchange structured data. A mobile app commonly receives JSON from a server and turns it into Kotlin objects.

---

## Where JSON fits

A server can send data to a client, and a client can send data back. In this recipe app, the phone requests category data and receives a JSON response. The data is text on the wire; after parsing, the app can read properties such as a category name or image URL.

JSON is not executable application logic. It describes values and their relationships. Kotlin classes define how the app represents and uses those values.

---

## Its two fundamental structures

| Structure | JSON notation | Common Kotlin representation |
| :--- | :--- | :--- |
| Name/value collection | Object: `{ "name": "Pasta" }` | Data class or map |
| Ordered values | Array: `["Beef", "Chicken"]` | `List<T>` or array |

Objects and arrays can be nested to represent more complex responses. Values can include strings, numbers, booleans, `null`, objects, and arrays.

---

## JSON compared with XML

XML is another structured text format and is still encountered in Android and web systems. XML uses paired tags around values, which can make documents more verbose. JSON's object-and-array notation is often compact and maps naturally to application models. Neither format makes the data meaningful by itself: documentation and a matching model are still needed.

---

## Example

```json
{
  "categories": [
    { "idCategory": "1", "strCategory": "Beef" },
    { "idCategory": "2", "strCategory": "Chicken" }
  ]
}
```

The outer object has a `categories` property. Its value is an array of objects. In Kotlin, this can become a response class containing a list of category objects.

---

## Recap / cheat sheet

- JSON = **JavaScript Object Notation**.
- It is lightweight, text-based, and language-independent in use.
- Objects group named properties; arrays hold ordered values.
- XML remains relevant, but JSON is a common format for REST APIs.
- Match the Kotlin model to the service's documented JSON shape.
