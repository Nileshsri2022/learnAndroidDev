# Implementing the Navigation and Passing Objects

---

## Overview

This lecture builds `RecipeApp`, the composable that owns the recipe app's navigation graph, connects
it to `MainActivity`, and passes an entire `Category` object from the grid to the detail screen.

The plan:

```text
MainActivity  →  RecipeApp (NavHost + NavController)
                     ├── Screen.RecipeScreen.route  → RecipeScreen
                     └── Screen.DetailScreen.route  → CategoryDetailScreen
```

The `MainActivity` stays the entry point and immediately hands control to `RecipeApp`.

---

## Step 1 — the `RecipeApp` composable

```kotlin
@Composable
fun RecipeApp(navController: NavHostController) {
    val recipeViewModel: MainViewModel = viewModel()
    val viewState by recipeViewModel.categoryState

    NavHost(
        navController = navController,
        startDestination = Screen.RecipeScreen.route
    ) {
        composable(route = Screen.RecipeScreen.route) {
            RecipeScreen(
                viewState = viewState,
                navigateToDetail = { category ->
                    navController.currentBackStackEntry
                        ?.savedStateHandle
                        ?.set("cat", category)
                    navController.navigate(Screen.DetailScreen.route)
                }
            )
        }

        composable(route = Screen.DetailScreen.route) {
            val category = navController.previousBackStackEntry
                ?.savedStateHandle
                ?.get<Category>("cat")
                ?: Category("", "", "", "")

            CategoryDetailScreen(category = category)
        }
    }
}
```

The parameter is a **`NavHostController`**, not a plain `NavController` — that is the type `NavHost`
requires.

---

## Passing an object with `SavedStateHandle`

A route can only carry text, so an object travels through the `SavedStateHandle` instead: a
key/value container attached to each back stack entry.

```text
RecipeScreen                                    DetailScreen
     │                                                ▲
     │ currentBackStackEntry                          │ previousBackStackEntry
     │   .savedStateHandle.set("cat", category)       │   .savedStateHandle.get<Category>("cat")
     ▼                                                │
 navigate(Screen.DetailScreen.route) ─────────────────┘
```

| Call | Purpose |
| :--- | :--- |
| `currentBackStackEntry` | The entry for the screen being left (the recipe screen) |
| `savedStateHandle.set("cat", category)` | Stores the object under the key `"cat"` |
| `navigate(Screen.DetailScreen.route)` | Moves to the detail destination |
| `previousBackStackEntry` | From the detail screen, the entry we came from |
| `get<Category>("cat")` | Reads the value back as a `Category` |
| `?: Category("", "", "", "")` | Fallback empty category if nothing was stored |

Every link in that chain is nullable — the entry, the handle, and the stored value — so the safe-call
`?.` and Elvis `?:` operators are essential.

> Store the object **before** navigating. Once the new destination is on top of the stack, the
> previous entry is where the value is read from.

## Step 2 — hoist the ViewModel and state

State used to be created inside `RecipeScreen`. Now `RecipeApp` creates the ViewModel and passes both
`viewState` and `navigateToDetail` down:

```kotlin
@Composable
fun RecipeScreen(
    viewState: MainViewModel.RecipeState,
    navigateToDetail: (Category) -> Unit
) {
    // loading / error / CategoryScreen(categories = viewState.categories, navigateToDetail)
}
```

Screens render state and report events; the app-level composable owns the ViewModel and the graph.
This is the same separation MVVM established earlier, applied to navigation.

---

## Step 3 — wire it into `MainActivity`

```kotlin
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            RecipeAppTheme {
                val navController = rememberNavController()
                RecipeApp(navController = navController)
            }
        }
    }
}
```

`setContent` now hosts `RecipeApp` instead of `RecipeScreen`, so the graph — not a single screen —
controls what is displayed.

## Step 4 — make `Category` transportable

An object placed in a `SavedStateHandle` must be `Parcelable`. Two changes are needed.

In the **app module** Gradle plugins block:

```kotlin
plugins {
    id("com.android.application")
    id("org.jetbrains.kotlin.android")
    id("kotlin-parcelize")        // ← added
}
```

On the data class:

```kotlin
@Parcelize
data class Category(
    val idCategory: String,
    val strCategory: String,
    val strCategoryThumb: String,
    val strCategoryDescription: String
) : Parcelable
```

Without these, storing a `Category` in the handle fails at runtime. Sync after adding the plugin.

## Result

Tapping **Beef** shows beef's title, image, and description; going back and tapping **Chicken** shows
chicken's. Long descriptions (Pork, for instance) scroll inside their own text area while the title
and image stay fixed.

---

## Recap / cheat sheet

- `RecipeApp(navController: NavHostController)` owns the graph; `MainActivity` only calls it.
- `startDestination = Screen.RecipeScreen.route` — route constants, never raw strings.
- Objects travel via `savedStateHandle.set(key, value)` and `get<T>(key)`.
- Write with `currentBackStackEntry`, read with `previousBackStackEntry`.
- Always provide a fallback for a missing value; the chain is nullable throughout.
- Complex arguments need `kotlin-parcelize` plus `@Parcelize ... : Parcelable`.
