## Theme

Give an app more than one screen — and a safe, centralized way to move between them. Day 10 builds a
minimal two-screen sample first, then adds a category detail screen to the recipe app and passes a
whole `Category` object into it.

## The navigation structure

```text
MainActivity
   │ setContent
   ▼
RecipeApp(navController = rememberNavController())
   │
   ├── NavHost(startDestination = Screen.RecipeScreen.route)
   │       │
   │       ├── composable(Screen.RecipeScreen.route)
   │       │        RecipeScreen(viewState, navigateToDetail)
   │       │             └── CategoryScreen → CategoryItem(Modifier.clickable)
   │       │                        │ navigateToDetail(category)
   │       │                        ▼
   │       │            currentBackStackEntry.savedStateHandle["cat"] = category
   │       │            navController.navigate(Screen.DetailScreen.route)
   │       │
   │       └── composable(Screen.DetailScreen.route)
   │                previousBackStackEntry.savedStateHandle.get<Category>("cat")
   │                        ▼
   │                CategoryDetailScreen(category)
   │                   title + Coil image + scrollable description
   │
   └── back stack: System Back pops the detail entry and returns to the grid
```

## Core pieces

```kotlin
// 1. Centralized, compile-time-safe routes
sealed class Screen(val route: String) {
    object RecipeScreen : Screen("recipe_screen")
    object DetailScreen : Screen("detail_screen")
}

// 2. The graph
@Composable
fun RecipeApp(navController: NavHostController) {
    val recipeViewModel: MainViewModel = viewModel()
    val viewState by recipeViewModel.categoryState

    NavHost(navController = navController, startDestination = Screen.RecipeScreen.route) {
        composable(Screen.RecipeScreen.route) {
            RecipeScreen(
                viewState = viewState,
                navigateToDetail = { category ->
                    navController.currentBackStackEntry?.savedStateHandle?.set("cat", category)
                    navController.navigate(Screen.DetailScreen.route)
                }
            )
        }
        composable(Screen.DetailScreen.route) {
            val category = navController.previousBackStackEntry
                ?.savedStateHandle?.get<Category>("cat")
                ?: Category("", "", "", "")
            CategoryDetailScreen(category = category)
        }
    }
}

// 3. An object that can travel
@Parcelize
data class Category(
    val idCategory: String,
    val strCategory: String,
    val strCategoryThumb: String,
    val strCategoryDescription: String
) : Parcelable
```

The app module also needs the navigation dependency and the parcelize plugin:

```kotlin
plugins {
    id("com.android.application")
    id("org.jetbrains.kotlin.android")
    id("kotlin-parcelize")
}

dependencies {
    implementation("androidx.navigation:navigation-compose:2.7.4")
}
```

## Passing data: two mechanisms

| Kind of data | Mechanism | Example |
| :--- | :--- | :--- |
| Simple value | Route argument | `navigate("second_screen/$name")` → `arguments?.getString("name") ?: "no name"` |
| Complex object | `SavedStateHandle` | `set("cat", category)` → `get<Category>("cat")` |

Simple values can be written into a route because a route is text. An object cannot, so it is stored
in the handle attached to a back stack entry — and it must be `Parcelable` to be accepted.

---

## Reading and writing the handle

| Call | Timing |
| :--- | :--- |
| `currentBackStackEntry?.savedStateHandle?.set(key, value)` | On the screen being left, **before** `navigate()` |
| `previousBackStackEntry?.savedStateHandle?.get<T>(key)` | On the destination, **after** arriving |
| `?: Category("", "", "", "")` | Fallback when nothing was stored |

Every step in both chains is nullable, so safe calls and a default value are mandatory.

---

## Important distinctions

- **Route vs composable:** the `startDestination` is a route *string*; the host resolves it to the
  matching `composable` block. A `composable` without its trailing content lambda crashes.
- **Hoisting vs navigating:** a screen calls a lambda it was given; only the graph calls `navigate()`.
- **`NavController` vs `NavHostController`:** `NavHost` requires the `NavHostController` type.
- **Sealed class vs string constants:** sealed subclasses are checked at compile time, so a typo
  fails in the editor rather than at runtime.
- **Parcelable vs JSON:** Parcelable moves objects inside the app; JSON exchanges data with servers.
- **Screen-scoped scrolling:** `Modifier.verticalScroll(rememberScrollState())` on one `Text` scrolls
  that text only, leaving the title and image fixed.

---

## Recap / cheat sheet

- **Graph:** `rememberNavController()` → `NavHost(startDestination)` → `composable(route) { … }`.
- **Move:** `navController.navigate(Screen.DetailScreen.route)`.
- **Hoist:** screens take `() -> Unit` / `(Category) -> Unit`; previews pass `{}` or sample values.
- **Tap:** `Modifier.clickable { }` anywhere in a `Modifier` chain.
- **Routes:** define once in `sealed class Screen(val route: String)` with `object` destinations.
- **Objects:** `savedStateHandle` + `@Parcelize` + the `kotlin-parcelize` plugin.
- **Null safety:** the handle, the entry, and the value can all be `null` — always supply a default.
