# Preparing our UI for Navigation

---

## Overview

The detail screen exists but nothing can reach it yet. The recipe app needs the same ingredients as
the sample app — a `NavHost`, a `NavController`, and a start destination (`RecipeScreen`) — plus a
way to hand a `Category` from the tapped tile to the detail screen.

The lecture starts with the UI: making a category tile clickable and passing that click upward until
something is responsible for acting on it.

---

## Step 1 — make the tile clickable

```kotlin
@Composable
fun CategoryItem(
    category: Category,
    navigateToDetail: (Category) -> Unit
) {
    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(8.dp)
            .clickable { navigateToDetail(category) },
        horizontalAlignment = Alignment.CenterHorizontally
    ) {
        AsyncImage(
            model = category.strCategoryThumb,
            contentDescription = "${category.strCategory} category",
            modifier = Modifier
                .fillMaxWidth()
                .aspectRatio(1f),
            contentScale = ContentScale.Crop
        )
        Text(
            text = category.strCategory,
            fontWeight = FontWeight.Bold,
            modifier = Modifier.padding(top = 8.dp)
        )
    }
}
```

`Modifier.clickable { }` turns any composable into a click target. It is chained **inside**
`fillMaxSize()`, in the same `Modifier` chain that already describes the tile.

---

## Step 2 — hoist the callback level by level

The tile does not know how to navigate, so it receives a `(Category) -> Unit` callback and calls it.
Each parent that renders the tile then demands the same callback from *its* caller, until the code
reaches the place that owns navigation.

```text
CategoryItem      – calls navigateToDetail(category)
      ▲ receives it from
CategoryScreen    – passes it down to every item
      ▲ receives it from
RecipeScreen      – passes it down to the grid
      ▲ receives it from
RecipeApp / graph – implements it with navController.navigate(...)
```

```kotlin
@Composable
fun CategoryScreen(
    categories: List<Category>,
    navigateToDetail: (Category) -> Unit
) {
    LazyVerticalGrid(columns = GridCells.Fixed(2), modifier = Modifier.fillMaxSize()) {
        items(categories) { category ->
            CategoryItem(category = category, navigateToDetail = navigateToDetail)
        }
    }
}

@Composable
fun RecipeScreen(
    viewState: MainViewModel.RecipeState,
    navigateToDetail: (Category) -> Unit
) {
    Box(modifier = Modifier.fillMaxSize()) {
        when {
            viewState.isLoading -> CircularProgressIndicator(modifier = Modifier.align(Alignment.Center))
            viewState.error != null -> Text(text = viewState.error, modifier = Modifier.align(Alignment.Center))
            else -> CategoryScreen(categories = viewState.categories, navigateToDetail = navigateToDetail)
        }
    }
}
```

> "The UI does not take care of the implementation of that logic. It just gives the responsibility
> to the higher ups."

---

## Why hoist instead of navigating inside the tile?

| Navigating inside `CategoryItem` | Hoisting a callback |
| :--- | :--- |
| Requires a `NavController` inside the tile | Tile stays a pure function of its inputs |
| Breaks previews (no controller available) | Previews pass `{}` or a no-op lambda |
| Hard to reuse the tile elsewhere | Tile can be reused in any graph or layout |
| Navigation scattered across the UI | All navigation decisions live in one graph |

---

## The temporary compile error

After these edits, `MainActivity` fails to compile: it still calls `RecipeScreen` without supplying
`navigateToDetail`. That error is expected — it is the compiler pointing at the exact spot where the
navigation graph has to be implemented. The lecture comments out the `RecipeScreen` call and moves
on to setting up the graph.

---

## Recap / cheat sheet

- `Modifier.clickable { }` makes any composable interactive.
- A tile that is tapped reports **what** happened, not **how** to handle it.
- Pass callbacks down (`navigateToDetail: (Category) -> Unit`) until one place owns the behaviour.
- Compile errors after adding a parameter mark every call site that still needs updating.
- Screens that only forward callbacks stay previewable and reusable.
