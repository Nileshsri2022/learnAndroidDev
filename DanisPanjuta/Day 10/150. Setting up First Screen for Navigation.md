# Setting up First Screen for Navigation

---

## Overview

Navigation is introduced with a fresh project, **NavigationSample**, created from the *Empty
Activity* template. The lecture uses a story to frame the concept:

> The Grand Bookstore has towering shelves and endless corridors, with sign boards for each genre —
> science fiction, mystery, biography. Navigating that bookstore is like navigating a Compose app:
> every aisle you choose to explore is a destination, and you decide which one to visit next.

Each genre aisle maps to a screen; choosing an aisle maps to navigating to that screen.

---

## Clean up the template

Delete the generated `Greeting` composable, its `GreetingPreview`, and the `Greeting` call, so the
project starts empty. Then create the first screen.

## The first screen

The screen asks for a name and offers a button that will eventually take the user to the next
screen.

```kotlin
@Composable
fun FirstScreen() {
    var name by remember { mutableStateOf("") }

    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(16.dp),
        verticalArrangement = Arrangement.Center,
        horizontalAlignment = Alignment.CenterHorizontally
    ) {
        Text(
            text = "This is the first screen",
            fontSize = 24.sp
        )

        Spacer(modifier = Modifier.height(16.dp))

        OutlinedTextField(
            value = name,
            onValueChange = { name = it },
            label = { Text("Name") }
        )

        Spacer(modifier = Modifier.height(16.dp))

        Button(
            onClick = {
                // Navigation goes here — filled in once NavHost exists.
            }
        ) {
            Text("Go to next screen")
        }
    }
}
```

| Element | Role |
| :--- | :--- |
| `var name by remember { mutableStateOf("") }` | Holds the typed name across recompositions |
| `Text` | Labels the screen so it is obvious which destination is visible |
| `Spacer` | Creates breathing room between elements |
| `OutlinedTextField` | Captures the name the user types |
| `Button` | Triggers the transition to the second screen |

> The lecture pastes in the familiar `Column`, `padding`, and `arrangement` boilerplate rather than
> re-typing it, since those basics have already been covered many times. The new concept is
> navigation, not layout.

## Preview

```kotlin
@Preview(showBackground = true)
@Composable
fun FirstPreview() {
    NavigationSampleTheme {
        FirstScreen()
    }
}
```

`showBackground = true` gives the preview a white background, which makes the composable easier to
see in split view. Use *Build & Refresh* if the preview does not render right away.

---

## Why ask for a name at all?

The name exists so the next lectures can demonstrate **passing data** between screens. Two screens
that do nothing but swap places would not show how arguments work; a typed value makes the data flow
visible and testable.

---

## Recap / cheat sheet

- Create a dedicated project when learning an isolated concept; keep the recipe app for later.
- `OutlinedTextField` needs a `value` and an `onValueChange` that writes back to state.
- The button's `onClick` is where navigation will eventually be triggered.
- Previews need an empty lambda (`{}`) for any navigation callback that has not been implemented yet.
