# Setting up the Routes with a Sealed Class

---

## Overview

Before the graph can be written, the recipe app needs its navigation dependency and a safe way to
refer to destinations. Typing route strings by hand invites typos that only surface at runtime, so
the lecture collects them in a `sealed class Screen`.

---

## Step 1 — add the navigation dependency

In the **app module** Gradle file:

```kotlin
dependencies {
    implementation("androidx.navigation:navigation-compose:2.7.4")
}
```

Sync Gradle before continuing. Using the course version keeps behaviour consistent with the videos,
because Navigation releases can change APIs.

---

## Step 2 — create `Screen.kt`

```kotlin
sealed class Screen(val route: String) {
    object RecipeScreen : Screen("recipe_screen")
    object DetailScreen : Screen("detail_screen")
}
```

| Part | Meaning |
| :--- | :--- |
| `sealed class` | A class whose subclasses are known at compile time |
| `val route: String` | Every destination carries its route string |
| `object RecipeScreen` | A singleton destination — only one instance is ever needed |
| `Screen("recipe_screen")` | The route value used by `NavHost` and `navigate()` |

Usage is then type-checked:

```kotlin
Screen.RecipeScreen.route   // "recipe_screen"
Screen.DetailScreen.route   // "detail_screen"
```

---

## Why sealed classes rather than plain strings?

> A sealed class is used when it is known in advance that a type will conform to one of the
> subclass types. Sealed classes ensure type safety by restricting types to be matched at compile
> time rather than at runtime.

| Approach | Failure mode |
| :--- | :--- |
| `navController.navigate("recipee_screen")` | Typo compiles fine, crashes or silently fails at runtime |
| `navController.navigate(Screen.RecipeScreen.route)` | Typo is a compile error in the IDE |
| `const val RECIPE = "recipe_screen"` | Safe, but constants are scattered and not grouped |

Because the compiler knows the complete set of subclasses, mistakes surface in Android Studio
instead of after launching the app. It also gives every screen one obvious home, which pays off as
the app grows:

```kotlin
sealed class Screen(val route: String) {
    object RecipeScreen : Screen("recipe_screen")
    object DetailScreen : Screen("detail_screen")
    // object FavouritesScreen : Screen("favourites_screen")   ← added later in one place
}
```

---

## Objects, not classes

Each destination is an `object` rather than a `class` because a route is a constant: it never holds
per-instance data, and there is no reason to create more than one of them. Kotlin creates the single
instance lazily on first access.

---

## Recap / cheat sheet

- Add `androidx.navigation:navigation-compose` to the app module and sync.
- `sealed class Screen(val route: String)` centralizes every destination in the app.
- `object X : Screen("route")` gives a compile-time-safe, singleton reference to a route.
- Refer to destinations as `Screen.DetailScreen.route`, never as a hand-typed string.
- Sealed classes restrict a type to a known set of subclasses, checked at compile time.
