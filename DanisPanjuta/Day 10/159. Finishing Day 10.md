# Finishing Day 10

## Overview

Day 10 covered fewer concepts than Day 9, but they were dense and universally useful: every app with
more than one screen needs what was built today.

---

## What you practiced

- Creating a two-screen sample project and keeping each screen in its own file.
- Adding `androidx.navigation:navigation-compose` and syncing Gradle before writing navigation code.
- Building a graph with `NavHost`, a `rememberNavController()`, and a `startDestination`.
- Navigating with `navController.navigate(route)` from inside a graph's `composable` block.
- Hoisting `() -> Unit` and `(Category) -> Unit` callbacks so screens stay independent of navigation.
- Passing a simple value through a route argument (`second_screen/{name}`).
- Making a category tile clickable with `Modifier.clickable`.
- Centralizing destination strings in a `sealed class Screen` with `object` members.
- Passing an entire object between screens via `currentBackStackEntry.savedStateHandle` and
  `previousBackStackEntry.savedStateHandle`.
- Enabling `kotlin-parcelize` and marking `Category` `@Parcelize` so it can be serialized.

## The navigation toolkit

| Need | Tool |
| :--- | :--- |
| A controller that owns the back stack | `rememberNavController()` |
| A container for destinations | `NavHost(navController, startDestination)` |
| A destination | `composable(route) { ... }` (content lambda required) |
| A safe route reference | `sealed class Screen(val route: String)` + `object`s |
| Moving to another screen | `navController.navigate(Screen.X.route)` |
| Passing a simple value | Route argument `"detail/{name}"` + `arguments?.getString("name")` |
| Passing an object | `savedStateHandle.set("key", obj)` / `get<T>("key")` |
| Making an object passable | `@Parcelize` + `kotlin-parcelize` plugin |
| Making a UI element tappable | `Modifier.clickable { }` |

## Why it felt harder than XML

The lecture notes that hopping between screens with intents in the old XML world was simpler for the
basic case — but it became painful once fragments and complex flows entered the picture. Compose
navigation asks for more setup upfront and repays it with a single, typed, centralized graph.

## Recap / cheat sheet

- Screens report events; the graph performs navigation.
- Routes are the contract between `NavHost` and `navigate()` — define them once.
- The back stack is what makes the system back button behave predictably.
- Simple values belong in route arguments; objects belong in the `SavedStateHandle`.
- `Parcelable` is the serialization contract for objects that travel inside an app.
