# NavHost NavController and Navigating

---

## Overview

With two screens in place, the app can finally be wired for navigation. Three pieces are needed:

| Piece | Responsibility |
| :--- | :--- |
| **NavController** | The central, stateful API of the Navigation component; owns the back stack |
| **NavHost** | The container that links routes to composable destinations |
| **Route** | A string that identifies a destination from anywhere in the app |

---

## Step 1 — add the dependency

In the **app module** `build.gradle` / `build.gradle.kts`:

```kotlin
dependencies {
    // Version used throughout this day of the course
    implementation("androidx.navigation:navigation-compose:2.7.4")
}
```

Sync Gradle afterwards and wait for it to finish. Editing code mid-sync is a common source of odd
build errors, and the navigation imports will not resolve until the sync completes.

> Pin the version used in the course rather than whatever the documentation currently shows.
> Navigation releases change APIs, and a newer version can break the code built here.

---

## Step 2 — create the graph

```kotlin
@Composable
fun MyApp() {
    val navController = rememberNavController()

    NavHost(
        navController = navController,
        startDestination = "first_screen"
    ) {
        composable(route = "first_screen") {
            FirstScreen {
                navController.navigate("second_screen")
            }
        }
        composable(route = "second_screen") {
            SecondScreen {
                navController.navigate("first_screen")
            }
        }
    }
}
```

```kotlin
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            NavigationSampleTheme {
                Surface(
                    modifier = Modifier.fillMaxSize(),
                    color = MaterialTheme.colorScheme.background
                ) {
                    MyApp()
                }
            }
        }
    }
}
```

Key details from the lecture:

- `rememberNavController()` is stateful — the controller survives recomposition and configuration
  changes.
- The `startDestination` is a **route string**, not a composable. The host resolves it by finding the
  `composable` block that declares the same route.
- The trailing `{ ... }` block after each `composable(...)` is required. A `composable` without its
  content lambda crashes the app.
- `composable(route = "...")` and `composable("...")` are equivalent: with a single argument, it is
  understood to be the route.

## Step 3 — let the screens ask for navigation

Navigation is **hoisted**: a screen receives a lambda and calls it, while the graph decides what the
lambda does.

```kotlin
@Composable
fun FirstScreen(navigateToSecondScreen: () -> Unit) {
    // ...
    Button(onClick = { navigateToSecondScreen() }) {
        Text("Go to next screen")
    }
}
```

`() -> Unit` means "pass me some code that takes no input and returns nothing" — exactly what a
button click handler needs. `SecondScreen` gets `navigateToFirstScreen: () -> Unit` in the same way.

Previews must now supply something for that parameter, so pass an empty lambda:

```kotlin
@Preview(showBackground = true)
@Composable
fun FirstPreview() {
    NavigationSampleTheme {
        FirstScreen(navigateToSecondScreen = {})   // do nothing in the preview
    }
}
```

## The back stack

> The back stack records the screens you visited and the order in which you visited them.

```text
Screen 1  →  Screen 2  →  Screen 3
                  ▲
                  └── pressing Back pops Screen 3 and returns here
```

Without a back stack, pressing Back could send the user somewhere unexpected. The `NavController`
keeps that history, along with the state of each destination, so the system back button behaves the
way users expect.

---

## Common pitfalls

| Symptom | Cause |
| :--- | :--- |
| Navigation imports unresolved | Gradle sync not finished, or dependency in the wrong module |
| Crash on launch | A `composable(...)` block is missing its trailing content lambda |
| Start destination not found | `startDestination` string does not match any declared route |
| Button does nothing | The screen never calls the navigation lambda it was given |

---

## Recap / cheat sheet

- `rememberNavController()` → the stateful controller that owns the back stack.
- `NavHost(navController, startDestination) { ... }` → the graph of destinations.
- `composable(route) { Screen { navController.navigate("other_route") } }` → one destination.
- Routes are plain strings; keep them consistent between the host and every `navigate()` call.
- Screens take `() -> Unit` callbacks; previews pass `{}`.
