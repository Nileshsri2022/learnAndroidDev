# Serialization and Deserialization with Parcelable

---

## Overview

The last lecture stored a whole `Category` in a `SavedStateHandle`. This one explains why that
worked — and why it would have failed without `Parcelable`. The lecture frames it with a story:

> In the Kingdom of Data, messages travelled between towns inside magical orbs called *pass-ables*.
> Anything could be placed in an orb, but first it had to be transformed into a form suitable for
> the journey — **serialization**. On arrival the contents were restored to their original form —
> **deserialization**. The magic guaranteed the contents arrived unchanged, however long the journey.

---

## The two halves

| Term | What it does | In the recipe app |
| :--- | :--- | :--- |
| **Serialization** | Converts an object into a transmittable/storable form | A `Category` is flattened so it can be placed in the `SavedStateHandle` |
| **Deserialization** | Rebuilds the original object from that form | `get<Category>("cat")` restores a real `Category` |

```text
Category(id, name, thumbUrl, description)
        │  serialization
        ▼
   flat, transportable form   ───── journey between destinations ─────►
                                                                       │
Category(id, name, thumbUrl, description)  ◄─── deserialization ───────┘
```

A `Category` is not a single string — it carries an ID, a name, an image URL, and a description.
Serialization packs all of those fields into one transportable value; deserialization unpacks them
into an equivalent object.

---

## Making `Category` parcelable

Two steps, both already applied in the previous lecture.

**1. Enable the plugin** (app module Gradle):

```kotlin
plugins {
    id("com.android.application")
    id("org.jetbrains.kotlin.android")
    id("kotlin-parcelize")
}
```

**2. Annotate the data class**:

```kotlin
import kotlinx.parcelize.Parcelize
import android.os.Parcelable

@Parcelize
data class Category(
    val idCategory: String,
    val strCategory: String,
    val strCategoryThumb: String,
    val strCategoryDescription: String
) : Parcelable
```

`@Parcelize` generates the `writeToParcel` / `createFromParcel` plumbing automatically. Writing that
code by hand for every model would be tedious and easy to get wrong — the plugin removes that work
entirely.

---

## Why the `SavedStateHandle` needs it

The handle stores key/value pairs. Simple values are fine as they are, but a **class type** must be
parcelable, because the entry may need to survive process death and be restored later. Without
`@Parcelize`, storing a `Category` fails at runtime.

```kotlin
navController.currentBackStackEntry?.savedStateHandle?.set("cat", category)   // needs Parcelable
val category = navController.previousBackStackEntry?.savedStateHandle?.get<Category>("cat")
```

---

## Parcelable vs JSON

Both flatten objects, but they serve different jobs:

| | Parcelable | JSON |
| :--- | :--- | :--- |
| Purpose | Move objects around inside an Android app | Exchange data with a server or storage |
| Readable by humans | No — a compact binary-ish form | Yes — plain text |
| Generated in this course | `@Parcelize` plugin | Retrofit + JSON converter |
| Typical use | Navigation arguments, saved state | API responses |

The lecture calls them "super similar, but slightly different": the destination is different, so the
format is too.

---

## Recap / cheat sheet

- **Serialization:** object → transportable form. **Deserialization:** form → object.
- Complex objects cannot ride in a route string; they need `Parcelable`.
- Add `id("kotlin-parcelize")` to the app module plugins, then `@Parcelize … : Parcelable`.
- `SavedStateHandle` requires class-type values to be parcelable.
- Simple types (String, Int, Boolean) can go straight into a route as an argument.
- JSON is for talking to the outside world; Parcelable is for moving data inside the app.
