# Setting up The Second Screen for Navigation

---

## Overview

A navigation demo needs somewhere to go. This lecture moves `FirstScreen` into its own file and
creates a matching `SecondScreen`, so there are two destinations to move between.

---

## One composable per file

The generated `MainActivity.kt` is not a good home for every screen. The lecture extracts the
screen:

1. Create a new Kotlin file `FirstScreen.kt`.
2. Move the entire `FirstScreen` composable **and** its preview into it.
3. Let Android Studio regenerate the imports automatically.

The same is then done for `SecondScreen.kt`. Keeping screens in separate files makes a growing
navigation graph far easier to navigate.

---

## The second screen

`SecondScreen` mirrors `FirstScreen` with a few changes: no text field, a larger welcome text, and a
button that returns to the first screen.

```kotlin
@Composable
fun SecondScreen() {
    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(16.dp),
        verticalArrangement = Arrangement.Center,
        horizontalAlignment = Alignment.CenterHorizontally
    ) {
        Text(
            text = "This is the second screen",
            fontSize = 24.sp
        )

        Spacer(modifier = Modifier.height(16.dp))

        Text(
            text = "Welcome",
            fontSize = 24.sp
        )

        Spacer(modifier = Modifier.height(16.dp))

        Button(
            onClick = {
                // Navigation back to the first screen goes here.
            }
        ) {
            Text("Go to first screen")
        }
    }
}
```

```kotlin
@Preview(showBackground = true)
@Composable
fun SecondPreview() {
    NavigationSampleTheme {
        SecondScreen()
    }
}
```

---

## Differences between the two screens

| Element | FirstScreen | SecondScreen |
| :--- | :--- | :--- |
| Title | "This is the first screen" | "This is the second screen" |
| Input | `OutlinedTextField` for the name | none |
| Extra text | none | "Welcome" at 24.sp |
| Button label | "Go to next screen" | "Go to first screen" |

The lecture copies the first screen and edits it, because the structure is deliberately similar —
the point is the transition, not the layout. Unused imports are removed afterwards to keep the file
tidy.

---

## Recap / cheat sheet

- Extract each destination into its own Kotlin file (`FirstScreen.kt`, `SecondScreen.kt`).
- Move the preview with the composable so previews stay next to the code they show.
- Two symmetric screens make it obvious whether navigation works in both directions.
- Unused imports are harmless but noisy — remove them as you go.
