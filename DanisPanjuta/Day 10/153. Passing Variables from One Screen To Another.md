# Passing Variables from One Screen To Another

---

## Overview

Moving between screens is only half the story; screens usually need data. This lecture passes the
name typed on `FirstScreen` to `SecondScreen`, where it is shown in the welcome message.

The mechanism is a **route argument**: the value is appended to the route string, and the destination
reads it back out of its back stack entry.

---

## Step 1 — the destination declares it accepts an argument

```kotlin
NavHost(
    navController = navController,
    startDestination = "first_screen"
) {
    composable(route = "first_screen") {
        FirstScreen { name ->
            navController.navigate("second_screen/$name")
        }
    }

    composable(route = "second_screen/{name}") { backStackEntry ->
        val name = backStackEntry.arguments?.getString("name") ?: "no name"
        SecondScreen(
            name = name,
            navigateToFirstScreen = {
                navController.navigate("first_screen")
            }
        )
    }
}
```

- `second_screen/{name}` — the `{name}` placeholder marks a variable part of the route.
- `backStackEntry.arguments` is a `Bundle?`; it can be `null`, hence the safe call.
- `getString("name")` reads the value stored under the key that matches the placeholder name.
- The Elvis operator `?: "no name"` supplies a default when nothing was typed.

---

## Step 2 — the screens carry the value

```kotlin
@Composable
fun FirstScreen(navigateToSecondScreen: (String) -> Unit) {
    var name by remember { mutableStateOf("") }

    // ...
    Button(onClick = { navigateToSecondScreen(name) }) {
        Text("Go to next screen")
    }
}

@Composable
fun SecondScreen(
    name: String,
    navigateToFirstScreen: () -> Unit
) {
    // ...
    Text(text = "Welcome $name", fontSize = 24.sp)

    Button(onClick = { navigateToFirstScreen() }) {
        Text("Go to first screen")
    }
}
```

The callback type changed from `() -> Unit` to `(String) -> Unit`: navigating to the second screen
now requires a string. The preview passes a sample value:

```kotlin
@Preview(showBackground = true)
@Composable
fun SecondPreview() {
    NavigationSampleTheme {
        SecondScreen(name = "Danis", navigateToFirstScreen = {})
    }
}
```

> Enter nothing in the text field and tap the button: the second screen shows "Welcome no name" —
> the default defined in the graph.

## Tracing the flow

| Step | What happens |
| :--- | :--- |
| 1 | The user types a name; `name` state in `FirstScreen` updates |
| 2 | The button calls `navigateToSecondScreen(name)` |
| 3 | The lambda in the graph runs `navController.navigate("second_screen/$name")` |
| 4 | Navigation matches the route `second_screen/{name}` |
| 5 | The value after the slash is bound to the argument key `name` |
| 6 | The graph reads `arguments?.getString("name")` and passes it to `SecondScreen` |

---

## What can be passed this way?

Strings, numbers, and booleans work naturally, because they can be written into a route string. A
full object cannot — it has no meaningful text form. That limitation is exactly why the recipe app
later uses `SavedStateHandle` and `Parcelable` instead.

---

## watch-outs

- Empty input still produces a valid route, so always handle the "no value" case with a default.
- Values inside a URL-like route should be simple and short; a route is not a database.
- Reserved characters in a value can corrupt the parsed route — encode values that may contain
  slashes or spaces.
- Typing the placeholder name in one place and the lookup key in another is error-prone; the sealed
  class in the recipe app reduces that risk.

---

## Recap / cheat sheet

- Declare the argument in the route: `"detail/{name}"`.
- Navigate with the value appended: `navController.navigate("detail/$name")`.
- Read it from the destination: `backStackEntry.arguments?.getString("name") ?: "no name"`.
- Callback types must match: `(String) -> Unit` on the way out, a plain parameter on the way in.
- Previews pass literal sample values.
- Simple types travel in routes; complex objects need `SavedStateHandle` + `Parcelable`.
