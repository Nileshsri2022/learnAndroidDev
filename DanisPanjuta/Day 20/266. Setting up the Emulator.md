## 📝 Summary

This lecture covers creating and configuring an **Android Virtual Device (AVD)**—a software emulator that mimics real Android mobile hardware directly on your development computer. Setting up an emulator enables rapid build-and-test cycles without needing physical cables or phones.

Denis demonstrates how to select appropriate hardware profiles (Pixel 4 with Google Play Store support), choose the correct system image based on host CPU architecture (x86_64 vs. ARM64), fine-tune advanced settings (CPU cores, RAM allocation, Quick Boot, and storage), and leverage the emulator's **Extended Controls** panel to simulate real-world conditions like mock GPS locations, variable battery levels, and throttled network speeds.

## 📒 Detailed Notes

### 1. Opening the Device Manager
You can launch the AVD Device Manager in three ways in Android Studio:
1. Click the **Device Manager** icon on the top-right toolbar.
2. Select **Tools → Device Manager** from the main menu.
3. Open the device target dropdown on the run bar and select **Device Manager**.

### 2. Selecting Device Hardware
- Look for the **Google Play Store icon** next to the device name.
- Devices with this icon (like the Pixel 4) come with genuine Google Play services pre-installed, allowing you to test authentication, Google Maps, and in-app updates seamlessly.

### 3. Choosing System Images (Critical Performance Rule)
- **Host CPU Compatibility:**
  - On **Intel or AMD PCs (Windows / Linux / Intel Mac):** Select **x86_64** or **x86** images.
  - On **Apple Silicon Macs (M1/M2/M3/M4):** Select **ARM64 (arm64-v8a)** images.
- Running an x86 image on an ARM machine (or vice versa) requires software emulation which makes the emulator virtually unusable. Matching the architecture leverages host hardware acceleration (Intel HAXM / Hyper-V / KVM / Apple Hypervisor).

### 4. Advanced Settings Customization
Click **Show Advanced Settings** to configure:
- **Camera:** Set front/back cameras to *Emulated* or route them directly to your PC webcam.
- **Network Speed:** Simulate edge conditions (LTE, HSDPA, UMTS, 3G, GPRS) with latency to test how your app behaves on slow connections.
- **Performance & Memory:**
  - Allocate 2–4 CPU cores.
  - Allocate 1536 MB to 2048 MB of RAM.
  - VM heap size: 256 MB – 512 MB.
  - Internal storage: 800 MB (expands automatically as apps are installed).

### 5. Managing AVDs & Resource Caution
- Each virtual device takes ~500 MB on creation, but expands to **3 GB – 8 GB** once booted.
- **Rule of thumb:** Run only **one AVD at a time**. Running multiple emulators simultaneously consumes immense RAM and CPU cycles, degrading compilation performance.
- If an emulator acts erratically or crashes, click the dropdown menu next to it in Device Manager and select **Wipe Data** or **Cold Boot Now**.

Click the **three dots (`...`)** on the emulator sidebar to open **Extended Controls**:

| Tab | Capabilities | Practical Testing Use Case |

| 📸 **Camera** | Configure simulated scenes or host webcam passthrough. | Test barcode scanners, profile photo pickers, and camera capture. |
| 🔄 **Orientation** | Rotate portrait / landscape or simulate phone tilting. | Test configuration changes, state retention, and responsive UI layouts. |

## 📌 Important Terms

| Term | Definition |
| :--- | :--- |
| **AVD** | Android Virtual Device — an emulator configuration defining hardware, OS, and system image. |
| **System Image** | The compiled Android operating system image that the emulator boots into. |
| **ABI** | Application Binary Interface — specifies machine code architecture (e.g., x86_64, arm64). |
| **Quick Boot** | An emulator state snapshot feature that enables near-instantaneous startup. |
| **Wipe Data** | Resets the virtual device back to its factory default state, deleting all installed apps and cache. |

## ❓ Q&A

**Q: Can I install APKs from outside the project on the emulator?**  
A: Yes! You can simply drag and drop any `.apk` file from your desktop directly onto the emulator window to install and run it.

**Q: Why does my emulator show a warning about antivirus software?**  
A: Some real-time antivirus scanners inspect every file access by the emulator disk image, which can slow down build and run performance. Adding your Android SDK and project folders to the antivirus exclusion list resolves this slowdown.

## ✅ Key Takeaways

1. 💻 **PC-based testing:** AVD provides a full-featured Android phone on your screen, complete with Google Play services.
2. ⚡ **Architecture matters:** Match system image ABI to your PC's CPU (x86_64 for Intel/AMD, ARM64 for Apple Silicon) for maximum speed.
3. 🏎️ **Quick Boot is standard:** Saves time by restoring memory snapshots in seconds.
4. 🎛️ **Simulate the real world:** Use Extended Controls to test mock GPS coordinates, dead batteries, and slow networks effortlessly.
