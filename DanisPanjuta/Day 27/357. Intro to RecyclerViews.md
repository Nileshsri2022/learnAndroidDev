# Intro to RecyclerViews

---

## Overview

Theory lecture on **RecyclerView** — used in almost every app for lists and grids — and why it replaced **ListView** and **GridView**.

---

## Why "recycler"?

A list of 1000 items doesn't create 1000 views. Only the views **visible on screen** (plus a few) are created; when one scrolls off-screen it is **recycled** — re-bound with the data of the item scrolling in.

```
┌──────────┐
│ Item 1   │ ← scrolls away → recycled
│ Item 2   │
│ Item 3   │   visible window
│ Item 4   │
└──────────┘
  Item 5     ← reuses Item 1's ViewHolder
```

→ Low memory, smooth scrolling.

---

## The building blocks

| Component | Role |
| :--- | :--- |
| **RecyclerView** | The scrolling container in XML |
| **LayoutManager** | Positions items: `LinearLayoutManager` (vertical/horizontal), `GridLayoutManager`, `StaggeredGridLayoutManager` |
| **Adapter** | Bridges data ↔ views; creates ViewHolders and binds data |
| **ViewHolder** | Holds references to one item's views (no repeated `findViewById`) |
| **Item layout** | XML for a single row |

---

## Adapter's three methods

```kotlin
override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): ViewHolder  // inflate row
override fun onBindViewHolder(holder: ViewHolder, position: Int)                // fill with data
override fun getItemCount(): Int                                                 // list size
```

---

## Advantages over ListView

- Enforced **ViewHolder pattern**.
- Pluggable layout managers (list, grid, staggered).
- Built-in item **animations**, `ItemDecoration`, `ItemTouchHelper` (swipe/drag).
- Fine-grained updates: `notifyItemInserted`, `notifyItemChanged`…

---

## Recap / cheat sheet

- **RecyclerView = container + LayoutManager + Adapter + ViewHolder.**
- Views are recycled, not recreated.
