# Looking at Lambdas once again

---

## Overview

A deeper look at **lambdas**, needed for the Room demo (adapter listeners, Flow collectors). Lambdas are concise **functions without a name**, and can be **passed as parameters** to other functions or classes.

---

## Declaring lambdas

```kotlin
// variableName: (ParamTypes) -> ReturnType = { params -> body }
val sum: (Int) -> Unit = { result -> println(result) }

val add: (Int, Int) -> Int = { a, b -> a + b }

val greet = { name: String -> "Hello $name" }   // type inferred
```

`Unit` = returns nothing (like `void` in Java).

---

## Lambda as a constructor parameter

```kotlin
class Arithmetic(val isEven: (Int) -> Boolean) {
    init {
        println(isEven(4))
    }
}

val a = Arithmetic { number -> number % 2 == 0 }   // true
```

---

## Lambda as a function parameter (higher-order function)

```kotlin
fun calculate(a: Int, b: Int, operation: (Int, Int) -> Int): Int {
    return operation(a, b)
}

calculate(4, 5) { x, y -> x * y }   // 20
```

---

## `it` and ignoring parameters

```kotlin
val square: (Int) -> Int = { it * it }
list.forEachIndexed { _, value -> println(value) }   // _ = unused
```

---

## Where it's used next

```kotlin
class ItemAdapter(
    private val items: ArrayList<EmployeeEntity>,
    private val updateListener: (id: Int) -> Unit,
    private val deleteListener: (id: Int) -> Unit
)

ItemAdapter(list,
    { updateId -> updateRecordDialog(updateId, dao) },
    { deleteId -> deleteRecordAlertDialog(deleteId, dao) })
```

The adapter doesn't need to know *what* happens on click — the activity passes that behaviour in.

---

## Recap / cheat sheet

- Type: `(A, B) -> R`.
- Pass functions into classes/functions; call like `listener(id)`.
- `it` for a single parameter, `_` to ignore.
