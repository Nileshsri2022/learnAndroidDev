Here is a clear, structured breakdown of the lecture on **`if` / `else` statements** — the
first real control flow in the course, and the mechanism that decides who wins the game.

---

### **1. The General Shape**

```kotlin
if (condition) {
    // runs when the condition is TRUE
} else {
    // runs when the condition is FALSE
}
```

A condition always evaluates to a **`Boolean`** — `true` or `false`. That is why the
Booleans lecture came first.

---

### **2. Comparison Operators**

| Operator | Meaning | Includes the boundary? |
| :--- | :--- | :--- |
| **`>`** | greater than | No |
| **`<`** | less than | No |
| **`>=`** | greater **or equal** | ✅ Yes |
| **`<=`** | less **or equal** | ✅ Yes |
| **`==`** | equal | — |

You can compare **variable to variable** or **variable to literal**. Either way the result
is a boolean.

> ⚠️ **`==` compares, `=` assigns.** Confusing them is one of the most common beginner
> mistakes.

---

### **3. Worked Example: The Club Bouncer**

> *"A bouncer checks: is this person 18 or older?"*

```kotlin
var age = 35

if (age >= 18) {
    println("You can go into the club")
} else {
    println("You are too young to go into the club")
}
```

Output:

```text
You can go into the club
```

---

### **4. Why the IDE Says "Condition Is Always True"**

Android Studio underlines the condition with the warning that it is **always true**. That is
not a bug — it is correct:

* `age` is **hardcoded** to `35`
* `35 >= 18` can therefore never be false
* So the `else` branch is **dead code**

The warning disappears as soon as the value comes from somewhere unknown at compile time —
which is exactly what **user input** provides in the next lecture.

---

### **5. Your Exercise**

Before the instructor writes it, he asks you to pause and create a variable holding your own
age:

```kotlin
var age = 35      // ← your number
```

Small as it is, writing it yourself is the practice that makes the syntax stick.

---

### **6. What `if` Unlocks**

Until now, every program you've written executed **every line, in order**. `if` is the first
construct that lets a program **choose** — which is what turns a script into something that
responds to input. Every screen, button and validation in the rest of the course is built on
this.

---

### **Key Takeaways**

1. **`if (condition) { … } else { … }`** runs one branch or the other, never both.
2. Conditions evaluate to **booleans**, built from `>`, `<`, `>=`, `<=`, `==`.
3. **`>=` and `<=` include the boundary value**; `>` and `<` do not.
4. **`==` compares, `=` assigns.**
5. A hardcoded value makes the condition **always true** — the IDE will tell you. Real
   branching needs runtime data.
6. `if` is your program's first ability to **make a decision**.
