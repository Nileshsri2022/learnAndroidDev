Here is a clear, structured breakdown of the lecture on **specifying a number's type
manually** — overriding Kotlin's automatic inference.

---

### **1. Why Override the Type at All?**

By default Kotlin stores whole numbers as `Int` (up to ~2.1 billion). The instructor's
prompt:

> *"My age will never reach 127, so why reserve space for 2 billion?"*

You can tell Kotlin to use a **smaller** type — or a **bigger** one when you need the range.

---

### **2. Syntax**

Put the type after the name, separated by a colon:

```kotlin
var myAge: Byte = 35
```

Hovering `myAge` now reports **`Byte`** instead of `Int`. `println` handles it identically —
it knows how to print a byte.

---

### **3. How Inference Decides**

Kotlin picks the type from the **value you assign**:

```kotlin
var myAge = 35            // small → Int
var myAge = 3000000000    // too big for Int → automatically Long
var myAge = 35000000      // 35 million, fits → Int
```

No annotation needed in any of those cases.

---

### **4. The Trap: Inference Locks the Type In**

This is the most important idea in the lecture.

```kotlin
var myAge = 35000000      // inferred as Int — permanently
myAge = 3000000000        // ❌ ERROR: too big for Int
```

Once inferred, the type is **fixed for the life of that variable**. Add the annotation and
the error disappears:

```kotlin
var myAge: Long = 35000000   // ✅
myAge = 3000000000           // ✅ fine
```

---

### **5. The Integer Ranges**

| Type | Range |
| :--- | :--- |
| **`Byte`** | −128 … 127 |
| **`Short`** | −32,768 … **32,767** |
| **`Int`** | −2,147,483,648 … 2,147,483,647 |
| **`Long`** | ±9.2 × 10¹⁸ |

The `Short` example: assigning 31,000 is fine, but the 3-billion value from earlier is not.

---

### **6. Practical Guidance**

| Situation | What to write |
| :--- | :--- |
| Almost everything | `val x = 5` — let Kotlin infer `Int` |
| The value may grow past 2.1 billion later | `val x: Long = 5` |
| You truly need to save memory | `val x: Byte = 5` |

In real apps the middle row is the only one you'll reach for often. Choosing `Byte` to save
a few bytes is almost never worth the readability cost.

---

### **Key Takeaways**

1. Annotate with **`name: Type = value`** to override inference.
2. Kotlin infers **`Int`** for normal numbers and switches to **`Long`** automatically when
   the literal is too large.
3. **Inference is permanent** — an `Int` variable cannot later hold a `Long`. Declare
   `: Long` up front if you'll need the range.
4. The four signed types are **`Byte`, `Short`, `Int`, `Long`** — same behaviour, different
   range.
5. `println` works with **all** of them without any conversion.
