Here is a clear, structured breakdown of the lecture on **`else if`** — handling more than two
outcomes — and the **`in`** range-check keyword.

---

### **1. Why `else if`?**

`if` / `else` gives you two branches. Real rules often have more:

> *"You must be 18 or older **and** under 40 to enter."*

That's three outcomes: too young, allowed, too old.

---

### **2. Structure**

```kotlin
if (condition) {
    // ...
} else if (anotherCondition) {
    // ...
} else {
    // ...
}
```

You can chain **as many `else if` blocks as you need**, and finish with a single `else`.

---

### **3. The Trap: Branch Order Matters**

This is the most important idea in the lecture. Consider the **wrong** order:

```kotlin
if (age >= 18) {
    println("You can enter")
} else if (age >= 40) {          // ⚠️ UNREACHABLE
    println("You are too old")
} else {
    println("You are too young")
}
```

Enter `120` and the output is **"You can enter"** — the age check failed to work.

#### Why

Code runs **top to bottom**, and the first matching branch **wins**:

* `120 >= 18` → **true** → prints "You can enter" and **stops checking**
* The `else if` is never reached — anyone 40+ is also 18+, so the first branch swallows them
* The IDE underlines it: **this branch can never execute**

---

### **4. Fix #1 — Reorder the Checks**

Test the **narrowest / most restrictive** condition first:

```kotlin
if (age >= 40) {
    println("You cannot go into the club, please go home")
} else if (age >= 18) {
    println("You can enter")
} else {
    println("You are too young")
}
```

Now `41` → *"cannot go into the club"*, `25` → *"you can enter"*. ✅

---

### **5. Fix #2 — Combine Conditions With `&&`**

Keep the original order but make the first branch **exclusive**:

```kotlin
if (age >= 18 && age < 40) {
    println("You can enter")
} else if (age >= 40) {
    println("You are too old")
} else {
    println("You are too young")
}
```

Now `120` correctly reports *"you are too old"*, because `120 < 40` is false and the first
branch is skipped.

---

### **6. The `in` Range Check**

Android Studio suggests replacing `age >= 18 && age < 40` with a **range check**:

```kotlin
if (age in 18..39) {
    println("You can enter")
}
```

| Syntax | Meaning |
| :--- | :--- |
| **`a in x..y`** | `a` is between `x` and `y`, **both endpoints included** |

Note the range ends at **`39`**, not `40` — because `..` is inclusive, `18..40` would include
40 and defeat the rule. (Kotlin also has `until`, where `18 until 40` excludes 40.)

---

### **7. Boundary Reminder**

* **`>= 40`** includes exactly 40
* **`<= 18`** includes exactly 18
* **`in 18..39`** includes both 18 and 39

Off-by-one errors live here. Be deliberate about which side owns the boundary.

---

### **Key Takeaways**

1. **`else if`** adds branches; you can chain many, with one final `else`.
2. **Order matters.** The first true branch wins and the rest are skipped.
3. A broad first condition makes later branches **unreachable** — the IDE flags this.
4. Fix it by **reordering** (most restrictive first) or by **narrowing with `&&`**.
5. **`in 18..39`** is a cleaner range check; `..` **includes both endpoints**.
6. `>=` and `<=` **include** the boundary value — watch your off-by-ones.
