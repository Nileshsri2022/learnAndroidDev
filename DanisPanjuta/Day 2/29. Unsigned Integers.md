Here is a clear, structured breakdown of the short lecture on **unsigned integers** —
included for completeness rather than because you'll use them often.

---

### **1. What "Unsigned" Means**

Normal ("signed") integer types split their range across negative and positive values.
**Unsigned** types throw away the negative half and spend it all on positives:

| Signed type | Range | Unsigned type | Range |
| :--- | :--- | :--- | :--- |
| **`Byte`** | −128 … 127 | **`UByte`** | 0 … **255** |
| **`Short`** | −32,768 … 32,767 | **`UShort`** | 0 … **65,535** |
| **`Int`** | −2.1bn … 2.1bn | **`UInt`** | 0 … ~4.3bn |
| **`Long`** | ±9.2 × 10¹⁸ | **`ULong`** | 0 … ~1.8 × 10¹⁹ |

Same bit width, **double the positive ceiling**, and **no negative values at all**.

---

### **2. Syntax**

Mark the literal with a **`u`** (or `U`) suffix:

```kotlin
val myAge: UShort = 35u
println(myAge)        // 35
```

Hovering `myAge` reports the type **`UShort`**.

---

### **3. The Instructor's Example**

> *"My age can never be negative — I can't be −35."*

So `myAge` is a natural fit for an unsigned type. And if he somehow lives past 127, a
`UByte` still covers him all the way to **255**.

Attempting to assign a negative number to an unsigned variable is a **compile-time error**.

---

### **4. When Would You Actually Use These?**

The honest answer from the lecture: **rarely**. The documentation's stated use case is
*"utilising the full bit range of an integer to represent positive values"* — which the
instructor admits he isn't thrilled with as an explanation.

Realistic cases:

* Bit-level work, checksums, colour channels
* Interfacing with protocols that specify unsigned fields
* Deliberately making "negative is impossible" a **compiler-enforced guarantee**

For everyday app code, plain `Int` is the right choice.

---

### **Key Takeaways**

1. **Unsigned types** (`UByte`, `UShort`, `UInt`, `ULong`) have **no negative values**.
2. They **double the maximum positive** value for the same storage size.
3. Mark literals with a **`u` suffix**: `35u`.
4. The compiler **rejects negative assignments** — useful when negativity is meaningless.
5. This lecture is here **for completeness**. You will almost never need these in the rest
   of the course.
