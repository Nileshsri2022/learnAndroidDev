Here is a clear, structured breakdown of the lecture on **`val` vs `var`** — immutable and
mutable variables — and printing values to the console.

---

### **1. The Core Distinction**

| Keyword | Term | Can you reassign it? | Use it for |
| :--- | :--- | :--- | :--- |
| **`val`** | **immutable reference** | ❌ No — read-only after first assignment | Constants: `pi`, a configured base URL |
| **`var`** | **mutable reference** | ✅ Yes — change it as often as you like | Values that change: a counter, an age, a score |

> **"Assigning"** is the terminology for giving a variable a value — including the very
> first time.

---

### **2. `val` — Assign Once**

```kotlin
val numberOne = 1
numberOne = 2        // ❌ COMPILE-TIME ERROR
```

Kotlin rejects this **before the program ever runs** — Android Studio underlines it in red
immediately. That is a *compile-time error*, and it is a feature: whole classes of bug
never make it to production.

---

### **3. `var` — Reassign Freely**

```kotlin
var myAge = 35
println(myAge)       // 35

myAge = 36           // ✅ allowed
println(myAge)       // 36
```

---

### **4. Default to `val`**

Kotlin's own recommendation — and the instructor's — is to **use `val` unless you genuinely
need to change the value**. Reach for `var` only when the value must vary.

```kotlin
val pi = 3.14159     // ✅ never changes → val
var score = 0        // ✅ increases during the game → var
```

---

### **5. Printing Variables**

`println` takes a variable directly — no string quotes needed:

```kotlin
println(myAge)       // prints: 36
```

`println` is a **built-in function** supplied by Kotlin; you don't write it yourself, and it
already knows how to print an `Int`.

> 💡 **Hover over any variable** in Android Studio to see its type — the tooltip reads
> `var myAge: Int`, confirming both the keyword and the inferred type.

---

### **6. Order Matters**

The lecture demonstrates sequential execution by placing the same `println` in two spots:

```kotlin
var myAge = 35
println(myAge)       // prints 35   ← runs BEFORE the reassignment

myAge = 36
println(myAge)       // prints 36   ← runs AFTER
```

Output:

```text
35
36
```

The same variable printed two different values, purely because of **where the line sits**.

---

### **Key Takeaways**

1. **`val` = immutable**, **`var` = mutable**. That is the whole difference.
2. Reassigning a `val` is a **compile-time error** — caught by the IDE, not at runtime.
3. **Prefer `val` by default**; use `var` only when the value must change.
4. `println(variable)` prints the value — no quotes, no conversion.
5. **Hovering** a variable shows its declared type.
6. Code runs **top to bottom**, so a `println` prints whatever the value is *at that line*.
