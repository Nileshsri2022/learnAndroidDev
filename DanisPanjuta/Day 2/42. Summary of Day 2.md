## 🧱 Variables

A variable is a **named container** for data that lives only while the program runs.

| Keyword | Mutable? | Use for |
| :--- | :--- | :--- |
| **`val`** | ❌ Read-only after assignment | Constants — `pi`, a base URL |
| **`var`** | ✅ Reassignable | Counters, scores, ages |

```kotlin
val pi = 3.14159     // can never change
var myAge = 35
myAge = 36           // ✅ fine with var, ❌ compile error with val
```

**Kotlin's rule: default to `val`.** The IDE underlines any `var` you never reassign and
tells you to switch.

## 🔢 Data Types

### Whole numbers

| Type | Range | Note |
| :--- | :--- | :--- |
| `Byte` | −128 … 127 | |
| `Short` | −32,768 … 32,767 | rarely used |
| **`Int`** | ±2.1 billion | ✅ **default** |
| `Long` | ±9.2 × 10¹⁸ | suffix the literal: `1L` |

Unsigned variants (`UByte`, `UShort`, `UInt`, `ULong`) drop negatives and double the
positive ceiling — `35u`.

### Decimal numbers

| Type | Size | Default? |
| :--- | :--- | :--- |
| `Float` | 32 bit | suffix `3.14f` |
| **`Double`** | 64 bit | ✅ **default** |

A `Float` that can't hold your digits **rounds them silently** — the IDE warns, so read it.

### The rest

| Type | Holds | Written as |
| :--- | :--- | :--- |
| `Boolean` | `true` / `false` | keywords, not strings |
| `Char` | exactly **one** character | `'a'` — **single quotes** |
| `String` | any sequence of characters | `"Dennis"` — **double quotes** |

### Type inference

Kotlin picks the type from the value — you rarely annotate it:

```kotlin
val x = 5              // Int
val y = 3000000000     // too big for Int → Long
val z: Byte = 5        // forced
```

⚠️ **Inference is permanent.** A variable inferred as `Int` cannot later hold a `Long` —
declare `: Long` up front if you'll need the range.

## 🧮 Operators

### Comparison — all produce a `Boolean`

`>`  `<`  `>=`  `<=`  `==`

* **`>=` and `<=` include** the boundary value; `>` and `<` do not.
* **`==` compares, `=` assigns.** The single most common beginner mistake.

### Logical

| Operator | Name | True when |
| :--- | :--- | :--- |
| `\|\|` | OR | either side is true |
| `&&` | AND | **both** sides are true |
| `!` | NOT | flips the value |

### Increment — three identical forms

`count++`  ≡  `count += 1`  ≡  `count = count + 1`

## 🔀 Control Flow

### `if` / `else` / `else if`

```kotlin
if (age >= 40) {
    println("Too old")
} else if (age >= 18) {
    println("You can enter")
} else {
    println("Too young")
}
```

**Order matters.** The first true branch wins and the rest are skipped — so a broad first
condition (`age >= 18`) makes a later narrow one (`age >= 40`) **unreachable**. Put the most
restrictive check first, or narrow with `&&`.

### `in` — the range check

```kotlin
if (age in 18..39) { ... }
```

`..` **includes both endpoints**, hence `39` and not `40`.

### `when` — the cleaner multi-branch

As a **statement**:

```kotlin
when (randomNumber) {
    1 -> computerChoice = "Rock"
    2 -> computerChoice = "Paper"
    3 -> computerChoice = "Scissors"
}
```

As an **expression** that returns a value — the elegant heart of the game:

```kotlin
val winner = when {
    playerChoice == computerChoice                            -> "Tie"
    playerChoice == "Rock"     && computerChoice == "Scissors" -> "Player"
    playerChoice == "Paper"    && computerChoice == "Rock"     -> "Player"
    playerChoice == "Scissors" && computerChoice == "Paper"    -> "Player"
    else                                                       -> "Computer"
}
```

Nine possible matchups reduced to **three rules**, because `else` absorbs everything left.
`else` is **mandatory** when `when` assigns to a variable.

## 🔁 Loops

```kotlin
var count = 0
while (count < 3) {
    println("Count is $count")
    count++
}
```

Prints `0, 1, 2` — it exits the moment `count` reaches 3.

**The infinite-loop rule:** every loop needs a condition that *can* become false, plus
something inside the loop that *makes* it false. `while (true) { }` crashes the app.

For input-driven loops, **re-read inside the loop**:

```kotlin
var input = readln()
while (input == "1") {
    println("Looping")
    input = readln()      // ← omit this and it never ends
}
```

## ⌨️ Console I/O

```kotlin
println("Please enter your age as a whole number")   // prompt
val entered = readln()                               // String — blocks until Enter
val age = entered.toInt()                            // parse to Int
```

* `readln()` **always returns a `String`**, even for numeric input — hence `.toInt()`.
* **Always print a prompt**, or the user faces a frozen, blank console.
* Non-numeric input throws a **`NumberFormatException`** at **runtime** — the IDE cannot
  catch it.

### Strings

```kotlin
firstName + " " + lastName      // + concatenates, adds NO space
name.uppercase()                // strings are objects → they have methods
"Dennis\nPanjuta"               // \n new line, \t tab
'\u00AE'                        // Unicode escape → ©
'\\'                            // a literal backslash (\ is the escape char)
// this whole line is a comment
```

Numbers interpolate **automatically** into string templates — no manual conversion:

```kotlin
println("Count is $count")
```

## 🎮 The Finished Game

```kotlin
fun main() {
    var computerChoice = ""
    var playerChoice = ""

    println("Rock, Paper or Scissors? Enter your choice:")
    playerChoice = readln()

    val randomNumber = (1..3).random()

    when (randomNumber) {
        1 -> computerChoice = "Rock"
        2 -> computerChoice = "Paper"
        3 -> computerChoice = "Scissors"
    }

    println("Computer chose: $computerChoice")

    val winner = when {
        playerChoice == computerChoice                             -> "Tie"
        playerChoice == "Rock"     && computerChoice == "Scissors" -> "Player"
        playerChoice == "Paper"    && computerChoice == "Rock"     -> "Player"
        playerChoice == "Scissors" && computerChoice == "Paper"    -> "Player"
        else                                                       -> "Computer"
    }

    if (winner == "Tie") {
        println("It's a tie!")
    } else {
        println("$winner won!")
    }
}
```

## ⚠️ The One Bug Still Open

Invalid input — typing `"rock source"` instead of `"rock"` — matches no winning condition
and isn't a tie, so it falls into `else` and **the computer wins automatically**.

The fix is the validation loop from the final lecture:

```kotlin
while (playerChoice != "rock" && playerChoice != "paper" && playerChoice != "scissors") {
    println("Invalid choice — please enter rock, paper or scissors:")
    playerChoice = readln()
}
```

## ✅ Key Takeaways

1. **`val` by default**, `var` only when the value must change.
2. Kotlin **infers** types — and the inference is **permanent**.
3. `Int` and `Double` are the defaults; reach for others deliberately.
4. Conditions are **booleans**, built from comparison and logical operators.
5. **Branch order matters** — first match wins; make later branches reachable.
6. **`when`** beats `if-else` chains, and as an expression can assign directly.
7. Every loop needs a **way out**.
8. **`readln()` returns a `String`** — parse it, prompt for it, and validate it.
9. Day 3 builds on all of this: **writing your own functions**, then classes and objects.
