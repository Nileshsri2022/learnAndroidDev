Here is a clear, structured breakdown of the lecture on **reading user input** with `readln()`
and converting it with `toInt()`.

---

### **1. Overview**

The club-bouncer example had a hardcoded age, so the condition was always true. This lecture
makes the program **ask** instead.

---

### **2. `readln()` — Reading a Line From the Console**

```kotlin
var age = readln()
```

`readln()` **pauses the program** and waits for the user to type something and press Enter.
Whatever they typed becomes the value.

---

### **3. The Type Mismatch Problem**

`readln()` always returns a **`String`** — even when the user types a number:

```kotlin
var age: Int = readln()      // ❌ Type mismatch: String vs Int
```

Typing `35` at the console produces the **string** `"35"`, not the **number** `35`. You
cannot compare a string against a number.

---

### **4. The Fix: `.toInt()`**

```kotlin
var age = readln().toInt()
```

`toInt()` **parses** the string into an `Int` and returns it. *"Parsing"* is the standard term
for converting text into a structured value.

#### The same thing, spelled out

```kotlin
var enteredValue = readln()        // String — exactly what the user typed
var age = enteredValue.toInt()     // Int — parsed
```

`enteredValue` is never reassigned, so it should be a **`val`** — and the IDE will say so.

---

### **5. Always Tell the User What to Type**

Without a prompt, the console just sits there with a blinking cursor:

```kotlin
println("Please enter your age as a whole number")
var age = readln().toInt()

if (age >= 18) {
    println("You can go into the club")
} else {
    println("You are too young to go into the club")
}
```

Session:

```text
Please enter your age as a whole number
17
You are too young to go into the club
```

---

### **6. Execution Order**

```
1. define age
2. print the prompt
3. readln() → program WAITS for input
4. toInt() parses it
5. the if/else runs
```

The program genuinely **blocks** at step 3 until Enter is pressed.

---

### **7. How to Break It**

Type something that isn't a number:

```text
Please enter your age as a whole number
asdf
```

```
Exception in thread "main" java.lang.NumberFormatException: For input string: "asdf"
```

A **`NumberFormatException`** — the parser expected digits and got text. The app crashes.

> This is your first **runtime error**: unlike the compile-time errors from earlier, the IDE
> could not catch it, because the bad data only exists once a human types it.

Handling that gracefully is exactly what the **`while` loop** lectures at the end of this day
are for — and it's the fix Rock, Paper, Scissors still needs.

---

### **Key Takeaways**

1. **`readln()`** reads a line from the console and **blocks** until the user presses Enter.
2. It always returns a **`String`** — even for numeric input.
3. **`.toInt()`** parses that string into an `Int`; without it you can't do numeric
   comparisons.
4. **Always print a prompt first**, or the user sees a blank, frozen console.
5. Non-numeric input throws a **`NumberFormatException`** at **runtime** — the IDE cannot
   warn you.
6. Validating that input is the job of the **`while` loop** lectures later today.
