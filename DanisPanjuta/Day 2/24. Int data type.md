Here is a clear, structured breakdown of the lecture on **Kotlin's number types** — starting
with `Int` and covering the whole integer family.

---

### **1. Overview**

The instructor works through the official Kotlin documentation
(`kotlinlang.org/docs/basic-types.html`) and translates it into plain language. His honest
verdict: the docs are **poorly written for beginners**, because they explain numbers in terms
of objects and classes — concepts you haven't met yet.

---

### **2. The Integer Types**

Kotlin has four signed integer types, differing only in **how big a number they can hold**:

| Type | Size | Range | Typical use |
| :--- | :--- | :--- | :--- |
| **`Byte`** | 8 bit | −128 … **127** | Small counters, raw data |
| **`Short`** | 16 bit | −32,768 … **32,767** | Rarely used |
| **`Int`** | 32 bit | −2,147,483,648 … **2,147,483,647** (~2.1 billion) | ✅ **Default** — ages, quantities, indexes |
| **`Long`** | 64 bit | −9,223,372,036,854,775,808 … 9,223,372,036,854,775,807 (~9 quintillion) | Timestamps, phone numbers, huge IDs |

---

### **3. Type Inference — The Big Difference From Other Languages**

In many languages you **must** declare the type. In Kotlin you usually don't:

```kotlin
val one = 1              // inferred as Int — automatically
val huge = 3000000000    // 3 billion doesn't fit in Int → inferred as Long
```

**Kotlin looks at the value and picks the type for you.**

---

### **4. Forcing a Specific Type**

Two ways to override the inference:

```kotlin
val oneAsLong: Long = 1L     // the L suffix marks a Long literal
val oneAsByte: Byte = 1      // explicit type annotation after a colon
```

Why bother? If a variable starts small but will later hold a big number, declaring it as
`Long` up front avoids a **compile-time error** later:

```kotlin
val myAge = 35          // locked in as Int
myAge = 3000000000      // ❌ ERROR — too big for Int

val myAge: Long = 35    // ✅ now it can grow
myAge = 3000000000      // ✅ fine
```

---

### **5. Choosing a Smaller Type to Save Space**

The instructor's example: a person's age will never exceed 127, so a `Byte` is enough.

```kotlin
val myAge: Byte = 35
```

This is technically more memory-efficient, but in practice **`Int` is the right default** —
clarity beats micro-optimisation almost everywhere.

---

### **6. Using the Documentation (and ChatGPT)**

* **`kotlinlang.org/docs/basic-types.html`** — the authoritative reference, worth skimming
  regularly.
* The docs assume you already know classes and objects. When they don't make sense, the
  instructor suggests asking an AI assistant to re-explain the same page *as if to a
  five-year-old* — then returning to the real docs.

---

### **Key Takeaways**

1. Four signed integer types: **`Byte`, `Short`, `Int`, `Long`** — same behaviour, different
   maximum size.
2. **`Int` is the default** and holds ~2.1 billion. Above that, Kotlin switches to `Long`.
3. Kotlin **infers** the type from the value — unlike Java or C, you rarely declare it.
4. Force a type with **`: Long`** or a literal suffix like **`1L`**.
5. Inference **locks the type in at first assignment** — a variable inferred as `Int` cannot
   later hold a `Long`.
6. The official docs are accurate but **not beginner-friendly**; supplement them.
