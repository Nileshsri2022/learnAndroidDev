The guilds of Crawfordsville in the town of Crawfordsville. Various guilds interfaces existed, each representing a specific craft. There was the blacksmiths guild, the bakers guild, the tailors guild, and so on. Each guild had a set of standards and practices, so methods that its members classes adhere to. However, some townsfolk were multi-talented. For instance, Sir Bakelite was not only a member of the bakers guild, but also the tailor skills, making him both a baker and a tailor implementing multiple interfaces. This multi guild membership allowed him to offer a diverse range of services, showcasing the power of multiple inheritances via interfaces. The guilds ensured that regardless of an individual's unique style or technique, certain quality standards and practices were maintained, symbolizing the contracts and interface enforces. So interfaces in programming, especially in object oriented programming languages like Kotlin, serve several essential purposes. Number one abstraction. So interfaces allow you to define a contract that classes can implement. This contract consists of method signatures that derived classes must provide implementations for. It abstracts the what from the how. A class can say, I promise to have this capability without immediately specifying how it achieves it. Then we have number two multiple inheritance. Most object oriented languages, including Kotlin, don't support multiple inheritance of classes due to the diamond problem and other complexities. However, a class can implement multiple interfaces, allowing you to inherit from multiple sources without the baggage that comes with class based multiple inheritance. And we have seen how multiple inheritance work. Basically with our third example with the archery and the bard. The singer, so to speak. Okay. Number three is flexibility and interchangeability. Since inheritance is focus on the what and not the how, you can have multiple classes implementing the same interface in various ways. This flexibility means that objects of these classes can be used interchangeably in contexts where only the capabilities guaranteed by the interface are relevant. Then there is number four encapsulation. So by using interfaces, you can hide the internal implementation details of a class and expose only the methods declared in the interface. This encapsulation ensures that external components interact with the object through a well-defined contract, and number five is evolution in scalability. As software grows and evolves, interfaces provide a stable contract that allows you to expand and refactor your underlying implementations without affecting classes that depend on the interface.
