## 📝 Summary

In many traditional programming languages like Java, C, and C++, `if` is strictly a **statement**—it performs an action but does not return a value. To assign a value conditionally on a single line, those languages rely on a special ternary operator (`condition ? a : b`).

In Kotlin, **`if` is an expression**. This means an `if-else` construct computes and returns a direct value. Consequently, you can assign the result of an `if` block directly to a variable, pass it as a function argument, or embed it inside string templates. This lecture explores how `if` expressions work, the mandatory requirement of `else` branches, multi-line expression blocks, and type inference rules.

---

## 🧠 Statement vs. Expression

```
STATEMENT (Java / C++):
Does work, produces NO value directly:
int max;
if (a > b) {
    max = a;
} else {
    max = b;
}

EXPRESSION (Kotlin):
Evaluates directly to a VALUE:
val max = if (a > b) a else b
```

| Feature | Java / C++ Approach | Idiomatic Kotlin Approach |
|---|---|---|
| **Syntactic Role** | Statement (does not return value). Requires ternary `? :` for inline assignment. | **First-class Expression:** Returns a value directly. |
| **Ternary Operator** | `int max = (a > b) ? a : b;` | **No ternary operator exists!** Use `val max = if (a > b) a else b`. |
| **Immutability (`val`)** | Difficult without ternary (requires pre-declaring mutable variables). | Seamless with `val`: variables are assigned cleanly in one atomic step. |
| **Completeness Check** | Not checked for statements. | The compiler **enforces an `else` branch** when used as an expression. |

## 📒 Detailed Notes

### 1. Basic `if` Expression Assignment
Because `if` returns a value, you can assign it directly to an immutable `val`:
```kotlin
val a = 25
val b = 42

// Directly assigns the greater number to max
val max = if (a > b) a else b
println("The greater number is $max") // 42
```

### 2. The Mandatory `else` Branch Rule
When using `if` as an expression, the compiler must be 100% certain that the variable receives a value regardless of what happens at runtime.
```kotlin
// 💥 COMPILER ERROR: 'if' must have both main and 'else' branches if used as an expression
val status = if (score > 50) "Pass" 

// ✅ VALID: All possibilities produce a String
val status = if (score > 50) "Pass" else "Fail"
```

### 3. Multi-Line Expression Blocks
If a branch contains multiple lines of logging or calculation, wrap it in curly braces `{ }`. In Kotlin, **the last expression inside the block becomes the return value**:
```kotlin
val temperature = 32

val advice = if (temperature > 30) {
    println("Log: Extreme heat detected")
    val waterNeeded = 3
    println("Log: Recommending $waterNeeded liters")
    "Drink $waterNeeded liters of water and seek shade!" // <-- RETURN VALUE of if block
} else {
    println("Log: Mild temperature")
    "Enjoy the weather!" // <-- RETURN VALUE of else block
}

println(advice)
```

### 4. Embedding `if` Expressions in String Templates
Because `if` produces a value, you can embed it inside Kotlin string templates using `${ ... }`:
```kotlin
val isOnline = true
val user = "Denis"

println("User $user is currently ${if (isOnline) "🟢 Online" else "🔴 Offline"}.")
```

### 5. Type Inference Across Branches
Kotlin's smart compiler inspects all branches to infer the most specific common return type:
```kotlin
val age = 22

// Inferred type is String
val category = if (age < 13) {
    "Child"
} else if (age < 20) {
    "Teenager"
} else if (age < 65) {
    "Adult"
} else {
    "Senior"
}
```
*Note:* If different branches return completely unrelated types (e.g., branch 1 returns a `String` and branch 2 returns an `Int`), Kotlin infers the common supertype `Any`, which may require subsequent type checks. Ensure branches return consistent types for clean code.

## 💻 Practical Android Use Cases

In Android development, `if` expressions are everywhere:

### Setting Dynamic UI Colors
```kotlin
val isError = formInput.isEmpty()
val borderColor = if (isError) Color.Red else Color.LightGray
val helperText = if (isError) "Field cannot be empty" else "Looks good!"
```

### Dynamic Button Text
```kotlin
val isPlaying = musicService.isPlaying()
val buttonLabel = if (isPlaying) "Pause" else "Play"
val buttonIcon = if (isPlaying) R.drawable.ic_pause else R.drawable.ic_play
```

## 📌 Important Terms

| Term | Definition |

| **Expression** | A syntactic unit that evaluates to a concrete value. |
| **Statement** | A syntactic unit that executes an action but produces no value. |
| **Ternary Operator** | A conditional operator (`? :`) used in languages where `if` is not an expression. |
| **Type Inference** | The compiler's ability to deduce data types automatically based on branch values. |

## ❓ Q&A

**Q: Why doesn't Kotlin just include `? :` like Java and C#?**  
A: Because `if (cond) a else b` is identical in length, much more readable to humans, and handles complex multi-line logic and chaining far better than nested ternaries (`a ? b : c ? d : e`).

**Q: Can I use `return if (...) ...` inside a function?**  
A: Yes! You can write single-expression functions:
```kotlin
fun getFee(isMember: Boolean): Double = if (isMember) 5.0 else 15.0
```

## ✅ Key Takeaways

1. 💎 **`if` returns a value:** In Kotlin, `if` is an expression, eliminating the need for a ternary operator.
2. 🔒 **`else` is strictly required:** When assigning from an `if` expression, every possible path must guarantee a return value.
3. 📦 **Last line is the result:** In multi-line `{ }` blocks, the final evaluated expression is what gets returned.
4. 🚀 **Enables immutability:** Allows assigning values to `val` variables in a single declarative step, making Android code thread-safe and robust.
