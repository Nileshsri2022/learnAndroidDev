## 🧠 Comparison Operators in Kotlin

Before constructing conditions, you must compare operands:

| Operator | Meaning | Example | Evaluates To |
|---|---|---|---|
| `==` | Structural equality | `170 == 170` | `true` |
| `!=` | Inequality | `170 != 189` | `true` |
| `>` | Strictly greater than | `170 > 189` | `false` |
| `<` | Strictly less than | `170 < 189` | `true` |
| `>=` | Greater than or equal | `21 >= 21` | `true` |
| `<=` | Less than or equal | `16 <= 18` | `true` |

## 📒 Detailed Notes

### 1. The Martial Arts Coach Analogy
Imagine coaching a fighter entering the ring:
- Fighter 1 height: `170` cm (~5'7")
- Fighter 2 height: `189` cm (~6'2")

What strategy should the coach advise?
- If Fighter 1 is taller: rely on raw physical mass and power.
- If Fighter 1 is shorter: rely on agile technique, speed, and leverage.
- If both fighters are the exact same height: execute secret power technique `1337`!

```kotlin
val heightPerson1 = 170
val heightPerson2 = 189

if (heightPerson1 > heightPerson2) {
    println("Strategy: Use raw force and physical weight!")
} else if (heightPerson1 == heightPerson2) {
    println("Strategy: Use your secret power technique 1337!")
} else {
    println("Strategy: Use agile technique, speed, and leverage!")
}
```

### 2. Execution Flow & Evaluation Order
1. **The `if` condition is tested first:** `170 > 189` evaluates to `false`. The first block is skipped.
2. **The `else if` condition is tested second:** `170 == 189` evaluates to `false`. The second block is skipped.
3. **The `else` branch serves as the default fallback:** Because all preceding conditions failed, the `else` block executes automatically, printing `"Strategy: Use agile technique, speed, and leverage!"`.

### 3. Caution: Condition Overlapping & Shadowing
When chaining multiple `else if` conditions, order matters! Kotlin evaluates conditions **top-to-bottom and stops at the very first branch that evaluates to `true`**. Subsequent branches are never evaluated:
```kotlin
// ⚠️ INCORRECT ORDER:
val score = 95
if (score >= 50) {
    println("Pass") // Matches 95! Evaluation stops here!
} else if (score >= 90) {
    println("Honors") // UNREACHABLE CODE!
}

// ✅ CORRECT ORDER (Most restrictive first):
if (score >= 90) {
    println("Honors")
} else if (score >= 50) {
    println("Pass")
}
```

### 4. Challenge: Legal Age Verification Ladder
Denis presents a challenge to print the highest legal privilege available for a person of a given `age`:
- `age >= 21`: May drink in the US
- `age >= 18`: May vote in elections
- `age >= 16`: May drive with a driver's license
- Otherwise: Too young for adult privileges

```kotlin
fun main() {
    val age = 31

    if (age >= 21) {
        println("Now you may drink in the US.")
    } else if (age >= 18) {
        println("You may vote now.")
    } else if (age >= 16) {
        println("You may drive now.")
    } else {
        println("You're too young to do whatever.")
    }
}
```

### 5. The Single-Line Syntax Trap
Kotlin permits omitting curly braces `{ }` if a branch contains only a single statement:
```kotlin
if (age >= 30)
    println("You're over 30.")
```

⚠️ **The Critical Pitfall:**  
If an unsuspecting developer adds a second line without adding braces:
```kotlin
if (age >= 30)
    println("You're over 30.")
    println("This line ALWAYS runs regardless of age!") // 💥 BUG!
```
The second line is **not part of the `if` body** and will execute unconditionally! For this reason, professional Kotlin style guides recommend **always using curly braces `{ }`** for multi-line control flow.

## 📌 Important Terms

| Term | Definition |
| :--- | :--- |
| **Control Flow** | The order in which individual statements and instructions are executed in a program. |
| **Branching** | Choosing between different paths of code execution based on boolean condition evaluations. |
| **Fallback (`else`)** | The default block executed when none of the preceding `if` or `else if` tests are true. |
| **Condition Shadowing** | A logic defect where a broad condition earlier in the chain prevents a specific condition later from ever running. |

## ❓ Q&A

**Q: Can I have an `if` statement without an `else`?**  
A: Yes! When used as a standalone statement, an `else` branch is optional. If the condition is false, execution simply continues to the next line.

**Q: Why does the IDE suggest "Cascade if should be replaced with when"?**  
A: Long chains of `if-else if-else` can become difficult to read. Kotlin offers the `when` expression (a modernized replacement for `switch`) which provides cleaner pattern matching.

## ✅ Key Takeaways

1. 🚦 **Control flow guides decisions:** `if` and `else if` evaluate boolean conditions to route execution dynamically.
2. 🛡️ **Always provide a fallback:** Use `else` as the safety net for unhandled inputs or edge cases.
3. 📐 **Order from strict to broad:** Test the most specific conditions first to prevent condition shadowing.
4. 🔒 **Always use curly braces:** Omitting braces on single-line `if` statements frequently leads to accidental indentation bugs.
