Here is a clear, structured breakdown of the lecture on **reading and replacing a single item
by index**.

---

### **1. Reading an Item — Bracket Notation**

```kotlin
println(shoppingList[2])        // prints just that one item
```

The **square-bracket operator** retrieves the item at a position, instead of printing the
whole list.

```kotlin
println(shoppingList)           // [Processor, Cooling system, RAM, Graphics card]
println(shoppingList[2])        // RAM
```

---

### **2. Recalculating the Index**

The lecture poses a quiz: *after inserting `RAM` at index 2, where is the graphics card?*

```
[Processor, Cooling system, RAM, Graphics card]
     0            1           2        3
```

**Index 3** — the insertion pushed everything from position 2 onward one slot to the right.

> The point: don't count from the *print statement* you ran earlier. Count from the list **as
> it stands right now**. Printing the list immediately before accessing it is the reliable
> habit.

---

### **3. Replacing an Item**

Assign to the bracket, exactly as you would to a variable:

```kotlin
shoppingList[3] = "Graphics card RX 7800 XT"
```

```text
Before: [Processor, Cooling system, RAM, Graphics card RTX 4090]
After:  [Processor, Cooling system, RAM, Graphics card RX 7800 XT]
```

The old item is **replaced in place** — the list length is unchanged and nothing shifts.

---

### **4. Replace vs Remove-then-Add**

| Approach | Result |
| :--- | :--- |
| **`list[3] = "new"`** | Replaces in place — **position preserved** |
| **`remove(...)` then `add(...)`** | Deletes, then **appends at the end** — position lost |

This is exactly why the graphics card ended up at the end in the earlier lecture: removing and
re-adding is *not* the same as replacing.

---

### **5. Requires a Mutable List**

Bracket assignment only works on **`mutableListOf`**. On a `listOf` the item is read-only:

```kotlin
val fixed = listOf("a", "b")
println(fixed[0])       // ✅ reading is fine
fixed[0] = "c"          // ❌ val cannot be reassigned
```

---

### **Key Takeaways**

1. **`list[i]`** reads the item at index `i`.
2. **`list[i] = value`** replaces it **in place** — no shifting, same length.
3. **Recalculate indexes after every change**; the list you're indexing is the current one.
4. Replacing is **not** the same as remove-then-add, which moves the item to the end.
5. Bracket **assignment needs a mutable list**; reading works on both.
