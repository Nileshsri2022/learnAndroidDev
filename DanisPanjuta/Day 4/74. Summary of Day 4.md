## 📋 Creating Lists

```kotlin
val fixed = listOf("Processor", "RAM", "SSD")            // immutable
val cart  = mutableListOf("Processor", "RAM", "SSD")     // mutable
val empty = mutableListOf<String>()                      // empty needs an explicit type
```

| | `listOf` | `mutableListOf` |
| :--- | :--- | :--- |
| Add / remove items | ❌ methods don't exist | ✅ |
| Replace an item | ❌ | ✅ |
| **Read** items | ✅ | ✅ |

> ⚠️ Immutability comes from **`listOf`**, *not* from `val`. `val` stops you reassigning the
> **variable**; `listOf` stops you changing the **contents**. A `val` holding a
> `mutableListOf` is completely normal — and is exactly what the BankAccountApp does.

An **empty** list needs `<String>` because there are no items for Kotlin to infer the type
from.

Lists hold **any type** — strings, numbers, or objects of your own classes.

## 🔢 Indexes

**Counting starts at zero.**

```
[Processor, RAM, SSD, Cooling system]
     0       1    2        3
```

* `.size` returns the **count** (`4`) — which starts at **1**
* Indexes run **0 … size − 1**
* **No gaps ever exist** — deleting an item shifts everything after it down

---

## 🛠️ List Methods

| Method | Effect |
| :--- | :--- |
| **`add(item)`** | Append to the **end** |
| **`add(index, item)`** | Insert at a position, shifting the rest right |
| **`remove(item)`** | Delete by **value** |
| **`removeAt(index)`** | Delete by **position** |
| **`removeFirst()` / `removeLast()`** | Delete the ends |
| **`removeAll { }`** | Delete everything matching a condition |
| **`set(index, item)`** | Replace in place — same as `list[index] = item` |
| **`contains(item)`** | Returns a **`Boolean`** |
| **`.size`** | The number of items |

### Reading and replacing

```kotlin
println(cart[2])              // read one item
cart[3] = "RX 7800 XT"        // replace in place — position preserved
cart.set(3, "RX 7800 XT")     // identical; the IDE prefers the bracket form
```

**Replacing is not remove-then-add** — the latter moves the item to the end.

## 🔁 For Loops

### By value — the default choice

```kotlin
for (item in shoppingList) {
    println(item)
}
```

Runs **once per item**. No counter, so **no risk of an infinite loop**.

### By index — when you need the position

```kotlin
for (index in 0 until shoppingList.size) {
    println("Item ${shoppingList[index]} is at index $index")
}
```

⚠️ `index` is a **number**, not the item — use `shoppingList[index]` to get the value.

### Exiting early

```kotlin
for (item in shoppingList) {
    if (item == "RAM") break       // leave the loop entirely
}
```

## ⚠️ `until` vs `..`

The most common off-by-one trap in Kotlin:

| Operator | Range | End included? |
| :--- | :--- | :--- |
| **`0 until 4`** | 0,1,2,3 | ❌ |
| **`0..3`** | 0,1,2,3 | ✅ |
| **`0..4`** | 0,1,2,3,4 | ✅ — **index 4 doesn't exist → crash** |

Because `size` starts at 1 and indexes at 0:

```kotlin
0 until list.size           // ✅ correct
0..list.size                // ❌ one past the end
0..list.size - 1            // ✅ correct
```

## 🏦 The Bank Account Program

The day's project, combining **everything** from Days 2–4.

### The class

```kotlin
class BankAccount(
    var accountHolder: String,
    var balance: Double
) {
    private val transactionHistory = mutableListOf<String>()

    fun deposit(amount: Double) {
        balance += amount
        transactionHistory.add("$accountHolder deposited $$amount")
    }

    fun withdraw(amount: Double) {
        if (amount <= balance) {
            balance -= amount
            transactionHistory.add("$accountHolder withdrew $$amount")
        } else {
            println("You don't have the funds to withdraw $$amount")
        }
    }

    fun displayTransactionHistory() {
        println("--- Transaction history for $accountHolder ---")
        for (transaction in transactionHistory) {
            println(transaction)
        }
    }
}
```

### The concepts it demonstrates

| Concept | Where |
| :--- | :--- |
| **Encapsulation** | `private val transactionHistory` — outside code can't touch it |
| **Typed empty list** | `mutableListOf<String>()` — inference has nothing to work from |
| **Mutable list in a `val`** | The variable never changes; the contents do |
| **`for` loop** | Printing every transaction |
| **Condition as a guard** | `if (amount <= balance)` prevents overdraft |
| **`+=` / `-=`** | Shorthand property updates |
| **`$$amount`** | First `$` is a literal currency symbol, second interpolates |
| **`Double` for money** | Decimals — with the caveat below |

### The floating-point gotcha

```text
Dennis Panjuta's total balance is: $2510.0000000000005
```

`Double` **cannot represent all decimal fractions exactly** — the same limitation you saw
with `Float` on Day 2. Real financial code uses **`BigDecimal`**, or stores **cents as a
`Long`**.

## ✅ Key Takeaways

1. **`listOf`** is immutable; **`mutableListOf`** lets you add, remove and replace.
2. Immutability comes from the **list type**, not from `val`.
3. **Indexes start at 0** and **shift after every change** — re-check them.
4. **`list[i] = x`** replaces in place; remove-then-add moves the item to the end.
5. **`until` excludes** the end, **`..` includes** it — pair `size` with `until`.
6. **Prefer `for (item in list)`**; use the index form only when you need the position.
7. **`contains`** returns a boolean you can use straight in an `if`.
8. **`private`** plus member functions is **encapsulation** — the core of the BankAccountApp.
