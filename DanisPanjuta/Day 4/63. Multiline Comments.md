Here is a clear, structured breakdown of the short lecture on **multi-line comments** — and
using them to declutter your file.

---

### **1. Syntax**

```kotlin
/*  everything in here is a comment */
```

| Marker | Role |
| :--- | :--- |
| **`/*`** | **Opens** the comment |
| **`*/`** | **Closes** it |

Everything between them is greyed out and ignored by the compiler — across as many lines as
you like.

---

### **2. Compared With `//`**

| Form | Scope | Use for |
| :--- | :--- | :--- |
| **`//`** | Rest of **one line** | Quick notes, disabling a single statement |
| **`/* … */`** | **Many lines** | Disabling a whole block, long explanations |

You already met `//` on Day 2.

---

### **3. The Practical Trick: Decluttering**

The instructor uses a multi-line comment to **hide everything except `main()`**, so the next
few lectures can focus on lists without scrolling past the Day 3 code.

```kotlin
fun main() {
    // today's work goes here
}

/*
fun makeCoffee(...) { ... }
fun add(...) { ... }
fun divide(...) { ... }
*/
```

---

### **4. Where to Put a Data Class**

While rearranging, he notes that **the position of a `data class` in the file doesn't
matter** — Kotlin doesn't care about declaration order.

| Choice | When |
| :--- | :--- |
| **Above `main()`** | His personal preference — you see the data shapes first |
| **Below `main()`** | When `main()` is the interesting part and the class is supporting detail |

Pick whichever reads better; both compile identically.

---

### **5. One Gotcha**

After closing a comment at the very end of a file, add a **blank line**. Otherwise the IDE
may keep showing a stale error at the bottom of the file.

---

### **Key Takeaways**

1. **`/* … */`** comments out **multiple lines**; **`//`** handles a single line.
2. Use block comments to **temporarily hide** code you don't need right now.
3. **Declaration order doesn't matter** — put data classes wherever reads best.
4. Add a **trailing blank line** after a closing `*/` at end of file.
5. Comments are for **humans**; the compiler ignores all of it.
