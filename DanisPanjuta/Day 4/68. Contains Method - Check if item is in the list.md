Here is a clear, structured breakdown of the lecture on the **`contains` method** — checking
whether a list holds a particular item.

---

### **1. Why You Need It**

Often you don't know whether something is already in a list. Rather than looping through and
comparing by hand, ask the list directly.

---

### **2. Syntax and Return Type**

```kotlin
shoppingList.contains("RAM")      // returns Boolean
```

| Input | Result |
| :--- | :--- |
| Item **is** in the list | `true` |
| Item **is not** | `false` |

> 💡 Hovering the method shows its signature, including **`: Boolean`** on the right — the
> same trick you used with functions on Day 3.

---

### **3. Storing the Result**

```kotlin
val hasRam = shoppingList.contains("RAM")

if (hasRam) {
    println("Has RAM in the list")
} else {
    println("No RAM in the list")
}
```

---

### **4. …Or Using It Directly**

Because `contains` returns a boolean, it can **be** the condition — no intermediate variable:

```kotlin
if (shoppingList.contains("RAM")) {
    println("Has RAM in the list")
} else {
    println("No RAM in the list")
}
```

Both forms are correct. Inline is more concise; the variable is better if you need the result
more than once.

This is exactly the pattern from Day 2: **conditions are booleans**, and any expression
producing a boolean can drive an `if`.

---

### **5. Verifying Both Paths**

Remove the RAM and re-run, and the `else` branch fires:

```text
No RAM in the list
```

Testing **both** outcomes — not just the happy path — is a habit worth building early.

---

### **6. Where This Shows Up Later**

* **Day 7 Shopping List:** checking whether an item is already on the list before adding it
* **Day 14 Room:** checking whether a record exists before inserting
* **Any form validation:** "is this field already taken?"

---

### **Key Takeaways**

1. **`contains(item)`** returns a **`Boolean`** — `true` if present.
2. It can be **stored in a variable** or used **directly as an `if` condition**.
3. Matching is by **value**, so it works on strings, numbers and objects.
4. It replaces hand-written search loops.
5. **Test both branches** — present and absent.
