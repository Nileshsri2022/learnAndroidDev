Here is a clear, structured breakdown of the lecture on **iterating by index** — when you need
the *position* as well as the item.

---

### **1. When You Need This**

`for (item in list)` gives you the **value**. But sometimes you need the **position** too — to
display "Item 3 of 5", to replace an item, or to pair an item with its slot.

---

### **2. Syntax**

```kotlin
for (index in 0 until shoppingList.size) {
    println(shoppingList[index])
}
```

| Part | Meaning |
| :--- | :--- |
| **`0 until size`** | The range **0, 1, 2, … size−1** |
| **`shoppingList.size`** | How many items the list holds — returns an **`Int`** |
| **`index`** | The current **position**, not the item |

⚠️ **`index` is a number here, not an element.** To get the item you must look it up:
`shoppingList[index]`.

---

### **3. The `until` / `..` Distinction**

This is the subtle part, and the source of most off-by-one bugs.

| Operator | Range | Includes the end? |
| :--- | :--- | :--- |
| **`0 until 4`** | 0, 1, 2, 3 | ❌ **No** — "less than" |
| **`0..3`** | 0, 1, 2, 3 | ✅ **Yes** — "less than or equal" |

Because **`size` counts from 1** (four items → `size == 4`) while **indexes count from 0**
(four items → 0…3), the two align perfectly with `until`:

```kotlin
0 until shoppingList.size     // ✅ 0,1,2,3 — correct
0..shoppingList.size          // ❌ 0,1,2,3,4 — index 4 doesn't exist → crash
```

With `..` you must subtract one: `0..shoppingList.size - 1`.

---

### **4. Worked Example — Item Plus Position**

```kotlin
for (index in 0 until shoppingList.size) {
    println("Item ${shoppingList[index]} is at index $index")
}
```

```text
Item Processor is at index 0
Item Cooling system is at index 1
Item RAM is at index 2
Item Graphics card is at index 3
```

Note the string template rules from Day 3: `${shoppingList[index]}` needs **braces** because
it's an indexed expression, while plain `$index` does not.

---

### **5. Indexes Are Always Contiguous**

The instructor makes an easy-to-miss point:

> *"There is no empty index inside a mutable list."*

Delete index 2 and every later item shifts down. You never get a "hole":

```
[A, B, C, D]        0,1,2,3
removeAt(2)
[A, B, D]           0,1,2      ← D moved down; no gap
```

That's why `0 until size` is always safe — every index in the range holds a real item.

---

### **6. Three Ways to Loop**

```kotlin
for (item  in shoppingList)                          // by value
for (index in 0 until shoppingList.size)             // by index
for (index in 0..shoppingList.size - 1)              // by index, inclusive range
```

Prefer the **first** unless you genuinely need the position — it's simpler and can't go out
of bounds.

---

### **Key Takeaways**

1. **`for (index in 0 until list.size)`** iterates over **positions**, not items.
2. **`list.size`** returns the item count as an `Int`.
3. **`until` excludes** the end; **`..` includes** it. With `size`, use `until`.
4. **`size` starts at 1, indexes start at 0** — which is why they pair up correctly.
5. **No gaps ever exist** in a mutable list; later items shift down on deletion.
6. Use **`list[index]`** to get the item, and **`${...}`** braces for it in string templates.
7. Reach for the **by-value loop first**; use indexes only when you need the position.
