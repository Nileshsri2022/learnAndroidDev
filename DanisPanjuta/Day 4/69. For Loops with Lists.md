Here is a clear, structured breakdown of the lecture on **`for` loops over lists** — doing
something with every item.

---

### **1. `while` vs `for`**

| Loop | How it terminates | Best for |
| :--- | :--- | :--- |
| **`while`** | A condition you must manage yourself | Repeating until *something changes* |
| **`for`** | Automatically, after every item | Going through **a known collection** |

A `for` loop over a list runs **exactly as many times as there are items** — no counter, no
risk of an infinite loop.

---

### **2. Syntax**

```kotlin
for (item in shoppingList) {
    println(item)
}
```

| Part | Meaning |
| :--- | :--- |
| **`for`** | The keyword |
| **`item`** | A name **you** choose for the current element |
| **`in`** | "each element **in**…" |
| **`shoppingList`** | The list to iterate |

Output for a four-item list:

```text
Processor
Cooling system
RAM
Graphics card
```

Four items → **four iterations**. Each pass, `item` holds the next element.

---

### **3. Exiting Early With `break`**

Stop the loop the moment a condition is met:

```kotlin
for (item in shoppingList) {
    println(item)
    if (item == "RAM") {
        break
    }
}
```

```text
Processor
Cooling system
RAM
```

`Graphics card` never prints — `break` **jumps out of the loop entirely**. (You met `break` in
Day 2's input-validation loop.)

---

### **4. Modifying the List From Inside**

```kotlin
for (item in shoppingList) {
    println(item)
}
shoppingList.removeLast()
println(shoppingList)
```

```text
Processor
Cooling system
RAM
[Processor, Cooling system, RAM]
```

The `remove` family has several forms:

| Method | Effect |
| :--- | :--- |
| **`remove(item)`** | By value |
| **`removeAt(index)`** | By position |
| **`removeFirst()`** | The first item |
| **`removeLast()`** | The last item |
| **`removeAll { }`** | Everything matching a condition |

---

### **5. The Definition Worth Remembering**

> A loop is a way to **repeat a set of instructions** a specified number of times, or until a
> condition is met.

---

### **6. Where This Is Used Throughout the Course**

* **Day 4 BankAccountApp:** `for (transaction in transactionHistory) println(transaction)`
* **Day 7 Shopping List:** rendering every item in a `LazyColumn`
* **Day 9 Recipe App:** iterating the JSON results from the API

The pattern is everywhere — this is one of the most-used constructs in the whole course.

---

### **Key Takeaways**

1. **`for (item in list) { }`** runs once per item — no manual counter.
2. The iteration count **equals the list's size**.
3. **`break`** exits the loop immediately.
4. You can **read and modify** the list around (and carefully inside) the loop.
5. `for` is safer than `while` for collections — **it cannot loop forever**.
6. This exact pattern drives the BankAccountApp, Shopping List and Recipe apps later.
