Here is a clear, structured breakdown of the lecture on **indexes** — how positions work in a
list, and why counting starts at zero.

---

### **1. Indexing Starts at Zero**

This is the single most important habit to build:

> **In programming you don't start counting at 1. You start at 0.**

```
[Processor, RAM, SSD, Cooling system, Graphics card]
     0       1    2        3              4
```

`Processor` is at index **0** — "the zeroth position". Get used to it; every language you
touch works this way.

---

### **2. Reading a Printed List**

```text
[Processor, RAM, SSD, Cooling system, Graphics card]
```

The **square brackets** are just how Kotlin renders a list. In some languages you must write
those brackets when *creating* a list; in Kotlin they only appear in the output.

---

### **3. Removing by Index — `removeAt`**

Two ways to remove:

```kotlin
shoppingList.remove("SSD")       // by VALUE — find this item and delete it
shoppingList.removeAt(2)         // by INDEX — delete whatever is at position 2
```

Deleting index 2:

```text
Before: [Processor, RAM, SSD, Cooling system, Graphics card]
After:  [Processor, RAM, Cooling system, Graphics card]
```

---

### **4. ⚠️ Indexes Shift After Every Change**

The lecture poses a quiz: *after removing the SSD, what index is `RAM` at?*

**Still 1** — nothing before it moved. But items **after** a deletion shift **down by one**.
That's the classic off-by-one trap:

```
[Processor, RAM, SSD, Cooling, GPU]     indices 0,1,2,3,4
removeAt(2)
[Processor, RAM, Cooling, GPU]         indices 0,1,2,3   ← Cooling and GPU moved down
```

**Re-check your indexes after any add or remove.** A hard-coded index that was right a moment
ago may now point at a different item.

The instructor demonstrates by removing index 1 to delete `RAM`, then printing to confirm.

---

### **5. Adding at a Specific Position**

`add` has **two overloads**:

```kotlin
shoppingList.add("RAM")            // append at the end
shoppingList.add(2, "RAM")         // insert at index 2, shifting everything after it right
```

Inserting `RAM` at index 2:

```text
[Processor, Cooling system, RAM, Graphics card]
```

---

### **6. The Full Method Table So Far**

| Method | Effect |
| :--- | :--- |
| **`add(item)`** | Append to the end |
| **`add(index, item)`** | Insert at a position |
| **`remove(item)`** | Delete by value |
| **`removeAt(index)`** | Delete by position |
| `removeFirst()` / `removeLast()` | Delete the ends (mentioned, covered later) |

---

### **7. Why Indexes Matter**

Positional access is what lets you:

* Update **one specific** item without rebuilding the list
* Display items in a **particular order**
* Pair an item with its position — e.g. "Item 3 of 5"

Day 7's Shopping List app and every `LazyColumn` in the course rely on this.

---

### **Key Takeaways**

1. **Indexes start at 0.** The first item is index 0, not 1.
2. **`removeAt(index)`** deletes by position; **`remove(item)`** deletes by value.
3. **Indexes shift** after every add or remove — re-check them.
4. **`add(item)`** appends; **`add(index, item)`** inserts at a position.
5. `[ ]` brackets only appear when **printing** a list in Kotlin.
6. Off-by-one errors live here — be deliberate.
